# ADR-0027：NovelAI 由插件启用，按实际就绪状态执行

状态：已采纳。2026-10-26 主人要求按 Shiori 改进生图模块；关联 [#246](https://github.com/sawaki-zexi/meido/issues/246)。部分替代 ADR-0016、ADR-0022 的生图配置门槛。

## 背景

插件已启用且凭据已保存时，额外的版本消费确认仍可能屏蔽 `generate_image`。普通参数编辑会清除此确认，角色因此误称自己没有生图能力。Shiori 的插件启用与工具注册更直接，未就绪时由能力自身说明原因。[调研](../research/novelai-shiori-meido-diagnosis-2026-10-26.md)区分了这个已证实的配置阻断和另一个尚未定位的模型回合失败。

## 决定与取舍

- `enabled` 是聊天与手动生图的唯一全局开关。凭据、允许模式及本地尝试次数满足时即可发起新请求；保存参数或凭据后不再要求版本消费确认。界面说明生成会使用 NovelAI 账户额度。
- 开关开启时保留 direct 工具。缺凭据、模式全关或本地次数用完时，工具描述及执行结果说明具体原因；实际执行仍检查当前状态。
- 自动 CG 保留角色开关、明确辅助模型、文生图模式及独立次数上限。标签范围与卡片写回仍单独选择；去掉角色版本消费确认。
- 服务修订、角色 epoch、来源校验及撤销继续生效。旧工具、在途任务、CG 候选不能继承后续配置；仅未来的新请求使用新参数。
- 保留一次 POST、结果不确定不重发、媒体归属与原来源交付。没有扩大到访客或无人值守消费。

减少重复确认会让已经启用且有凭据的旧配置立即可用于后续生成，这是本次明确的产品行为变更。仍可通过插件开关暂停；次数上限继续约束消费。就绪只代表本地配置完整，不代表 Token 已向供应商验证或账户有余额。

## 兼容与验证

旧 `manualEnabled` 写入在未提供 `enabled` 时作为其别名；公开读取返回有效开关。旧消费确认字段继续接收和保留历史结构，但不再控制准入，也不伪造历史确认。角色旧字段继续兼容读取，不迁移或删除历史账本。

错误解释从受控错误码生成，不展示供应商响应正文。验证沿用公开 API、实际工具调用、隔离 HTTP peer、React 用户操作及既有撤销/幂等/CG 回归，不使用真实账号或消耗。
