# ADR-0027：按可信身份共享外部成员资料，并以持久版本保护编辑

状态：已接受，按维护者要求实施多端对齐规格中的 A2、A3。

最后核验：2026-10-26

事实来源：[Issue #237](https://github.com/sawaki-zexi/meido/issues/237)、[完整对齐规格 PR #243](https://github.com/sawaki-zexi/meido/pull/243)、[外部会话资料规格](../specs/external-conversation-memory.md)、[资料仓库](../../backend/app/channels/external_memory.py)、[成员仓库](../../backend/app/channels/external_members.py)。

## 背景

[ADR-0009](0009-multichannel-conversation-threads.md) 将群友资料按线程整理，保证原文隔离，但同一人在两个群中会形成互不相识的档案。加入人工编辑后，仅比较整理前后的文字无法发现“清空后恢复原文”或“删除后重新学习”的竞争；进程内锁也不能覆盖重启和多个页面。

Shiori 的成员档案按角色及平台身份共享，保留昵称历史和来源。Meido 同时接入飞书、QQBot，应用内编号必须保留可证明的应用作用域，不能照搬仅平台加编号的键。

## 决定

- 规范档案属于角色，身份由渠道、作用域和真实发送者编号组成。QQ、Telegram 使用平台范围；应用渠道使用消息接收时保存的应用身份。缺少历史证明的旧资料保持独立历史作用域，不用当前账号配置反推。
- 会话关联和昵称观察独立保存。昵称来自宿主观察，模型不得改写。原始消息、运行、附件及投递记录保持独立线程。共享成员资料不会授予主人权限，也不会共享群笔记或群原文。
- 笔记属于线程，成员档案属于规范身份，两者都有单调递增的持久版本。人工保存、清空、删除、配对边界及自动整理使用同一版本。删除保留版本和墓碑；未来读取新快照的整理可以重新学习。
- 自动整理先取得资料与版本，在事务外调用模型；提交时短事务复验角色、账号来源、主人绑定、资料版本和原游标，原子提交全部资料及对应游标。冲突或失败不推进游标，不以最后写入者覆盖另一群的新事实。
- 群事件与成员事实分开输入。笔记和动态包含主人群发言及角色已确认送达的回复；成员事实排除当前或历史标记为主人的发送者及角色自身。主人私聊不使用外部笔记入口。
- 最近动态按最近三天、最多五个外部线程选择，排除当前线程及当前主人私聊。普通、自然接话、主动与 Drift 均在每次模型请求前重新读取候选，并计算完整请求的剩余预算。未填写模型容量时，额外资料采用本地 32768 token 输入容量基准扣除回复预留；这是 Meido 的保守预算，不是 Shiori 的字符限制或模型容量声明。
- 升级前创建并校验 SQLite 备份。导入、候选和完成标记在同一事务内写入；失败保留旧表，可恢复后重试。单来源或相同内容直接发布，冲突内容保留来源与候选，必须由主人选择或编辑后发布。自动整理只能增加冲突候选，不能代替人工确认。

## 取舍与后果

规范档案提高跨群连续性；因此修改和删除会影响同作用域下的多个会话，界面需要明确说明。版本冲突可能导致模型重算，但避免人工修改和并发群事实静默丢失。迁移保留旧表和备份增加磁盘占用，降级必须使用备份或经过验证的兼容路径。

本决定替代 ADR-0009 中“外部成员档案按线程独立整理”的部分。主人 MemoryEngine、原始 transcript 隔离、来源授权以及角色删除排空规则继续有效。
