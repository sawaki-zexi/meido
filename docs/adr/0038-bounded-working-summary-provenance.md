# ADR-0038：宿主保存完整来源，工作摘要使用有界集合引用

状态：已采纳；维护者已批准 [#351](https://github.com/sawaki-zexi/meido/issues/351) 的独立修复范围。最后核验：2026-11-10。
事实来源：[来源投影](../../backend/app/agent_runtime/summary_sources.py)、[压缩控制器](../../backend/app/agent_runtime/context_provider.py)、[HTTP 行为回归](../../tests/python/test_summary_sources.py)、[手动失败反馈](../../tests/python/test_compaction_memory_sources.py)。

## 背景

固定 Shiori `c14152ed225954a2a50da775075fe64dbf7b8b50` 的摘要仍回写原始消息 ID。长会话的来源列表即使没有正文也可能超过摘要限额，唯一一次缩短无法消除这一固定开销。只读诊断与合成复现支持这一缺口；报错现场没有保留实际摘要输出计量，因此不据此宣称已证明该次失败的唯一原因。本决定是经批准的 Meido 改进，不是上游已有修复。

## 决定

1. 保留现有持久化合同：六个状态字符串及完整 `source_message_ids`，以及窗口的完整 `removed_ids`、原文指纹、权限与版本。没有新表、迁移或中间提交。宿主独立证明切点覆盖；模型不能选择或扩大来源授权。
2. 每次压缩在记忆覆盖完成后创建宿主来源绑定。来源集合只包括此前合法摘要的来源和本批实际展示的原文，必须属于已准备的完整切点。集合引用固定为 `sources:` 加 24 位摘要值，绑定角色、会话、scope、authority、窗口版本、原文指纹、调用随机值、批次号和准确来源集合。预算探测和实际发送使用相同投影。
3. 本批原文和此前摘要的 `source_message_ids` 都投影为当前这一个集合引用。消息级 `message_refs` 仅区分发言；只对已识别的来源和引用关联字段使用对应短标记。范围外关联标为不同的 `unavailable:` 短标记，不准入为来源。说话人、平台消息号、工具调用号、业务正文和其中的标识符保留。
4. 模型输出先按当前唯一集合引用严格校验，再按投影正文计量；合法超长结果仍只允许一次缩短，并保留同一绑定。通过后由宿主恢复该批的完整原始来源列表。未知集合、消息标记、原始 ID、其它 scope、旧调用、旧批次和未展示来源不能作为本批输出来源。
5. 发送、只读检查、最小窗口和重启恢复共用同一个摘要投影入口：从合法持久摘要及角色/会话/来源范围派生一个稳定、有界的集合引用。既有合法摘要保持可读，普通读取不改写存储；最终输入继续由真实适配器准备并计量，不会因回放展开完整来源列表而膨胀。
6. 继续遵守 [ADR-0036](0036-shiori-context-memory-ownership.md) 的先覆盖、再摘要、最后原子提交。原文/权限/版本变化、取消、结构错误、未知来源和失败缩短不发布半成品，不重放工具。手动超长失败经现有 `reason` 返回实际计量、上限和计量口径；安全诊断的 `sourceCount` 表示完整原来源数量，不记录正文、原 ID、集合映射或凭据。

## 取舍

来源数组表达宿主绑定的完整证据集合，不再要求模型逐一回写其使用过的原始消息编号；具体业务事实和发言关系仍由六字段正文保留。宿主继续保存完整出处与覆盖证明。集合引用不能作为普通工具参数或权限凭据，也不提供新查原文工具。

生成时的集合引用按调用/批次失效，回放引用按合法已保存集合稳定派生；两者具有相同有界格式，最终请求始终重新按实际投影计量。真正超长的业务正文仍可能失败，预算不自动提高，JSON 不被截断，没有额外重试。
