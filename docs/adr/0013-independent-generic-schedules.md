# ADR-0013：独立于待办的通用调度

## 状态

已采纳。批准时间：2026-10-15。#158 本地实现待两轴复核及总 PR #162 集成，未合入 main；当前行为与限制见[调度契约](../reference/owned-schedules.md)。

## 背景

Shiori schedule 支持固定文本、到时模型执行、绝对/相对时刻、间隔和 cron。Meido 待办则属于主人共享清单，具有当天提醒者、当天暂停和次日生效等独立规则，不能将通用时间任务转换为待办来近似实现。

## 决定

1. 建立独立 Schedule 应用模块，复用宿主时钟、SQLite 和既有投递服务；不改变 ADR-0005 的待办领域规则。
2. instant 投递固定内容；soft 交独立 TaskRuntime 执行。调度记录计划时刻、IANA 时区、原始触发、消息接收时间、次数和幂等键。
3. 角色与来源从宿主绑定，不能由模型参数覆盖。创建、列表、取消及到时执行都重新验证相应归属与投递许可。
4. 失败、离线、过期和重启的补执行策略明确持久化并通过可注入时钟测试；不将已接受、已提交或结果不确定当作已送达。
5. 统一使用角色投递服务，不保留上游已经失效的 schedule → message_push 外部发送捷径。
6. 主动决策和 Drift 可共享任务/调度生命周期，但各自拥有事件 ACK、内容候选、活跃判定、草稿提交和结束协议。

## 取舍

独立调度可保留每种任务的角色、触发和执行语义，代价是需要额外的持久化与恢复规则。复用待办表更省代码，但会改变两种用户概念，不能满足完整复刻目标。
