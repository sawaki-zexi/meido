# ADR-0010：渠道能力启停与托管 QQ 接入

状态：已接受，按维护者在 Issue #134 的 Shiori 复刻要求实施

最后核验：2026-10-15

事实来源：[多端配置规格](../specs/shiori-channel-settings-spec.md)、[Shiori 源码研究](../research/shiori-channel-settings-ux.md)、[ADR-0009](0009-multichannel-conversation-threads.md)、当前渠道宿主与托管 NapCat 模块。

## 背景

原有账号启停只作用于一个角色，不能表达“暂停整个平台”。全局身份又被放在角色账号表单中，造成作用域混淆。Shiori 将渠道能力、角色账号和主人身份分开，同时管理本地 NapCat 的准备、扫码和进程生命周期。

## 决定

- 每个平台持久保存能力级启停，账号继续保存其独立连接意愿；实际连接和准入同时检查两者。迁移默认允许平台能力，保留旧账号行为；没有配置账号时不会建立连接。
- 使用已有宿主准入和连接排空边界管理平台暂停，等待角色锁的入站消息在启动回合前重新验证。恢复和重启只连接仍符合条件的账号，不通过重写全部账号 enabled 实现总开关。
- 全局配对和身份管理与角色账号分离，沿用现有一次性码与授权数据，不迁移会话或改写配对历史。
- 托管 QQ 复用 NapCat 平台适配器；管理器负责下载、环境检查、独立配置、官方二维码和进程，宿主负责角色/账号归属、真实身份确认及收发准入。
- 使用固定版本和摘要的上游运行包，私有目录按不透明引用隔离，本机随机端口和令牌不进入公开状态。Windows Job 管理本应用启动的进程树；不接管或终止外部进程。
- 保留现有外部 NapCat 连接作为兼容模式；托管模式不把内部本机地址暴露为普通可编辑账号配置。

## 原因与后果

保留账号意愿能让“暂停平台后恢复”与“主动断开某个账号”有不同且稳定的含义。复用现有渠道宿主可使界面简化保持原有线程、凭据库、权限及发送账本边界。

固定运行包及已验证的官方 QQ 版本增加环境要求，但将下载完整性和启动兼容性变成可诊断的条件。托管模式增加安装缓存、登录状态与进程清理责任；外部模式继续供已有部署和非 Windows 环境使用。首期只实现这些内置渠道的生命周期，不引入动态插件加载系统。

2026-10-25 补充：已验证的环境以运行包及所需依赖的固定摘要组合为准，不要求桌面 QQ 的当前版本与包内 wrapper 版本相同。首次准备将兼容依赖校验后缓存到私有托管目录，启动时重新校验缓存，避免桌面自动更新破坏已经准备好的连接。版本和验收范围见[多端配置规格](../specs/shiori-channel-settings-spec.md#qq-接入)。
