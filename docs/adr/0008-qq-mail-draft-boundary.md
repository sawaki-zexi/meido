# ADR-0008：QQ 邮件草稿边界与版本策略

## 状态

已接受

最后核验：2026-10-14

## 背景

邮件处理需要访问主人邮箱并产生外部副作用。QQ 草稿可能被主人在网页端编辑、删除或发送；如果自动重试直接复用旧快照，就会覆盖人工审核结果，或把不确定的远程状态误报为成功。重新生成还需要明确是否覆盖旧草稿。

## 决定

1. 邮箱适配器只使用 SSL IMAP。Meido 可以读取收件箱、已发送和草稿箱，也可以向草稿箱追加草稿；不提供 SMTP、发送、删除、归档或移动命令。
2. 草稿写入必须携带稳定的 Meido 标记，并在 QQ 草稿箱再次读取核验。核验不到时任务进入待核实状态。
3. 本地保存 QQ 草稿内容哈希和来源映射。同步发现远程哈希变化就标记人工修改/可能过时；普通处理和重试不得覆盖该草稿。
4. 重新生成采用“创建新草稿”策略：使用新的请求幂等键和远程标记追加版本，原草稿始终保留并可在网页查看。
5. 邮件任务、角色工具和提醒均使用持久状态与审计记录；邮件全文不进入普通角色会话或长期记忆。

## 取舍

追加版本会留下多个待审核草稿，需要网页清晰展示版本和状态，但能保留主人修改记录并避免不可逆覆盖。IMAP-only 限制了发送能力，却把发送确认留给主人，降低凭据和外部副作用风险。写入后重新读取增加一次网络请求，但能区分“服务端已写入”和“本地请求已发出”。

## 后果

- #95 的重新生成行为已经确定为创建新草稿，#96 和 #97 可以复用同一版本规则。
- 网络中断或 QQ 返回异常时必须显示待核实/失败，不能自动补建可能已存在的草稿。
- 后续若要支持附件、发送或其他邮箱协议，需要新规格和独立 ADR，不得扩大当前适配器权限。

## 验证

- `tests/python/test_mail.py` 验证自动处理幂等、重新生成保留旧草稿和角色工具不泄露凭据。
- 真实 QQ 账号验收验证文件夹访问、草稿写入、网页端编辑和主人手动发送。
