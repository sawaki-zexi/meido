# ADR-0025：主动推送设置与角色模型继承

状态：已采纳，2026-10-24 主人在 PR #215 审核中明确要求按 Shiori 简化。

本决定部分替代 [ADR-0018](0018-explicit-autonomy-and-drift-grants.md) 的独立开关与独立模型设置；原身份、授权和恢复边界继续适用。

## 背景与决定


PR #215 审核中，主人要求按 Shiori 简化名称和设置结构。常用入口改为「主动推送」，以一个角色开关控制主动判断及「空闲活动」，默认关闭；使用角色当前聊天模型，移除重复模型选择和额外同意勾选，开关旁说明模型用量。旧配置在读取时不迁移，保存常用设置时才切换到统一开关和角色模型继承。

「推送策略」提供日常 / 低打扰，「执行参数」默认折叠，保留推送步数、候选内容数、网页上下文字符数、空闲活动步数及最小间隔。名称、默认值和结构参考 [Shiori 执行参数](https://github.com/YinFengWindy/Shiori-Agent/blob/d149de7f052f77c5bb88d4d1393d48dce1870875/apps/desktop/renderer/src/roles/RoleProactiveExecutionFields.tsx)；Meido 沿用自身执行边界，不引入 Shiori 的 presence / relationship 调度。日常仍每 30 分钟检查，低打扰每 2 小时检查并使用更保守的推送提示；原日额度、token、时限及权限约束继续生效。

常用设置按版本合并，保留已配置的来源、工具、目标和表情授权。来源及工具许可仍须显式授予，空闲活动只执行已有获准技能；相关管理、停止、对账和记录移到「高级 → 开发者模式 → 主动推送诊断与授权」。关闭功能不受已失效的原授权阻塞，重新启用仍验证依赖。每次运行冻结当时的角色模型，角色或默认模型变化会使旧绑定失效；继承模型不自动改授表情视觉权限。
