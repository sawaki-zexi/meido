# ADR-0007：角色会话承载多端独立线程

状态：已接受

事实来源：

- 多端会话规格 [Issue #116](https://github.com/sawaki-zexi/meido/issues/116)
- [Shiori-Agent 多端接入实现](../research/shiori-multichannel-integration.md)，基线 `1c241a2627bbcc99124aef71abaee237ac057499`
- Meido 当前会话模型：`backend/app/session_store.py`、`backend/app/session_manager.py`、`backend/app/agent_runtime/`

## 背景

Meido 当前一个角色只有桌面会话。要接入 Telegram、QQ NapCat、官方 QQBot 和飞书，必须让一个角色拥有多个渠道聊天，同时确保访客、主人私聊、各个群和桌面之间不会意外共享原始上下文。ADR-0002 中“不引入 channel/chat_id scope”的决定针对当时不支持多端会话的范围；记忆的 `role_id` 硬隔离仍然有效。

## 决定

- 每个角色仍有一个共享角色会话和 Runtime；桌面及每个渠道私聊/群聊是独立的会话线程，不为每个平台复制 Agent Runtime。
- 每条消息和运行都关联结构化 `role_id`、`thread_id` 与来源账号；会话读取必须通过宿主上下文视图，不能以任意 JSON metadata 作为权限事实。
- 未配对私聊和群聊回合默认只读取当前线程。主人配对私聊从配对时间开始获得主人上下文；主人在群触发时可使用全部主人级工具，但原始群聊历史仍限当前群。
- 主人身份由宿主根据配对记录判定。平台适配器提供的 `sender_is_user` 等字段不能直接授予主人权限。
- 主人资料和主人私有信息不进入访客上下文；外部用户及群产生的信息按身份/群边界保存和检索。现有桌面记忆迁移为主人私有。
- 角色负责统一账号归属、身份、准入、线程路由和工具策略；静态平台适配器负责连接、事件解析、媒体和平台收发 API。
- 账号及平台能力遵循规格中的 Shiori 能力矩阵。角色每适配器最多绑定一个账号；平台不支持的功能明确拒绝。
- 现有会话历史迁移到角色的 `desktop` 线程，保留消息 ID、顺序、运行与工具记录。

## 原因

共享角色 Runtime 保留当前模型、角色设置、并发控制及运行生命周期。独立线程保留 Shiori 的上下文隔离和手机端网络会话展示。将 thread 作为结构化归属，使 Meido 可在数据库访问与上下文构造边界验证权限，不依赖插件始终正确维护 JSON 字段。

## 后果

- 会话、消息、运行和记忆查询需接受明确的线程/可见性范围；访客渠道请求不能调用桌面默认历史读取。
- 身份配对、绑定时间、账号作用域及角色/群可见性成为持久数据和验收契约。
- 角色记忆仍以 `role_id` 硬隔离；同时需区分主人私有、外部身份和群作用域，不能把访客内容提升为主人记忆。
- 新线程及账号删除不删除其他线程；删除角色时按角色清理全部渠道数据和待处理运行。
- 本决定替代 ADR-0002 中“Meido 只有唯一会话且不引入 channel/chat scope”的会话范围；ADR-0002 的 MemoryEngine 契约、SQLite 权威数据源、Markdown 视图及 `role_id` 记忆隔离决定继续有效。
