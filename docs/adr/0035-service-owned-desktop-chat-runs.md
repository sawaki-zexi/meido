# ADR-0035：桌面聊天任务由服务持有，SSE 只负责订阅

状态：当前，已采纳；维护者批准 #293 的任务归属、刷新续接和确切 Stop 方案。
最后核验：2026-11-02。
事实来源：[#293](https://github.com/sawaki-zexi/meido/issues/293)、[#291](https://github.com/sawaki-zexi/meido/issues/291) 流式热路径补充、[规格](../specs/chat-responsiveness.md)、[生命周期合同](../reference/chat-run-lifecycle.md)、[行为测试](../../tests/python/test_chat_lifecycle.py)、[流式持久化回归](../../tests/python/test_chat_stream_projection.py)。

## 背景

原 `/messages` 的 SSE 生成器同时负责执行、保存和清理。连接断开会取消任务；拟人补充输入还会在生成器启动前等待旧任务，因此只删除断线 watcher 无法保证已接受的输入得到收尾。前端通过相同正文推测是否接受，也无法区分同文输入和新旧运行。

固定 Shiori `be6343d1deaa62c69f27d33654e77020b8f17c67` 的 [DesktopChatService](https://github.com/YinFengWindy/Shiori-Agent/blob/be6343d1deaa62c69f27d33654e77020b8f17c67/apps/backend/desktop_bridge/chat_service.py) 由服务持有 turn task；task 覆盖 previous/background 等待及最终清理，终态等角色所有权释放后发布。本决定适配这一归属和顺序，不复制 Electron JSONL bridge。

## 决定

1. `ChatRunService` 持有接受后的桌面任务，消费既有 `RuntimeManager`；不引入另一套模型或工具执行器。提交、订阅、停止是独立操作。旧 `/messages` 保留为同一提交和订阅的兼容组合。
2. **替代 ADR-0003 第 6 条的客户端断开即取消部分**：关闭或刷新网页仅解除订阅。显式 Stop、服务退出与既有来源失效仍取消，并等待已开始的工具回执和清理。provider/tool 超时和权限边界保持原合同。
3. 浏览器在请求前生成 `requestId`，对应固定 `runId`。现有 run 快照保存规范化请求摘要；重复提交只可恢复同角色、同输入的接受结果，不重复写用户消息。丢失接受响应后只读取或停止这个标识，不按正文或当前活动运行兜底。
4. 拟人输入先原子保存 `queued` run、用户行及占位行，再由同一个服务任务等待前驱。`queued` 只表示已接受、未执行；随后使用 RuntimeManager 原角色锁转为 `created`。SQLite 的文本状态无需结构迁移，既有 `created/running` 唯一索引继续限制实际执行。排队取消也等待前驱，不能取消或越过旧工具。
5. 服务保留有界当前工具投影和事件环；生产者不等待订阅者。超出事件窗口时明确发送快照信号，客户端读取数据库历史及所有者的当前消息投影和游标，再接续事件。#291 补充沿 Shiori 的回合所有权，在片段到达时只更新已有运行正文／公开思考和发送事件，不逐片段提交 SQLite。所有者向既有恢复入口提供当前占位消息，完成消息与真实工具回执仍在原边界持久化；Stop、失败及有序退出在发布终态前保存部分内容。结束时清除读取入口，不保留另一份历史或永久逐 token 日志。
6. Runtime 结束不等于桌面任务结束。工具清理、附件处理、拟人多段发送完成之前，恢复投影仍是活动状态；终态事件延后到所有者完成收尾，避免界面恢复发送后撞上上一条清理。重复 Stop 等待同一任务，不反复取消 cleanup。
7. 前端的角色选择只决定所看订阅；旧连接、旧角色及旧 run 事件不能写入新视图。准备、摘要、模型请求、工具调用及收尾阶段由真实边界发布。按 2026-11-01 的展示纠正，界面沿 Shiori 用头部输入状态和空回复光标表示等待，不常驻展示内部阶段文案；消息过程区保留真实模型思考及工具反馈。
8. 沿用 ADR-0034 的独立 I/O worker 边界，恢复接口不在事件循环执行 SQLite 和历史投影。当前占位消息在事件循环捕获，worker 仅将它覆盖到相同运行、相同会话及相同消息 ID 的未完成记录；Runtime 已保存失败正文但桌面仍在清理时，只补充尚未保存的公开思考，不覆盖持久终态正文。worker 读取前后由事件循环校验现有运行引用、序号及最新接受身份；三次无法取得一致视图便返回可重试 503，不用暂停生产者来保证读者进度。已接受 POST 改用 202 身份回执，确切运行 503 也确认该身份，避免把暂时不能投影误判为未接受。不新增永久逐 token 表或另一层全局序号。
9. 使用薄的 Meido Uvicorn Server 适配，在 HTTP/SSE drain 前先关闭聊天所有者。仅 lifespan shutdown 太晚，会等待长连接退出才取消模型。保持 Uvicorn 原文件监听和 worker 创建，reload 前同样等待精确任务及工具清理；Windows 自有开发 launcher 使用私有 stdin 控制，共享退出信号只传给其 reload worker，不强杀其他请求或服务。支持入口和原生 uvicorn 的边界写入运行手册。

## 取舍和恢复

网络中断后运行继续，用户需要显式 Stop 才停止已接受的回复。进程内投影不会跨重启保留；启动将 `queued/created/running` 收敛为失败并保留已经写入的原输入、消息和工具记录，绝不重放模型或工具。跨进程自动续跑不在本决定范围。

#291 的这次补充明确改变旧实现逐片提交所提供的耐久性：显式 Stop、模型失败及支持入口的有序退出会保存部分正文与公开思考；SIGKILL、进程崩溃或断电可能丢失当前模型消息尚未到消息边界的片段。已接受用户消息、已完成模型消息、已保存工具回执和成功摘要不受此取舍影响。隔离测量中 300 次同步占位更新耗时约 2.47 秒，逐片提交放大本地等待；选择沿现有回合所有者收尾保存，避免后台写队列、定时刷新配置和永久 token 表，不能声称任意强杀都保留最后一个片段。

事件环会舍弃中间增量，因此协议要求处理序号缺口，不能将 SSE 当成完整审计日志。当前文本复用运行本来已经累积的一个活动消息，公开思考仍限 16 KiB；历史过程从既有工具记录投影，不增加另一份全文历史或按订阅者累积的内容。边界与数值见生命周期合同。

角色删除同时检查 Runtime 和尚未清理的桌面所有者；queued 也阻止删除。全局活动查询优先返回正在执行的运行，避免桌面排队输入遮蔽渠道的当前运行。工具准入仍只接受已进入执行的 `created/running`，queued 不授予任何工具能力。
