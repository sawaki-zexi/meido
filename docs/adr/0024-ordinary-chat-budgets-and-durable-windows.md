# ADR-0024：普通聊天全局预算与持久工作窗口

状态：已采纳。2026-10-19 主人明确批准[高级设置方案第 3 节](../specs/advanced-settings-parity-spec.md)。实施验收状态以该规格为准。

事实来源：Shiori 固定 076a87b 的 input_budget、compaction 与 session/window；[七栏审计](../research/shiori-settings-implementation-audit.md)。

普通桌面与渠道回合冻结全局高级配置和有限模型请求预算；压缩请求也计入同一次预算。专用视觉、Coding、NovelAI、主动与 Drift 保持既有用途预算及许可。暂停创建子任务推进撤销代，恢复不能使旧运行重新获得创建或接续权；查询和取消继续可用。

配置及幂等操作结果在独立 SQLite 存储中原子保存，先查同 operationId 的原结果，再检查修订。保存队列保留失败草稿和不明结果，确认写入后的回读失败只重读。运行应用以已提交配置作可重复协调；计时器交接由原请求负责收尾，保存不立即触发优化。

采用显式模型容量及本地输入估算，在真实 provider 边界计量完整系统、记忆、schema 和消息。工作摘要与 cut 在 sessions.db 同事务条件提交，按角色、会话和来源 scope 隔离，后续回合及重启继续读取。提交依赖原文指纹、窗口版本、当前来源权限以及 MemoryEngine 的维护覆盖证明；尝试维护不等于覆盖。记忆暂停或来源无义务时明确 not_required。

原始历史保留。历史修改/撤销使受影响窗口失效，角色删除的回滚恢复原窗口；备份含同一 SQLite 表，读取时仍验证当前来源。更换模型重新计量，不删除合法摘要；未知容量仅停新压缩并保留兼容原文尾部及已有摘要。

取舍：持久窗口增加历史生命周期的维护责任，但避免跨回合反复付费生成同一摘要。服务商 tokenizer 各异，因此估算保留安全余量并明确限制；超大完整轮或摘要请求前缀不能装入时明确失败，不无限分块、重试或静默丢原文。有界诊断代替上游完整 payload 快照，保持既有凭据与原图不额外进历史的约束。

## 2026-10-28：#265 按当前 Shiori 修正失败降级

上文保留持久窗口、完整计量及原历史不删除的决策。原“摘要不合法即终止普通聊天”的实现不符合当前 Shiori：辅助压缩失败后，软阈值且原请求仍在硬预算内直接保留原请求；硬超限时临时使用当前输入、既有合法摘要与工具回执，保留必需渠道身份，禁用业务工具并重新计量。必需块仍超限才明确失败，失败摘要绝不提交。

辅助请求仍计入请求步数，但拥有独立 30 秒上限，不耗尽正文 deadline。支持显式关闭思考的已识别端点按供应商协议关闭辅助思考，未知端点不添加私有参数。安全的阶段、结束原因及用量始终保存，开发者模式只控制界面展示，避免关闭开发者模式后完全无法定位故障。采用现有窗口表与诊断元数据，无新存储迁移或删除。

## 2026-10-29：对齐摘要请求默认期限

维护者要求输入预算等默认配置对齐 Shiori。回复上限 8192、摘要上限 2000、压缩触发比例 0.75、目标比例 0.4、安全余量 4096、保留原文 2 轮及新安装迭代上限 40 已一致，不修改已保存的模型容量或用户设置。

将上节的摘要独立期限由 30 秒调整为 90 秒，与 Shiori `LLMProvider` 的 `request_timeout_s=90.0` 默认额度一致；上游 `SummaryRequest.rewrite` 通过该 provider 调用摘要，没有额外的 30 秒期限。源码基线为 Shiori `d149de7f052f77c5bb88d4d1393d48dce1870875` 的 [provider](https://github.com/YinFengWindy/Shiori-Agent/blob/d149de7f052f77c5bb88d4d1393d48dce1870875/apps/backend/agent/provider.py#L360) 与 [摘要请求](https://github.com/YinFengWindy/Shiori-Agent/blob/d149de7f052f77c5bb88d4d1393d48dce1870875/apps/backend/core/compaction_summary_request.py#L87)，2026-10-29 同时核验上游 main 相应默认值。

此处只对齐时间额度，不声称复制上游 provider 的重试及流空闲超时语义。摘要仍独立计时、可取消、计入请求步数，正文期限及失败回退不变；慢摘要可能让正文开始前多等待最多 60 秒。没有运行中配置迁移，也不据此宣称长历史工具续接或角色参考生图已修复。

## 2026-10-30：#277 保留预算内的授权工具与摘要协议

两次桌面运行约 201/146 秒，完整输入本地估计 97,236/98,587，硬输入上限 87,712；摘要失败记录为 TimeoutError/ValueError，随后 minimal 的 `toolsDisabled=true`、`toolCount=0`。角色自然分条关闭，因此自然模式的事件缓冲不是这两次慢回复的解释。辅助摘要约 29.9k、最小正文约 1,413 实际输入来自不同请求，不能直接替换完整请求的输入估计。日志未提供 ValueError 的结构化具体原因，JSON 协议差异只是源码证实的缺口。

本次覆盖 #265 的“硬预算回退禁用业务工具”：保留本次已授权声明并重新计量最小请求；必需块、工具结果及声明仍无法装入硬预算时明确失败，不提交失败摘要或删除原历史。发现工具继续按原授权冻结目录工作，下一请求载入新声明，既有撤权与执行检查不变。固定 Shiori `d149de7` 的 minimal 仍清空业务 schemas，本改动是为满足长历史工具连续性而保留的明确差异，不称为上游原样行为。每个后续请求重新检查预算，不建立跳过预算的工具特例。

摘要请求对 OpenAI completions 链传递 `response_format: json_object`；其他协议不添加该参数。验证要求必需六字符串字段与合法来源 ID，允许额外字段后规范化投影和去重。长度优先使用有效的供应商输出 token；缺失用量，或移除额外字段/重复 ID 且原用量超额，才用规范化文本本地计量。结构合法但超长最多缩短一次，截断或结构非法不提交。诊断增加失败阶段以便后续区分前缀装不下、请求失败与校验失败，不记录完整正文或凭据。

来源：[固定上游及数据流核验](../research/shiori-live-reply-tool-loading-2026-10-30.md)。本地 HTTP 验证覆盖硬预算回退后发现 deferred 工具、下一请求真实执行、always-on 生图模拟工具可见、禁用候选不出现以及最终回复。没有引入 Shiori 的摘要分批或 actual/anchor_delta 输入校准；本地估计保守导致反复压缩的可能性仍存在，不能宣称本次消除了全部长历史等待。

## 2026-10-30：#282 按单次实际输入校准预算

此前仅本地估计的行为由已批准 [#282](https://github.com/sawaki-zexi/meido/issues/282) 扩展：复用各协议实际请求的纯准备入口，以相同请求的实测量或可比较前缀的实测加差值驱动预算；工具、格式、模型连接、历史改写或真实来源改变则回到本地估计。静态系统约束不变更性质，时间、记忆和活动资料使用明确的宿主上下文帧。

采用固定 Shiori `71c8b0e` 的 64 上下文 LRU 和最新 pending 响应约束，普通回合复用现有冻结授权身份，摘要排除、独立子任务临时存储。无账单持久化迁移，未知容量不显示假百分比，实际输出预留、安全余量与预算内保留工具的决定继续有效。协议合同、生命周期、诊断字段与验收见[输入用量校准](../reference/input-usage-calibration.md)。本次不实现分批摘要。

## 2026-10-30：#283 按辅助预算连续分批归纳

已批准 [#283](https://github.com/sawaki-zexi/meido/issues/283) 将“整段摘要输入装不下即失败”扩展为固定 Shiori `71c8b0e` 的连续分批：优先整批，否则选择最长可容纳原文前缀，前批合法摘要进入下一批；单条按上游逐步收缩文本，最低可用输入仍超限才失败。保留既有六字段/来源/输出长度合同、一次缩短和每次真实请求的步数、用量及期限，不新增摘要流水。

全部批次与最终预算成功后才在原事务一次提交；记忆覆盖等待后再次按当前窗口工具计量，防止等待期间声明变化造成超限摘要已落地。取消或失败保留原文及旧摘要，工具行为继续遵守 #278 与 ADR-0032，辅助用量不成为普通请求锚点。取舍是超长历史可继续归纳，但可能产生更多请求与等待，仍受有限步数约束。准确收缩下限、提交条件与验证见[分批工作摘要](../reference/working-summary-batches.md)。
