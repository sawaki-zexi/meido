# ADR-0005：待办工具与角色主动提醒边界

## 状态

已采纳

最后核验：2026-10-09

## 背景

待办既需要在自然对话中管理，也需要由角色主动发送提醒。若对话整理器、模型工具、前端和调度器分别实现待办写入或提醒逻辑，会造成行为不一致。若把角色提醒作为普通用户回合写入，也会错误触发待办整理和记忆维护。

## 决定

1. 待办操作通过 Agent Tools 暴露给角色；`todo.write` 处理创建、修改、完成、取消和恢复，`todo.search` 可提供只读查询。Tool 是调用入口，不是权限边界。
2. 后端待办应用服务是所有待办写入的唯一规则入口。角色工具和网页 API 共用该服务；后端负责主人范围、输入、目标、状态转换和幂等校验。模型不能直接写存储或扩大作用范围。
3. 每日从可用提醒角色中随机选择一位并持久保存当日角色。该角色负责当天 04:00 汇总和所有精确时间提醒；角色失效时重新选择，没有可用角色则不发送。
4. `todo.reminder_control` 只允许当前角色加入或退出自己的提醒资格；变更从次日生效。当天暂停是主人级操作，只在主人明确要求时执行，并自动在次日恢复。
5. 调度器以待办存储为提醒事实来源，调用选定角色生成自然语言表达。精确时间和每日汇总属于同一当天角色。
6. 成功提醒写入角色会话并标记为 `proactive_reminder`，但不构成用户回合，不触发待办整理，也不进入记忆维护输入。投递状态必须持久且可去重。

## 取舍

模型能够提出待办操作，因此意图识别依赖模型对主人表达的理解；统一应用服务仍保证模型不能绕开数据校验或访问其他主人数据。将提醒写成角色主动消息可以保留角色人格和会话体验，但要求会话持久化与记忆/回合处理能识别消息类型。每天固定角色会降低逐条随机带来的变化，同时保持一天内提醒者一致。

## 后果

- TodoPlugin 需要提供共享应用服务，供 Agent Tool、前端和提醒流程调用。
- 提醒配置需要保存可用角色资格、当日角色选择和当天暂停状态。
- 调度器需要创建可恢复、可去重的主动提醒消息；用户回合和记忆消费者必须忽略此类消息。
- 现有 PR #91 的只读查询和应用内提醒收件箱属于基础实现，未满足本 ADR 的目标；实现状态以源码与测试为准。
