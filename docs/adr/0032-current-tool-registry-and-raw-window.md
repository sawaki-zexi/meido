# ADR-0032：按当前注册表执行，从当前原文窗口恢复工具

状态：已采纳；2026-10-30 维护者明确批准“工具执行绑定 / 已加载工具恢复 / 按 Shiori 的来”。

事实来源：[Issue #280](https://github.com/sawaki-zexi/meido/issues/280)、[规格 #279](https://github.com/sawaki-zexi/meido/issues/279)、[当前工具回归](../../tests/python/test_current_tool_registry.py)、[窗口回归](../../tests/python/test_context_windows.py)。上游基线为 Shiori `71c8b0e460530683cd28aad6bb62e873c7167c89` 的 `agent/tools/registry.py`、`tools/execution.py`、`core/passive_turn/helpers.py` 和 `reasoning_loop.py`。

## 背景与取舍

ADR-0026 将每次请求的定义与执行方法固定，正常完成后保存独立 `toolSelection` 指纹选择。工具更新必须等待新的请求或运行，压缩后的原文与恢复集合可能不一致。维护者认为这些防御超过当前产品需要，选择上游当前注册表与原文窗口规则。

本决定替代 ADR-0011/0026 中的请求执行器固定、完整定义相等门槛、同回复不可调用新解锁工具和选择缓存恢复；保留原记录供解释历史。真实角色、渠道来源、受管任务归属、原目标投递与历史审计事实继续有效。

## 决定

1. 每次调用按名称查当前实现；执行钩子之后，检查当前来源许可和最终参数，再进入当前实现。替换或重连后的下一调用使用新定义和实现，已注销或当前不可用工具不能调用旧对象。已经进入函数的调用自然完成；宿主停止、超时和工具自身的领域取消规则继续生效，不重放旧效果。
2. 常驻工具按注册顺序提供，再按实际原文窗口中使用/解锁名称的首次出现顺序去重，按当前定义和来源规则筛选。成功搜索结果先保存为原调用回执，然后立即更新后续调用可见性；同一模型回复也按调用顺序处理。本轮尚未加载的调用记录不自行解锁下一模型步骤；新用户回合仍按原文恢复旧历史使用名称，包括失败调用。
3. 解锁名称随原 `tool_result` 的 `unlockedTools` 保存。旧搜索结果中的 `details.unlocked` / JSON 可读取。停止读写独立 `toolSelection`，旧 JSON 和数据库列不删除。历史清空、线程切换和原文窗口水位推进后，不从旧选择缓存补回工具。
4. 请求构造、压缩候选计量、压缩后的实际声明和重启共用原文窗口选择。摘要不是原文，不产生工具解锁。自然回复的 `finish_reply` 属于宿主协议，压缩保留该声明，格式纠正仍只提供该协议。硬预算回退沿用 #278：保留当前合法工具并计量，仍放不下才明确失败。
5. spawn 保留明确的名称范围和原宿主身份，后续调用查当前工具；soft schedule 保存名称范围，旧完整声明只用于读取名称。MCP 重连更新当前目录和参数定义，原 peer 已进入的调用仍按其真实结果收尾。Drift 作者证明仍记录实际 run/call/技能内容与产物事实，旧定义指纹仅是审计资料。钩子可替换工具，所以业务执行前应将既有未结束调用审计同步绑定到实际选中的定义；不修改已结束审计或建立第二份账本。

移除固定执行门槛后，模型基于旧 schema 产生的参数可能在更新后被当前定义拒绝；模型可据实际错误调整下一调用。工具卸载不会自动撤回已经发生的外部动作。没有新增恢复缓存、工具目录服务或迁移账本。
