# ADR-0034：准备投影与执行授权分离，按配置保留完整轮次

2026-11-02：上下文/记忆的后续变更由 [ADR-0036](0036-shiori-context-memory-ownership.md) 替代；本文保留原决策历史，其余适用边界继续有效。

状态：当前，已采纳；维护者于 2026-10-31 批准三票及整体架构对照。
最后核验：2026-11-02。
事实来源：[#291](https://github.com/sawaki-zexi/meido/issues/291)、[规格](../specs/chat-responsiveness.md)、[调研](../research/chat-responsiveness-shiori.md)、[准备回归](../../tests/python/test_context_preparation.py)、[流式边界回归](../../tests/python/test_stream_preparation.py)。

## 背景与取舍

原候选估算重复进入真实执行授权：每个候选、每个工具及 namespace 提示都重新读取整套宿主状态。长历史把同步 I/O 放大到 25 秒。永久缓存授权虽然快，却会破坏 [ADR-0032](0032-current-tool-registry-and-raw-window.md) 的当前执行规则。

## 决定

1. 每次准备先异步读取宿主事实，生成仅用于请求描述的工具元数据及上下文块；候选筛选、namespace、提示渲染和计量使用这些值，不反复回调宿主。摘要／覆盖检查等待后重新准备，失败回退也使用当前事实。
2. 请求输入显式包含 rich messages、工具声明、模型配置和输出上限。摘要及覆盖检查等待结束后，捕获最终候选与对应可见工具视图，校验容量后提交水位；提交成功直接发布该视图并发送同一输入，不因提交期间注册表变化重新筛选或计量。提交失败才重新准备原窗口的回退请求。真实执行仍核验当前定义及许可，已经发送的声明不冻结执行权。估算与发送复用既有 adapter 规范化，估算不隐式改写 provider 提示字段；无需更换厂商 SDK。
3. 真实工具调用仍按当前注册表、来源许可及最终参数准入。准备投影不授予执行权；搜索结果仍先保存真实回执，再发布同轮可见性。
4. 自动压缩从配置保留的完整已完成轮数向零递减，保留当前输入、连续未完成输入和全部工具交换。默认两轮最多三个不同候选。目标预算无法达到时优先保留硬预算允许的最大轮数；实际摘要与最终工具完整计量后再提交。
5. 窗口来源 fingerprint 批量读取后按原 ID 顺序还原，保留现有哈希、版本、失效墓碑及提交事务，不迁移数据库。独立 I/O 放到 worker，注册表、可见性发布和用量锚点由运行所有者管理。取消已开始的窗口写入时通知信号并等待事务退出，避免终态后的迟到写入。
6. 普通请求及辅助摘要在准备、发送、接受完整结果和窗口提交边界验证固定历史内容，完整读取放到 worker。SSE 回调仅检查取消、角色及当前来源许可，不逐片段重新解析和哈希全部历史；适配器已检查的事件不再重复检查。固定来源许可集合为空时，不查询当前授权表：后来新增的授权本就不会扩展该窗口；角色与来源账号检查保持执行。集合非空时仍逐片段检查撤权。缓冲事件之间协作让出，允许页面请求和 Stop 推进。流中删除或修改历史在接受结果时拒绝，不能提交成功回复、工具调用或摘要。工具回执进入下一请求前仍重新核验来源，成功摘要沿用现有持久窗口复用。
7. 候选准备返回既有 `PreparedRequest` 与 `InputEstimate`，选择结果由单次请求局部持有；纯试算不覆写 wrapper 上的待发送状态。普通未压缩输入只进行一次预算准备，实际供应商用量锚点仍在发送边界记录；摘要、覆盖等待及失败回退按原规则重新准备。

## 影响与边界

默认两轮会比旧“从最早切点尝试”更积极地移出较早原文；原文仍保存在数据库，并遵循既有工具原文窗口恢复规则。外部模型和摘要的网络等待仍存在，本决定不保证模型速度。

本决定补充 ADR-0024 的保留轮数选择方式，不替代 ADR-0032 的即时执行规则。摘要正文计量及缩短反馈见 #292；刷新续接与任务归属由 #293 和 [ADR-0035](0035-service-owned-desktop-chat-runs.md) 实现，后者明确替代 ADR-0003 的断线取消行为。本次没有引入全局永久缓存、代际 Runtime 或新数据库 schema。
