## 1. 当前实现范围

主人可以为角色配置 Telegram、QQ NapCat、官方 QQBot 和飞书账号，从外部渠道私聊或在受支持的群聊中与角色交互。Meido 网页提供账号管理、渠道线程和历史查看，并随消息更新。宿主统一处理账号归属、身份、准入、线程路由、工具权限、目标目录和投递账本；平台适配器负责连接、事件解析、媒体和平台 API。

当前实现包含一次性配对、私聊/群聊 transcript 隔离、主人识别、访客工具限制、NapCat 群旁听、群成员与笔记工具、角色回复和目录目标投递。当前不引入云端服务、多主人账户、动态插件市场或远程插件执行环境。

## 2. 当前产品行为

- 账号可独立启停，设置私聊/群聊响应范围，并按发送者 ID 或平台别名屏蔽用户；未配对私聊按访客处理。
- Telegram 和 NapCat 群聊在 @ 角色或回复角色消息时触发回合；NapCat 可按群启用旁听，非触发消息只入库。
- 已配对主人在群中可使用角色已启用的主人工具；模型初始原始聊天历史仍限当前群，不自动合并其他群、私聊或桌面历史。
- 访客只能使用显式标记 `external_allowed` 的工具，能力声明和执行入口均受校验。访客主动发送只能使用当前账号联系已配对主人。
- `account_targets` 返回账号已观察或发现的目录；主人发送使用目录项 ID，角色回复固定当前线程。平台不支持的目标类型被拒绝。
- 投递账本区分 `pending`、`sent`、`failed` 和 `uncertain`；启动时遗留 `pending` 转为 `uncertain`，不自动重发。

## 3. 平台能力矩阵

| 适配器 | 私聊 | 群聊 | 群触发 | 旁听 | 目标发送 |
| --- | --- | --- | --- | --- | --- |
| Telegram Bot | 支持 | 支持 | @角色或回复角色消息 | 不支持 | 已观察到的私聊/群聊；受 Bot 权限限制 |
| QQ NapCat / OneBot | 支持 | 支持 | @角色或回复角色消息 | 支持，按群配置 | 已观察到的私聊、群和可发现群成员 |
| 官方 QQBot | C2C 私聊 | 未实现 | 不适用 | 不支持 | 已观察到的 C2C 私聊 |
| 飞书 Bot | 支持 | 未实现 | 不适用 | 不支持 | 已观察到的私聊 |

各适配器声明私聊、群聊、旁听、媒体、回复、流式编辑和目标类型能力，网页展示这些能力并禁用不支持的群响应开关。Telegram 私聊通过消息编辑显示流式回复，QQBot 使用 C2C 流式消息，飞书使用 CardKit 卡片；群聊与 NapCat 使用最终回复。平台不支持编辑或卡片权限不足时，适配器依据是否已经部分投递决定回退或标记不确定，不能重复外发。实际可收事件和可发目标仍取决于平台权限、部署与账号配置。

Meido 的 Telegram @/回复触发比研究基线中仅 @ 的条件更完整。飞书和 QQBot 群聊扩展须另行验证平台事件与权限，不作为当前能力。

## 4. 账号与身份

配置入口和 QQ 托管生命周期以[Shiori 多端配置与 QQ 扫码接入规格](shiori-channel-settings-spec.md)为准：全局“渠道”管理平台启停，“我的身份”管理配对，角色详情“账号”管理接入；手机会话不再常驻账号表单。

每个角色每种适配器最多绑定一个账号，同一平台账号只能归属一个角色。账号保存角色归属、平台身份、启停状态、私聊/群聊开关、屏蔽列表、显示信息和连接错误；网页支持添加、修改、测试、启停和移除。已登记的平台身份不能原地替换成另一机器人或应用，需删除后重新添加。移除账号停止连接并清理凭据、该账号作用域的身份、主人私聊关联、主人投递目标、目标目录和群开关，保留历史线程与消息；平台作用域的主人身份仍供其他账号识别。系统凭据库清理失败时保留已停用的账号记录，以便重试。

Bot token、App secret 等使用系统凭据库，凭据键包含渠道、账号和凭据名称。普通配置与公开响应不保存明文凭据；系统凭据库不可用时不回退到明文存储。

网页生成的配对码默认 10 分钟有效，全应用只有一个待用码，仅保存在当前进程；生成新码或重启后旧码失效。可从任一已连接角色账号的私聊消费，不受生成页面的角色或平台限制。配对命令及确认不进入会话历史，不触发角色模型回合。主人身份由宿主的全局绑定识别：Telegram/NapCat 使用 `platform` 作用域，一次绑定适用于该平台所有角色账号；QQBot/飞书使用 `account` 作用域，只适用于绑定的机器人应用。身份共享不跨角色共享原始历史或角色记忆。全局“我的身份”中的“已配对主人”可刷新和解绑；解绑撤销身份、私聊上下文及主人目标授权，并取消相关提醒目标配置，保留聊天和投递记录。重新配对不会恢复先前的提醒订阅。

配对从成功时刻起建立当前私聊的上下文边界，不追溯授权配对前的访客消息。主人后续在新私聊中发言时记录该聊天的授权起点和最近活动；主动联系主人时，从当前账号仍有效的配对私聊目标中解析。

## 5. 会话、线程和权限上下文

线程表结构化保存 `role_id`、`thread_id`、`session_key`、渠道、账号、平台 `chat_id`、聊天类型、标题和最后活动时间。桌面线程 `desktop:<role_id>` 指向已有 `role:<role_id>` session；外部聊天各使用独立 `thread:<thread_id>` session。各线程共用角色级 Runtime 管理、配置和并发锁，不共用 transcript。

消息通过 session 归属线程，渠道消息 metadata 保存线程、账号、发送者、引用和 @ 等来源信息；渠道运行的 snapshot 保存线程和权限信息。入站消息和确认已发送的主动消息保存宿主产生的公开账号来源快照，线程保留 `viaAccount` 与账号移除标记。头像由宿主独立缓存并在读取时投影，身份授权不依赖头像或显示名。当前未把所有消息及运行来源改成独立数据库列，统一构造器仍可作为接口深化方向。

当前模型初始上下文与权限如下：

| 回合来源 | 可读原始消息 | 权限与自动注入 |
| --- | --- | --- |
| 桌面 | 桌面 transcript；可加入已配对主人私聊的授权片段 | 主人级；角色已配置渠道账号时才注入渠道工具，实际发送要求可用账号；不读取访客或群原文 |
| 已配对主人私聊 | 当前私聊授权起点之后的 transcript；桌面及其他已授权主人私聊的近期文字片段 | 主人级；注入角色记忆上下文 |
| 未配对私聊 | 当前私聊 transcript | 仅 `external_allowed`；不注入主人记忆或主人资料 |
| 群聊主人触发 | 当前群 transcript、本群近期旁听、笔记/摘要及相关成员档案 | 角色已启用的主人工具；不自动注入主人私有上下文 |
| 群聊访客触发 | 当前群 transcript、本群近期旁听、笔记/摘要及相关成员档案 | 仅 `external_allowed`；不自动注入主人私有上下文 |
| 旁听 | 只保存到当前群，不创建模型回合 | 不适用 |

主人权限由宿主查询已保存的配对关系，不能由适配器或消息 metadata 中自报的身份字段授予。群内主人可使用记忆检索、主人资料等已启用主人工具；这些工具返回内容可能进入群回复，这是保留 Shiori 主人群权限的结果。

每个渠道回合的初始 transcript 截止当前触发消息，排队期间后来的发送者消息不会成为这个回合的当前请求或继承其权限。模型输入包含宿主生成的渠道、聊天、发送者、主人/访客身份、结构化提及和附件标识；持久化正文仍保留原发言内容。

角色 MemoryEngine 的既有记录保持主人私有分类与 `role_id` 隔离。已配对主人渠道回合可以提取主人长期事实；主人在群中的发言按可信身份处理，群友不会因此进入主人记忆。主人私聊完成后，Markdown 的 `RECENT_CONTEXT` / `HISTORY` 使用桌面与已授权主人私聊的共同视图维护，保留各消息的原始 session 与序号；独立维护顺序不会改写桌面 API、运行 transcript 或数据库消息序号。读取近期主人上下文前重新投影当前授权关系，解绑后不再通过旧 `RECENT_CONTEXT` 暴露私聊原文。

陌生私聊和群聊整理只更新当前线程的成员档案、群笔记与摘要，不写入主人 MemoryEngine；回合只自动注入当前线程相关档案。旁听使用独立整理游标，可信主人旁听发言可进入主人事实，群友旁听仅形成当前群的外部资料。模型返回的成员 ID 必须来自当前整理输入，角色删除和关闭时会排空或取消对应维护任务。

## 6. 群聊、旁听与群上下文工具

适配器依据平台 @ 或 reply 元数据判断群触发，不使用正文关键词冒充触发。入站记录保存平台消息 ID、发送者、引用消息 ID、引用正文/附件和被提及成员等 metadata；模型本回合可看到引用内容，持久化正文仍是发送者自己的发言。旁听不下载图片、文件或引用附件。渠道回复引用当前触发消息，NapCat 群回复原生 @ 触发者；平台原生展示效果仍需账号部署时验证。

NapCat 旁听按角色/账号/群持久化开关并记录操作人。非触发消息写入独立旁听存储，不进入正常回合 transcript、不触发角色回复或工具；每日默认最多入库 200 条，可设置全局默认与单群覆盖。达到入库上限后的消息只保留于内存最近 30 条窗口，仍可成为当前群近期上下文，重启后不恢复溢出窗口。网页提供独立旁听分页、每日计数、配额设置和清理；清理不删除同群触发回合与角色回复。旁听每批 50 条整理，跨天不足一批的记录由 30 分钟扫描收尾，独立游标只在结果通过当前线程及乐观版本校验后前进。

`lookup_group_member` 可供访客使用，但仅查询当前群目录中已观察/发现的成员。群笔记和摘要查询/修改仅供主人，按角色及群线程归属校验；主人可以查询同角色其他群已保存的笔记，工具不返回原始聊天。旁听设置仅主人可修改，主人在群回合中只能修改当前群的旁听。

## 7. 工具、目标目录与主动发送

Tool 定义携带风险和 `external_allowed` 等策略；冻结能力快照控制模型 schema，运行时和渠道宿主再次校验执行。访客 `account_send` 只能传 `target_id="owner"`，宿主强制使用当前来源账号，并解析该账号的已配对主人私聊；访客无法自选账号或任意目标。主人回合可选当前角色账号及其目录目标，普通回复只能发回当前线程。

`account_targets` 返回持久目录中的稳定目标 ID、类型、显示名、账号和能力。目录由适配器观察或发现，发送前还需通过适配器的目标类型校验；它不保证平台此刻一定接受发送，最终结果以投递状态为准。向群成员私发使用平台支持的私聊或临时私聊目标，消息和附件记录到该成员私聊线程，不写回原群 transcript。

主动投递在目标线程记录出站消息，模型回复在原运行消息上补充投递状态。账本保存账号、目标聊天、内容、时间、状态、平台消息 ID、错误类型、来源回合/工具调用或提醒事件，以及实际使用的连接代次。网络结果不确定时标记 `uncertain`，不自动重发；网页消息显示状态和平台消息编号，账本有查询接口。

`message_push` 解析当前角色仍已绑定的主人私聊，支持文本、图片与文件，并同步到目标线程。主人可在对应私聊的“会话设置”显式选择接收待办提醒的已配对私聊，停用、解绑或删除账号时不改投其他目标；同一提醒对同一账号只尝试一次，外部失败或不确定不影响桌面提醒。发送前重新校验当前身份和目标授权。

消息支持文本、图片和文件，每条最多 4 个附件，单个最多 10 MB，角色附件存储上限 256 MB。附件存储按角色归属；访客发送附件还需证明附件 ID 出现在当前线程，主人发送可使用当前角色的附件。平台不支持的媒体或目标返回错误，不能假定部分内容已成功投递。

## 8. 网页同步

网页“手机会话”按角色列出线程，以最近活动排序，展示标题、渠道、私聊/群聊类型、最近消息预览、来源账号快照和账号移除标记。进入线程后按稳定 sequence 分页读取，消息展示发送者、来源账号、正文、图片/文件、引用/提及文本、投递状态、平台消息编号和时间。通过 EventSource 接收消息及投递事件并刷新相关历史，无需整页刷新。

网页没有渠道消息输入框，实际外部发言从对应平台产生。网页显示账号、发送者与会话头像；缓存七天刷新、校验并缩成最大 128 像素 PNG，后台获取失败保留旧头像，不阻塞聊天。私聊来源的应用内用户 ID 与头像按账号隔离；群和联系人头像仅从可信平台资料/CDN获取。渠道记忆可定位普通消息或独立旁听来源，校验线程属于当前角色，支持近期列表外旧线程；来源不可访问时明确提示。当前没有未读计数或独立投递诊断面板。账号来源快照、显示名与头像不是授权依据。

## 9. 后续架构建议

建议用唯一的 `ConversationContextBuilder` 产生受限历史、记忆范围和工具权限，并由模型消息构建、记忆检索、工具声明与执行共同使用。可进一步把消息/运行中的 thread、account 和信任来源改为结构化字段，持久层查询要求明确的授权线程集合。

当前通过主人 MemoryEngine 与线程范围外部档案分开保存记忆。若未来把它们合并为通用 MemoryScope，迁移必须保留既有记录主人私有、检索前按授权范围过滤及当前群隔离；不能仅依赖 prompt 要求模型保密。

同角色渠道回合目前在进程内等待角色锁，不进入持久待处理队列。后续若引入队列，建议按角色串行、跨角色并行，保存已接受事件、恢复状态及队列满策略，并在执行时重新校验触发和权限。该增强不属于 Shiori 基线。

## 10. 兼容与失败恢复

已有桌面历史只登记为 `desktop` 线程，不重写消息 ID、顺序、工具结果或运行记录；登记可重复执行。删除角色按角色清理渠道账号、身份、线程、目标、群设置/笔记与投递记录，并沿用角色附件清理；其他角色不受影响。移除账号保留已有线程、消息与已保存的来源快照。

角色删除在排空渠道后保存仅进程内的角色渠道快照，包含全部线程历史、凭据、旁听/档案/推送状态与缓存头像。数据库删除后若文件清理等步骤失败，恢复数据、凭据和原启用连接；不会把恢复快照或秘密写到普通文件/API/日志。删除开始前同步关闭渠道回合准入，已准入但未启动的消息收到重发提示，不会等待删除持有的角色锁导致排空死锁。

启动恢复会完成持久删除标记对应的渠道、凭据、角色资料理解和推送清理。若凭据库等清理失败，保留删除标记且禁止残留账号连接；账号启动入口均要求所属角色存在且没有待完成删除。

适配器对平台事件做短期去重，宿主以线程和外部消息 ID 持久去重。入站消息先持久化，再等待角色锁并预留运行；当前没有持久化重放队列，重启后尚未开始的回合不保证自动补跑。运行消息沿用 Runtime 的持久化与重启收束规则，渠道网页更新使用渠道事件流。

配置替换先关闭账号准入，等待已接受事件和发送结束，停止旧连接，再保存并启动新配置；失败时恢复原配置、凭据和启停状态。暂停期间每账号最多缓冲 64 条尚未准入的消息，恢复后重新通过当前连接、规则和身份授权；缓冲溢出、禁用或删除时通过原连接告知“尚未处理，请重发”。该缓冲只保存在进程内，无法恢复连接空窗或进程退出时未接收到的消息。已开始发送由取得的适配器处理，投递账本记录实际连接代次，当前未建立持久账号换代模型。飞书传输层默认使用基于 `lark-oapi` 的长连接 runner，并保留签名校验的 webhook 兼容入口；常规部署不需要为入站消息公开回调服务。实际平台权限仍须在部署中核验。启动时未完成投递转为 `uncertain`，保留账本且不自动重发。

## 11. 验收清单

以下用于判断功能是否完成，需结合测试与实际平台验证，不是完成声明；第 5–8 节已列出的实现限制仍有效。

- 主人能管理四类账号；普通数据库、API 响应和诊断不泄露凭据，凭据库失败时不会回退到明文。
- 配对码单次、限时、仅私聊有效；配对命令不触发模型，配对前消息不追溯获得主人上下文。
- 访客私聊不能读取桌面、主人资料/记忆、其他私聊或群原文；错角色账号、错线程和伪造身份不能提升权限。
- 私聊与群各有独立线程；仅已配对主人私聊按授权边界读取其他主人对话片段。
- 群聊仅 @/回复触发；NapCat 旁听只保存当前群且不触发工具，其他平台没有伪造的旁听能力。
- 主人群回合只自动读取当前群历史，角色启用的主人工具仍可用；非主人无法获得这些工具。
- 主人发送只接受当前角色目录目标；访客只能由当前账号联系配对主人；回复目标限当前线程，附件遵守角色/线程授权。
- 平台确认、确定失败和结果不确定可区分；重启与配置替换不会盲目重复外发。
- 网页线程、最近消息预览、稳定分页、媒体、引用/提及文本、来源快照、头像、当前主人标记、投递状态和实时更新可验证；未读计数与平台原生样式不属于当前网页功能。
- 既有桌面消息/运行兼容，重复登记不重复建线程；账号删除保留历史，角色删除按范围清理。
- 适配器契约、权限矩阵、重启、去重、配置替换和附件边界有自动化回归；真实账号收发、权限与事件订阅经过实测。

## 13. Shiori 之外的改进建议

1. 如需限制主人群回合的高风险工具，另行决定每群 allowlist/denylist，不能把该建议写成当前授权行为。
2. 增加按角色持久入站队列，明确积压与恢复策略，减少重启丢失；该能力不属于本次 Shiori 复刻基线。
3. 飞书和 QQBot 群聊先验证真实平台事件与权限，再扩展能力声明和验收。
4. 为长期保存的旁听增加用户可配置的自动保留策略，并深化投递诊断与统一上下文接口；这些改进不取代本次已实现的独立旁听、配额、整理、来源展示和记忆隔离。
