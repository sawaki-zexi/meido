## Problem Statement

长历史准备反复读取整套权限和配置，导致服务事件循环长时间不能响应其它页面。工具已经执行完，后续预算和摘要仍可能让界面长时间等待。浏览器刷新还会取消正在执行的回复。

## Solution

对齐 Shiori 的轻量当前工具筛选、配置保留轮数驱动的压缩候选、摘要计量与一次缩短协议、后端持有聊天任务的原则。用户发送后能及时看到阶段，其他页面继续可用；切页或刷新后回到同一个执行；显式停止仍终止该执行。

## User Stories

1. 作为主人，我希望长历史发送后仍能打开设置和插件页面。
2. 作为主人，我希望上下文准备与工具衔接不反复读取相同配置。
3. 作为主人，我希望压缩遵循保留轮数设置，并保护当前输入和未完成工具交换。
4. 作为主人，我希望摘要长度只按正确的可见输出口径判断，不因思考用量误触发额外缩短。
5. 作为主人，我希望过长摘要能获得具体长度反馈，格式或来源错误则明确回退，不循环重试。
6. 作为主人，我希望看到真实的上下文准备、整理历史、模型回复和工具执行阶段。
7. 作为主人，我希望切换页面、角色或刷新后，原回复继续，回到该角色时恢复显示。
8. 作为主人，我希望主动停止准确作用于所选运行，已发生的工具动作不会重新执行。
9. 作为主人，我希望关闭工具权限仍影响后续实际调用，优化不复活旧工具或旧授权。
10. 作为主人，我希望失败、取消和服务退出都正常收尾，原文与已完成回执得到保留。

## Implementation Decisions

- 复用现有 Runtime、当前工具注册表、会话数据库、SSE 事件与 Shiori 式聊天界面，不引入第二套任务系统或永久工具选择缓存。
- 一次预算准备先得到可复用的权限／工具元数据投影，多个候选只进行轻量筛选与计量；实际执行仍按当前注册表、当前来源和最终参数检查。跨模型／摘要等待后重新核对当前事实，避免使用陈旧执行许可。
- 按用户进一步要求，修复以架构责任为边界：准备输入负责宿主读取，候选请求负责纯渲染／计量，执行器负责实际调用准入。估算不修改共享 Provider 状态或重复回调宿主 I/O，实际发送使用已经校验的同一候选输入；桌面和渠道复用这条准备链路。详见 [架构对照](../research/chat-responsiveness-architecture.md)。
- 自动压缩按 Shiori 从配置保留轮数向下选择候选，不再从最早历史逐轮试遍。默认保留两轮会比当前实现更积极地移出较早原文；原文仍保存在历史中。当前输入和完整工具交换不可切断，最终完整请求重新验证容量后才提交水位。
- 将重的同步准备及必要读取移出服务事件循环，或在适合的计算边界异步化；由性能与并发测试确认效果。不可只加一个 loading 文案或全局永久缓存。
- 摘要采用完整六字段 JSON 模板及有效来源 ID；规范化输出的计量区分总输出、reasoning 和可见正文，缺失／异常用量回到本地估算。已支持的厂商保留其辅助思考控制；未知协议不能发送臆造的关闭思考参数。
- 仅完整合法且过长的摘要允许一次带计量反馈的缩短。超时、截断、非法 JSON、无效来源均保存脱敏阶段并按既有软／硬预算规则回退；不无限重试。所有批次成功才提交。
- 聊天任务由后端持有。断开 SSE 只释放订阅；显式 Stop、服务退出和既有来源失效继续取消。此决定替代 ADR-0003 的“客户端断开即取消”部分，需要随实现记录新 ADR。
- 复用稳定 runId 与事件序号：打开会话时恢复活动执行的当前投影，并重新订阅后续事件。浏览器恢复不得再次发送原消息或重跑工具。内存投影有界，最终消息仍由数据库负责；不新增永久逐 token 日志。
- 显式停止、终态、迟到事件、重复订阅及拟人多段回复继续保持归属和顺序。服务重启只将旧未完成执行收尾，不自动重放。
- 阶段状态使用已有过程展示位置；摘要等待与实际工具执行分开呈现。

## Testing Decisions

- 复用上一轮无网络合成性能夹具，在相同机器和约 8.2 万 token 输入下比较本地准备耗时，目标低于 2 秒；不把这个机器相关数值作为脆弱的 CI 单一判据。
- 通过可控慢 I/O 和真实应用 HTTP 边界证明准备期间 health／设置／插件请求与取消仍可推进；覆盖不同工具数量和历史长度，避免成本随两者乘积反复增长。
- 通过窗口与 provider 请求夹具校验当前工具替换／撤销、工具搜索加载、跨摘要等待后重核、来源隔离及预算一致。
- 用供应商协议夹具验证 visible／reasoning 用量、缺失／异常计量、合法超长一次缩短、字段与来源失败、超时、批次原子提交。
- 用服务端流与前端集成测试覆盖连接断开、刷新重连、页面／角色切换、多个订阅、显式停止、接收确认丢失、终态抢先完成、自然回复分段和旧运行迟到事件。
- 使用独立开发实例、真实浏览器和本地可控模型／工具服务进行端到端验证：普通多轮聊天、慢准备期间打开其它页面、工具前后消息衔接、摘要成功／失败、刷新续接与主动停止。记录真实端到端边界及未调用付费服务的限制。
- 定向后端／前端测试、受影响类型检查和构建、CI、独立规范与规格审查。测试使用独立数据和 fake provider／tools，不调用正式模型或真实外部事务。

## Out of Scope

更换用户模型或充值、增加外部事务、跨服务进程崩溃自动继续推理、模型速度保证、重写全部插件 SDK、修改长期记忆归属。合并、部署和关闭 Issue 不由本规格自动授权。
