# 主人资料与角色理解规格

状态：当前

事实来源：主人资料实现及测试、[`CONTEXT.md`](../../CONTEXT.md)、[`memory-system-spec.md`](memory-system-spec.md)、[`agent-runtime-tau-integration-spec.md`](agent-runtime-tau-integration-spec.md)、[`ADR-0003`](../adr/0003-tau-inspired-agent-runtime-boundary.md)、[`ADR-0004`](../adr/0004-role-scoped-shell-tool-boundary.md)。

## 1. 目标

主人在飞书知识库维护日记、学习笔记和个人资料。Meido 将普通文档同步到本地，供角色按需查阅；每个角色也可以结合自身人格、角色设定、主人资料和既有记忆，形成一份独立的“对主人的想法”。

飞书是原文和编辑的权威来源。本地文档副本、索引和角色理解均可重建。Meido 不修改飞书原文。

目标行为：

- 首次连接后同步整个知识库；之后每天检查，启动时补查，并允许手动立即同步。
- 主人可以整体启用或暂停主人资料功能；暂停保留连接和本地数据，但停止资料读取与后台更新。
- 只导入普通文档；其他节点明确报告为跳过。
- 角色可以在当前问题相关时检索主人资料，也可以通过 Runtime 只读工具主动细化查询。
- 每个角色独立形成和更新一份主观理解；不固定注入对话，也不写入角色记忆。
- 同步与后台生成失败不影响普通对话；角色理解更新失败保留旧版本。

## 2. 领域边界

### 2.1 主人资料

主人资料是从主人连接的外部来源同步到本地的来源文档。第一版来源为飞书知识库，只导入普通文档。来源原文不属于角色记忆。

### 2.2 角色理解

角色理解是某个角色基于主人资料、角色设定和该角色已有记忆形成的主观认识。它可以体现角色人格和视角，不是权威事实，也不保存日记原文。每个角色单独维护一份，支持查看和手动重新生成，不提供手工编辑。

### 2.3 与角色记忆的关系

现有 MemoryEngine 和记忆维护流程继续管理互动中形成的记忆。主人资料服务可只读 MemoryEngine 和角色设定作为角色理解生成输入，但：

- 同步、资料检索和角色理解生成不得创建、修改、强化、遗忘或删除记忆条目。
- 角色理解不得交给记忆提取、consolidation 或 Optimizer。
- 主人资料证据、角色理解和角色记忆在检索结果及模型上下文中分别标记。

## 3. 总体架构

```text
Application Plugin Manager
  └─ OwnerKnowledgePlugin [enabled | paused]
       ├─ Feishu sync + local SQLite / FTS5 / sqlite-vec
       ├─ bounded search + background role-understanding updates
       └─ owner_knowledge.read -> read-only Runtime tool
```

主人资料整体作为一个应用级插件，由应用级 Plugin Manager 注册、启用、暂停和恢复。插件拥有该模块的连接、同步、解析、存储、检索、定时调度和角色想法后台任务；实现时这些职责可以是插件内的函数或类，不要求拆成多个服务。应用设置提供独立的主人资料插件开关，控制整个模块。

当前 Runtime 的 `PluginRegistry`/`CapabilityRegistry` 在角色运行期间装配能力。主人资料插件启用时，通过这个扩展点向 Agent Runtime 提供 `owner_knowledge.read` 只读工具；该运行时工具适配器不拥有资料库或后台任务。角色理解由应用级插件自身的后台任务生成和保存，不注册成 Agent 写工具。对话仍由现有 Runtime 和 MemoryEngine 负责；主人资料只通过限额后的上下文结果或只读工具结果进入当前运行。实现需要扩展现有插件系统，加入应用级插件生命周期与独立启停管理。

主人资料插件有一个全局启用/暂停开关，不按角色分别配置。暂停保留插件配置、飞书授权和本地数据，但停止其同步、检索和角色理解更新；恢复时重新启动插件并先补同步。

## 4. 用户流程

### 4.1 连接与同步

主人可以在应用插件设置中独立启用或暂停主人资料插件，并在插件内连接飞书只读授权及整个知识库。启用且完成连接后，插件递归枚举节点，同步普通文档，解析、切片并建立本地索引；界面显示新增、更新、删除、跳过和失败数量及可定位错误。插件启用期间用户可手动同步或断开连接。

启用期间每天自动检查一次；Meido 关闭期间错过检查时，下次启动补查。未变化文档不重新解析或生成 embedding。只有完整枚举授权范围并成功结束的扫描才能确认删除；扫描不完整、权限错误或读取失败时保留旧的可用版本。

暂停插件会阻止新的自动/手动同步、上下文检索、Agent 搜索工具调用和角色理解更新任务，并停止后续定时调度。暂停不撤销飞书授权，也不删除本地资料、索引或已生成的角色理解。已经开始的原子文档/理解更新可以完成当前提交边界；尚未开始的任务保留待处理状态。暂停期间已开始的对话可能已经收到本轮准备好的资料上下文。

恢复插件时先执行一次完整补同步；补同步成功后插件进入启用状态，重新开放资料检索，并继续处理角色理解任务。补同步失败时插件保持暂停，展示错误，不向角色开放可能过期的资料。主人主动断开连接是独立操作，按第 7 节清理连接数据。

首期只导入普通文档。表格、多维表格、演示文稿、思维笔记、附件和其他不支持节点必须显示为跳过，不能伪装为已同步。

### 4.2 角色理解更新

一次同步提交了新增、修改或删除后，为所有现有角色逐一排入增量更新。更新输入包括本次变化资料、旧版角色理解、角色设定和该角色的只读记忆。一个角色失败不影响其他角色。一次每周对每个角色执行一次全量重读，以当前有效资料校正删除、过期信息和长期认识。全量处理必须分批读取文档，不能假设完整知识库能装入单次模型上下文；使用临时中间结果归并，全部成功后再原子替换正式版本。主人可以单独查看角色当前想法或请求重新生成。

更新使用该角色当前绑定的模型。模型不可用、输入不完整或输出无效时保留原版本并留下可诊断失败状态。删除角色时清除其理解和待处理任务；不得影响共同的主人资料索引或其他角色。

### 4.3 对话检索

每轮对话保留现有 MemoryEngine 行为。仅当主人资料插件已启用时，应用才根据当前用户消息对主人资料和当前角色理解做一次有界检索；检索结果仅在命中相关内容时进入上下文，不固定注入整份日记或完整角色理解。

主人资料能力由应用级插件开关控制，不为每个角色增加单独授权设置。插件启用时，各角色可在 Agent Runtime 中调用只读 `search_owner_knowledge(query)` 细化搜索，取得主人资料片段和/或当前角色理解；插件暂停时自动检索和该工具均不可用。工具通过现有运行时 `PluginRegistry`/`CapabilityRegistry` 装配，角色范围由当前运行上下文绑定，工具不得接受目标角色 ID。工具结果进入当前运行的 tool transcript，不作为普通对话消息，也不进入记忆提取。

主人资料证据可带标题、位置和飞书链接，方便角色基于原文回答。角色理解是主观认识，独立标记；不要求在其文本中附加事实来源、置信分数或时间范围。无论是自动检索还是工具检索，失败都不能阻止回复。

## 5. 本地存储和检索

主人资料使用独立于 `memory2.db` 的 SQLite 数据库，例如 `owner-knowledge.db`。这让索引扩展加载、资料断开清理和资料迁移与 MemoryEngine 生命周期隔离。SQLite 保存原文副本、目录、同步状态及角色理解；FTS5 用于精确词补充；`sqlite-vec` 保存 chunk 向量并执行语义召回。

存储至少表达以下数据：

- 来源连接、授权状态、同步运行及同步错误账本。
- 远端节点/文档稳定 ID、类型、标题、链接、远端修改时间、内容哈希和同步状态。
- 片段正文、顺序、章节/日期等位置元数据、embedding 模型版本和向量。
- 每角色当前角色理解及其检索向量、版本/更新时间及待执行、执行中、成功或失败的生成任务。

远端文档 ID 与来源 ID 是身份依据，标题不能作为主键。向量结果必须能回取正文、标题、位置和来源链接。embedding 模型或维度变化时建立新索引版本并重建，不混用不同向量空间。

文档与查询使用同一版本的本机 embedding。embedding 模型选择、Windows 打包与 `sqlite-vec` 扩展加载策略属于实现计划，需要在实现前验证；不得复用当前按角色模型服务请求 embedding 的 MemoryEngine provider 来替代本机 embedding 要求。发送给聊天模型的资料片段会随当前请求发送到该角色模型服务商；此数据边界已由主人接受。

切片优先保留文章、标题、日期和自然段：短日记可以整篇作为片段；长文按自然段或连续自然段组合；只在单段过长时继续拆分。每个片段保留文档 ID、顺序和位置。长度、重叠及中文解析参数通过代表性日记评估，不在领域规则中硬编码数值。

## 6. Runtime 和权限

- 资料同步、存储、索引和角色理解更新属于 `OwnerKnowledgePlugin` 的应用级生命周期，不运行在 Agent Loop 内。
- 应用级 Plugin Manager 提供独立启停状态；主人资料插件启用时，再通过现有运行时 `PluginRegistry`/`CapabilityRegistry` 注册声明 `owner_knowledge.read` 的只读工具。
- `owner_knowledge.read` 只授予读取主人资料和当前角色理解的能力，不授予同步、断开、存储、角色理解写入或 MemoryEngine mutation。
- 不支持结构化工具调用的模型不暴露该工具，但仍可使用应用侧自动检索；搜索工具故障也不能使普通回复失败。
- Runtime 工具适配器只取得绑定当前角色的窄只读接口，不直接持有存储或飞书客户端，也不持有记忆写接口；资料库和后台任务由应用级主人资料插件管理。
- 工具参数、候选数、输出长度和执行时间有上限；尊重取消信号并写非敏感审计信息。
- 飞书文档是待引用的资料内容，不作为系统指令或工具权限来源；OAuth 凭据不得写入资料正文或普通日志。
- 自动检索与工具检索共用同一 Reader 和结果长度预算，避免重复实现检索逻辑。

## 7. 一致性、失败与清理

- 文档更新采用幂等写入；新版本文档解析和索引成功后再切换当前版本。
- 完整扫描才确认远端删除；部分失败不清空本地数据。
- 同步任务和角色理解任务持久化状态，启动时恢复可重试工作；同一角色的理解更新串行执行，合并重复待处理变更。
- 插件暂停时不接收新同步/检索/理解任务，保留未执行任务、插件配置、授权和全部本地数据；恢复时先完整补同步，成功后才重新提供检索。
- 角色理解生成在临时版本完成并校验后原子发布；失败保留旧版本。
- 检索、索引、同步和理解更新错误不改变或阻塞已保存的会话消息，不触发角色记忆 mutation。
- 主人确认断开飞书后，清理该来源的本地文档、片段、FTS/向量索引、同步状态、授权凭据以及依赖该来源的理解派生数据和任务；不删除飞书原文、会话、消息或角色记忆。

## 8. 验收标准

1. 用户完成飞书只读授权后可连接整个知识库，并查看新增、更新、删除、跳过和失败结果。
2. 主人可以在应用插件设置中独立启用或暂停主人资料插件；暂停保留连接、本地资料、索引、角色理解和待处理任务，不再开始同步、检索或理解更新。
3. 恢复插件时先执行完整补同步；成功后重新开放资料检索并恢复后台更新，失败则插件保持暂停且不暴露旧资料。
4. 启用期间首次、每日、启动补查和手动同步能处理普通文档增删改；不支持节点被明确跳过。
5. 不完整扫描、权限错误或文档临时不可读不会误删上一版本地文档或索引。
6. 文档未变化时不重复解析或生成 embedding；修改文档只重建受影响索引，且片段可返回标题、位置和飞书链接。
7. 自动检索及当前角色只读工具都能从同一资料库检索；工具不能切换角色、改写资料、调用记忆 mutation 或让工具结果进入记忆提取。
8. 不相关资料不会作为整库内容固定注入；相关资料证据与角色理解在上下文和工具结果中分别标记。
9. 资料新增、修改或删除后，后台会为各角色排队更新；角色更新失败保留旧版本且不影响其他角色或普通对话。
10. 每周全量重读按有界批次处理资料，全部成功后才替换角色理解；支持单角色手动重新生成和查看。
11. 角色理解使用当前角色设定、当前模型和该角色现有记忆；模型不可用时保留旧版本并记录状态。
12. 所有资料和角色理解操作不创建、修改、强化、遗忘或删除角色记忆，也不写 `SELF.md`、`MEMORY.md` 或其他记忆文档。
13. 删除角色只清除该角色的理解与任务；断开来源只清除该来源资料及其派生状态，不影响会话、消息和角色记忆。
14. 自动化测试覆盖开关状态、暂停时的任务与能力门控、恢复补同步、完整/不完整扫描、增量索引、工具角色隔离与只读、任务恢复、角色级失败保留和记忆隔离。

## 9. 不包含

- 创建、修改或删除飞书原文。
- 首期支持非普通文档节点、附件 OCR、实时在线飞书检索或多用户账户。
- 将主人资料原文或角色理解写进现有角色记忆。
- 向 Agent 暴露写角色理解、记忆或外部资料的工具。
- 通用第三方插件市场；主人资料插件是 Meido 内置、应用级管理的功能。
- 承诺具体 embedding 模型、切片数值或 SQLite 物理 schema。
