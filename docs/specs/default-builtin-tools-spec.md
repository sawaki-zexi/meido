# 默认内置工具与插件启停

状态：已确认 / 实施中。2026-10-17 主人要求参考 Shiori：基础工具默认自带，仅特殊插件需要启停；对 Shell 默认执行的具体追问回答“按照 shiori 来就行”。Parent #137，替代 #163 的逐项基础授权体验。

## 用户结果

新建角色与旧角色无需勾选基础工具即可在下一轮对话使用文件、网络、消息原文、记忆、工具发现、Shell/后台任务、子任务、时间任务和桌面推送。MCP 管理工具默认可被发现，具体服务仍需已有 trust/grant。依赖或宿主服务关闭时明确说明原因，不自动配置凭据。

基础工具身份由宿主内置清单决定。旧 enabledTools 为空、只含部分名称或普通资料保存均不删除默认工具；未知扩展工具、插件、grant 和专用配置继续保留。插件工具不会因迁移旧配置而自动开启。

角色资料仅编辑身份和设定，不再显示工具、预算、插件开关或工具目录。工具配置统一进入“设置 → 工具与插件”，选择已有角色后调整；资料保存不提交 agentConfig，创建角色使用后端默认配置，旧创建草稿中的隐藏许可不会被提交。插件保存刷新角色后仅合入实际编辑项，保留最新资料与其他授权。

## 插件设置展示

2026-10-18 主人要求对照 Shiori 插件管理页精简设置。首页只列可选插件的名称、简短说明、已保存状态，以及“设置”和“启动/关闭”。不展示默认工具清单；Shell/子任务预算与实际目录进入独立的“高级运行设置”，默认不展开。一次仅打开一个插件配置，视觉、CG 和 Coding 等表单不会在列表挂载时加载。

普通插件的“已启用”表示角色许可，不能冒充原生进程已运行。浏览器、桌面控制和待办按钮直接持久保存；屏幕、生图、编程、自主与桌宠启动先进入各自配置以补齐模型、消费、仓库或动作包许可。自主及桌宠关闭读取最新版本再提交，保留来源和动作包配置。操作失败保留原状态并显示原因。

NovelAI 按钮明确“关闭生成许可”，同时撤销手动、CG 和卡片写回许可，保留连接、额度和标签。重新启动只打开设置，不自动改成手动模式；主人重新选择许可并确认消费后保存。编程委托全局页提供持久启停按钮，仓库/CLI、发布凭据与原生核验分组折叠。

展示参考固定 Shiori `4f266ae` 的 `apps/desktop/renderer/src/plugins/PluginRow.tsx`、`PluginManagementSection.tsx` 和 `PluginDetailsDialog.tsx`：摘要行与启停、设置入口分离，诊断细节按需查看。复选框样式使用全局紧凑布局，兼容标签直接包含文字和 span 两种形式；用浏览器测量验证对齐及窄窗口无横向溢出。

## 已确认的执行边界

- 默认 Shell 在 Windows 使用 PowerShell 7，在 POSIX 使用 /bin/sh，支持正常 shell 语法。普通主人对话不再要求 enabled/allowedCommands；保留固定角色 workspace、最小环境、输出/时间预算和原 TaskRuntime 进程树回收。不是 OS 沙箱。受限子任务/自主运行沿既有独立许可，不继承普通聊天的默认 Shell 权限。
- 记忆仍受全局记忆服务开关和真实来源限制。文件仍限角色 workspace；消息原文仍限真实角色/线程；群与访客继续采用 external_allowed 过滤。
- 浏览器、桌面控制、屏幕、生图、Coding、桌宠、主动/Drift 保留各自默认关闭和配置，在插件设置中管理。付费服务、视觉连接、账号发送目标及自主来源 grant 不被默认工具替代。
- 默认提供不是自动运行。启动不主动调用模型、执行 Shell、生成图片或发送测试消息。

## 实施与验证

宿主为普通对话合并默认工具与旧扩展选择；不重写角色磁盘配置，普通运行、目录与实时授权使用同一结果。旧内置开关保留兼容与受限用途，不再关闭普通聊天的默认工具。Shell 的普通模式与受限 argv 模式分开，避免扩权受限 worker。界面取消基础逐项授权与默认工具清单，依赖诊断按需查看；插件启停沿真实保存接口。

沿已确认的角色 HTTP→工具→下一 Provider、目录及 React 保存接口做红绿验证，覆盖旧空配置、真实工作区文件与 Shell、未知扩展保留和插件未开启；运行受影响检查及两轴独立 review，不重复旧全量验收。真实用户数据只用于最后重启和只读目录确认，不由自动化测试读取凭据或调用远端模型。
