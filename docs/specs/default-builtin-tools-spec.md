# 默认内置工具与插件启停

状态：已确认 / 实施中。2026-10-17 主人要求参考 Shiori：基础工具默认自带，仅特殊插件需要启停；对 Shell 默认执行的具体追问回答“按照 shiori 来就行”。Parent #137，替代 #163 的逐项基础授权体验。

## 用户结果

新建角色与旧角色无需勾选基础工具即可在下一轮对话使用文件、网络、消息原文、记忆、工具发现、Shell/后台任务、子任务、时间任务和桌面推送。MCP 管理工具默认可被发现，具体服务仍需已有 trust/grant。依赖或宿主服务关闭时明确说明原因，不自动配置凭据。

基础工具身份由宿主内置清单决定。旧 enabledTools 为空、只含部分名称或普通资料保存均不删除默认工具；未知扩展工具、插件、grant 和专用配置继续保留。插件工具不会因迁移旧配置而自动开启。

## 已确认的执行边界

- 默认 Shell 在 Windows 使用 PowerShell 7，在 POSIX 使用 /bin/sh，支持正常 shell 语法。普通主人对话不再要求 enabled/allowedCommands；保留固定角色 workspace、最小环境、输出/时间预算和原 TaskRuntime 进程树回收。不是 OS 沙箱。受限子任务/自主运行沿既有独立许可，不继承普通聊天的默认 Shell 权限。
- 记忆仍受全局记忆服务开关和真实来源限制。文件仍限角色 workspace；消息原文仍限真实角色/线程；群与访客继续采用 external_allowed 过滤。
- 浏览器、桌面控制、屏幕、生图、Coding、桌宠、主动/Drift 保留各自默认关闭和配置，在插件设置中管理。付费服务、视觉连接、账号发送目标及自主来源 grant 不被默认工具替代。
- 默认提供不是自动运行。启动不主动调用模型、执行 Shell、生成图片或发送测试消息。

## 实施与验证

宿主为普通对话合并默认工具与旧扩展选择；不重写角色磁盘配置，普通运行、目录与实时授权使用同一结果。旧内置开关保留兼容与受限用途，不再关闭普通聊天的默认工具。Shell 的普通模式与受限 argv 模式分开，避免扩权受限 worker。界面取消基础逐项授权，展示默认工具与依赖；插件启停沿真实保存接口。

沿已确认的角色 HTTP→工具→下一 Provider、目录及 React 保存接口做红绿验证，覆盖旧空配置、真实工作区文件与 Shell、未知扩展保留和插件未开启；运行受影响检查及两轴独立 review，不重复旧全量验收。真实用户数据只用于最后重启和只读目录确认，不由自动化测试读取凭据或调用远端模型。
