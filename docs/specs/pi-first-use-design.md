# 新版 Meido 首次使用与模型连接

状态：后续方案（待评估） · 更新于 2026-11-18。第一版不纳入本文所述的首次使用流程及其验收。以下设计留待后续版本讨论。

设计依据见[角色创建方案](pi-role-creation-design.md)、[Pi 宿主边界](pi-runtime-integration-design.md)和[图片与表情方案](pi-media-library-design.md)。连接草稿、凭据和测试沿用[本地模型连接边界](../adr/0001-local-model-connection-boundary.md)。

## 第一次打开

新版宿主在本机初始化或读取本实例的主人身份与独立数据目录。重启后继续使用同一身份、草稿和角色。角色 ID 在确认定稿时生成。主人打开网页即可开始，无需注册、绑定渠道、填写 ID 或选择目录。

首次进入应用时，欢迎卡提供「配置聊天模型」和「先创建角色」。引导可跳过，以后从「设置 → 首次使用指南」重新打开。引导中的按钮打开日常使用的设置页和角色页。重新打开时根据已保存的连接和角色显示下一步，例如「继续编辑草稿」或「进入聊天」。

| 想做的事 | 页面上的操作 | 完成后看到什么 |
| --- | --- | --- |
| 先看看角色怎么创建 | 选「先创建角色」，填写名字和人物设定 | 可以保存草稿、预览并定稿。定稿后进入空的正式聊天，即使此时还没有模型。 |
| 配好模型再开始 | 选「配置聊天模型」，进入「设置 → 模型服务」 | 选择服务商，填写模型 ID 和服务商需要的凭据。预设填入服务地址；自定义服务可编辑地址和协议。本地免密服务允许留空凭据。 |
| 确认能收到回复 | 点「测试连接」 | 宿主用当前表单通过正式聊天使用的流式调用路径发送一条短测试消息。收到有效文本并正常结束后显示模型名及实际回复。测试消息只显示在设置页。 |
| 用这个模型聊天 | 点「保存并设为默认」，再选「创建角色」或返回原角色 | 页面显示已保存的默认模型名。从试聊或聊天转来时回到原草稿或角色，保留已输入的文字，由主人点击发送。 |

测试成功时若表单尚未保存，提示「连接测试通过。保存后可用于聊天」。编辑地址、协议、模型或凭据后清除旧的成功提示。仅保存但尚未验证的连接显示「已保存，尚未测试」。测试失败保留表单，例如鉴权失败提示「服务商拒绝了凭据，请检查后重试」，模型不可用提示「此连接无法使用该模型，请核对模型 ID 和访问权限」。测试和保存由本地宿主处理，浏览器只显示已保存凭据的设置状态。

## 试聊与正式聊天用哪个模型

建议试聊与正式聊天共用一套选择规则。草稿初始选择「跟随默认」，旁边显示实际模型名。主人也可为该角色选一个已保存的聊天连接。定稿时保留所选模式，连接绑定独立于只读初始卡。正式聊天页展示当前模型，可切回「跟随默认」。更换默认只影响跟随默认的角色，从下一轮生效。

宿主在每轮开始时确定连接和模型。草稿的「同句重试」沿用原轮的模型和前序消息，以便只比较人设变化；原模型已变更或不可用时提示主人恢复原配置，或选择其他模型另开试聊。指定连接失效时显示连接名称、失败原因和「更换模型」，由主人决定是否切换。定稿后正式聊天从空历史开始，仅主动收录的示例随人设进入正式卡。

## 缺少服务时的界面

| 发生位置 | 界面文案与操作 | 仍可进行的操作 |
| --- | --- | --- |
| 草稿试聊，缺聊天模型 | 「还没配置聊天模型。配好后可以试聊，也可以先完成创建。」提供「配置聊天模型」「完成创建」。 | 编辑、保存、定稿。 |
| 正式聊天，缺聊天模型 | 输入框旁显示「角色已就绪。配置聊天模型后，就能发送第一条消息。」提供「配置聊天模型」，保留输入。 | 查看角色、输入消息、进入设置。 |
| 生成图片，缺生图服务 | 「尚未配置生图服务。配置后可以生成图片和原创表情。」提供「配置生图服务」。 | 文字聊天、浏览和使用已有可用素材。 |
| 制作原创表情，缺视觉评估 | 「原创表情需要视觉评估。请选择支持图片输入的模型，再开始制作。」提供「配置视觉评估」。提交前检查，避免产生一次无法完成的付费生图。 | 文字聊天、普通生图、使用已通过评估的表情。 |
| 已出图，评估服务临时失败 | 「图片已保存，视觉评估未完成。」展示原图、失败原因和「重试评估」。 | 重试只评估已有图片；待评估条目不会进入聊天候选。 |

视觉评估和生图是两项独立的可选设置。视觉评估可以明确选用支持图片输入的聊天连接。一次文字测试成功只证明该模型能回复文字。欢迎卡只介绍两项图片能力的设置入口，跳过它们即可完成首次文字聊天。

## 后续版本的候选验收场景

1. 在全新隔离实例跳过教程和模型配置，创建角色并重启；仍能找到同一角色，从聊天页补配模型后发送原先输入的文字。另一个隔离实例看不到该角色或连接。
2. 先配模型时，用错误凭据测试得到可操作的错误，修正后看到真实测试回复。仅测试后离开，原默认连接保持有效；显式保存并设为默认后，新一轮试聊使用新连接。
3. 用两个可辨认的模型核对选择结果。「跟随默认」的草稿定稿后继续跟随；指定连接的角色定稿后继续用指定连接。切换默认后同句重试仍使用原模型，正式聊天历史中没有测试或试聊消息。
4. 分别移除生图、视觉评估连接，核对对应入口的文案与可用操作。缺少视觉评估时普通图片仍可生成；原创表情在提交前提示，生图请求数为零。模拟出图后评估失败，重试后生图总数仍为一次。
5. 跳过引导后再次启动直接进入应用，从设置重开教程时可进入已有角色。更换开发实例后首次引导按该实例自己的状态显示。
