# 角色创建模块开发方案

状态为开发设计草案，2026-11-18。维护者已确认新版使用完整 Pi，角色卡独立保存，初始卡包含五项字段。下文给出创建交互、持久化和 Pi 接入的建议实现，验收场景待开发后执行。[已确认的重构决策](pi-refactor-decisions.md) · [重构开发索引](pi-based-meido-design.md)

## 用户结果

主人从「角色 → 创建角色」进入，一页内写好初始设定。只填名字和人物设定就能直接创建，也可以先试聊，用同一句话比较修改前后的口吻。主人确认定稿时生成稳定的角色 ID 和只读的初始卡，随后进入一段新的正式对话。创建模块负责草稿、试聊、定稿以及正式聊天读取初始卡的交接；长期记忆、生图和渠道接入由各自的模块负责。

## 五项字段与填写方式

| 页面字段 | 数据键 | 填写提示和行为 |
| --- | --- | --- |
| 名字（必填） | `name` | 单行文本。提示“她叫什么？”用于角色列表和消息署名。同名角色按 ID 区分。 |
| 人物设定（必填） | `description` | 多行纯文本，支持粘贴完整设定。提示“她是谁？她在意什么？遇到两难时通常怎么选？”保留作者的段落和措辞。 |
| 关系起点（选填） | `initialRelationship` | 提示“第一次正式聊天时，你们是什么关系？”例如“我们合住两年，常在厨房碰见”。留空时，由当前交流建立关系。 |
| 表达风格（选填） | `speakingStyle` | 提示“她怎么称呼你？选一两个听起来像她的特点。”例如“偶尔叫我胡老师。担心时只问一句短话”。 |
| 示例对话（选填） | `dialogueExamples` | 有序的 `{userText, characterText}` 列表，界面使用“我说／她回”两个输入框。支持增删、排序和从试聊收录。 |

控件内的提示和例句只作占位。草稿允许暂时缺字段或只填了半组对话。试聊和定稿复用一套校验：去除字段首尾空白后检查必填值，保留正文内部换行；全空的示例行忽略，半组示例定位到具体行并提示补全或移除。可选文本空值和空示例列表在构造 Pi 输入时省略。

## 页面状态与操作

1. **填写草稿。** 第一次编辑即分配草稿 ID，修改自动保存到当前实例本地。页面显示保存中、已保存或保存失败。离开再回来恢复字段和示例顺序。保存失败保留输入并允许重试。进入试聊或最终预览前，先保存屏幕上的最新内容。
2. **进入试聊。** 使用已保存的草稿版本创建临时预览。主人可自由输入，也可点一句示例开头。返回编辑时保留本次打开页面中的对话。若已编辑人设，再次生成时标出所用草稿版本，旧回复继续标明旧版本。
3. **用新版重试这句。** 针对选中的一条用户消息，用最新草稿、原来选定的模型、完全相同的用户消息和该消息之前的对话重新生成。保留旧、新回复供比较；主人可以选择其中一个版本继续聊。重试较早消息时保留原来的后续对话，新分支从选中的那一轮继续。比较时变化的是人设输入，模型采样本身仍可能使回复不同。
4. **收为示例对话。** 从一个已完成的回复复制该轮“我说／她回”到示例编辑区，可修改措辞后保存或取消。只收录所选的一对消息。这是试聊文字进入正式卡片的唯一显式入口。
5. **确认定稿。** 「完成创建」先展示五个字段的最终预览和示例顺序，注明初始卡定稿后只读。主人可返回编辑，也可跳过试聊直接确认。确认成功后进入正式聊天。模型未配置或暂时不可用时，试聊提示原因，创建和保存角色仍可完成。

## 数据归属与模块分工

| 对象 | 建议持有者 | 最小数据与生命周期 |
| --- | --- | --- |
| 创建草稿 | 本地 Meido 角色服务 | `draftId`、五项内容、`revision`、状态和定稿后的 `roleId`。保存后可跨页面、跨进程恢复。 |
| 试聊轮次 | 创建页面与宿主预览服务 | `previewId`、轮次 ID、父轮次、草稿版本和输入快照、模型标识、用户消息、生成状态和回复。建议会话级暂存，关闭创建页后回收；重开只恢复已保存的草稿。 |
| 正式角色 | 本地 Meido 角色服务 | `roleId`、初始卡内容、卡片格式版本、创建时间、唯一的来源 `draftId`。预览和定稿共用同一字段规范；定稿卡由正式运行只读引用。 |

**建议服务契约。** 这些操作可以经宿主 IPC 或本地 API 暴露，传输方式由新版宿主决定。

| 操作 | 输入 | 可观察结果 |
| --- | --- | --- |
| 读取／保存草稿 | 草稿 ID、预期版本、完整字段 | 首次保存返回 ID 和版本，后续返回新版本。旧窗口保存时如版本冲突，提示重新载入，保留本窗口未保存的文字。 |
| 开始／重试试聊 | 草稿 ID 与版本、预览请求 ID、输入或原轮次 ID | 返回归属于该请求的 Pi 事件；完成、取消和失败有独立终态。重复提交同一请求 ID 时复用该请求，避免重复生成。 |
| 定稿 | 草稿 ID、最终预览对应的版本 | 返回稳定角色 ID。版本过期时刷新最终预览，让主人核对变化后再确认。 |
| 读取初始卡 | 角色 ID | 返回定稿快照，供角色详情和正式聊天共同读取。 |

建议草稿和正式卡落在同一个支持事务的本地存储中。定稿时校验版本，以草稿 ID 为唯一来源，在一次事务中创建角色、保存卡片并把草稿标成已定稿。提交成功但页面未收到回执时，再次确认返回已创建的角色。并发自动保存不能改写已定稿的草稿或角色。进入聊天页面失败时，只重试打开该角色。

## Pi 接入与隔离

**一份字段编译逻辑，两种会话。** 宿主按名字、人物设定、关系起点、表达风格、示例对话的顺序构造角色上下文。关系段注明“初次相处的背景”，示例段注明“作者给出的口吻参考”。示例留在角色上下文里，实际会话历史只含该会话真实输入和生成的消息。预览和正式运行都用该编译器，正式运行从定稿快照读取。

试聊使用独立的临时 Pi 会话，只提供文本对话所需的上下文。宿主为它单独装配工具与资源，关闭会产生文件、渠道、记忆或其他业务写入的能力。重试从所选轮次之前的消息恢复上下文，替换角色段，排除原回复和后续消息，避免旧设定被重复注入。角色服务在定稿后新建或按需打开空的正式会话，将其绑定到角色 ID。

**迟到事件处理。** 每次生成绑定预览请求和草稿版本；修改字段期间完成的旧回复仍归原请求。取消、关闭页面或定稿时中止未完成的预览，丢弃其后续显示事件。模型报错时保留草稿、用户输入和已完成回复，失败或取消的半截回复不能被一键收为示例。

## 开发顺序与验收

| 次序 | 可演示的成果 | 验收方法与预期结果 |
| --- | --- | --- |
| 1 | 填写五项、恢复草稿、直接创建 | 用名字和设定创建成功。必填项只有空格或示例缺半组时可保存草稿，定稿提示对应字段。重启后中文段落和示例顺序一致。 |
| 2 | 定稿卡用于首次正式聊天 | 用户在最终预览看见的内容等于正式快照。同名角色各自绑定自己的卡。连续点击确认、两个窗口并发确认、成功后丢失回执再试，都只产生一个角色。 |
| 3 | 用草稿在 Pi 中试聊、改后重试 | 用记录请求的测试替身核对两次输入，旧版和新版采用相同模型、问题和前序历史；新版本只带最新人设。模型失败或取消不妨碍编辑及定稿。 |
| 4 | 收录示例、正式开聊 | 在试聊中说“我刚失业”，只收录另一组台词。检查定稿卡只含主动收录的示例，正式会话历史为空。定稿后到达的预览事件不会出现在正式聊天。 |
| 5 | 用真实模型核对使用体验 | 在隔离开发实例上，用同一问题比较两种表达风格。人工评估作者能否听出差别、能否找到要改的字段。自动化检查绑定版本、上下文和数据归属，不断言模型逐字回复。 |

实现入口依赖新版宿主的本地持久化、角色详情／聊天入口和 Pi 会话接口。可先交付“填卡并直接创建”，随后接入可取消的 Pi 试聊与同句重试。以上均为开发与验证计划。
