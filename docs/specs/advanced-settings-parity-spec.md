## 1. 调研基点的缺口

Shiori 的高级页有五组十三项。Meido 在 6035dfd 基点的高级页只有角色 Shell/Spawn 预算及工具诊断。该版本普通桌面聊天最多 8 步，含 Computer Use 时 32 步；渠道聊天 8 步，回复 token 上限未统一传入；最近输入窗口为 24 条，后台优化开关/间隔来自进程启动环境。尚无通用工作摘要压缩器，也没有每模型上下文容量字段。下述实现补齐这一批缺口，不代表七栏全部完成。

不能只增加可保存却不被执行器读取的控件。实现必须覆盖公开 HTTP 到真实 provider 请求、能力目录/执行、记忆调度和压缩输入的用户行为。

## 3. 需要确认的跨功能决定

### A. 全局配置与运行范围

增加严格校验、原子持久化的全局高级配置，使用 `GET/PUT /api/settings/advanced`；PUT 只更新明确提交字段并带 expectedRevision 与 operationId，过期返回 409、不覆盖其他窗口。界面采用五组卡片、串行防抖自动保存和保存状态，不并发发出互相覆盖的快照。无效数字/跨字段错误保留为本地草稿；已确认写入但回读失败只重读，同 operationId 的不明结果重试不能重复应用。重复 operationId 携带不同值必须拒绝。刷新可恢复服务器值，离开页应安排最终合法草稿保存，不将密钥写到浏览器持久存储。

已完成 operationId 的查询先于 expectedRevision 冲突判断；配置新修订与对应操作结果原子持久化。重启后同一次不明结果重试仍返回原结果，不重复增加修订或重新应用运行副作用。

普通桌面和渠道回合开始时冻结预算与配置版本，不在同一运行中增加额度。子任务取全局与原任务有限预算的较小值；专用视觉、Coding、NovelAI、自主来源、Drift 等既有独立预算和许可不被全局参数覆盖。费用/外部账号和发送目标不随设置保存授权。

能力开关关闭对当前运行的新调用生效，关闭再打开不能复活原运行的 spawn 准入；停止和清理原任务始终保留。spawn_manage 的查询与取消保留，`continue` 会开始新 Coding 执行，必须与 spawn 一样检查新执行准入、原角色/仓库/CLI/费用许可及冻结代，不能借管理入口绕过暂停。按需发现只是 schema 展示策略，关闭不授予新能力，运行开始时冻结的候选仍是上界。

关闭按需发现时仍保留内部版本目录，以便已冻结许可的 MCP 服务在连接成功、工具结果提交后发布下一版直接可见 schema；按 #277 对当前 Shiori `21e68d9` 的核验，`tool_search` 仍作为常驻工具保留，精确选择已可见工具只返回 `already_loaded`，不重复加载或扩权。原候选、隐藏工具、来源和风险检查保持有效，保存连接意愿后的新运行也直接展示已获准远程工具。

### B. 工作摘要压缩

补充每模型可选 `contextWindowTokens` 与 `modelAutoCompactTokenLimit`，在模型详情显式填写，不猜测服务商容量。旧连接保持空值；未填写时明确显示“尚未配置模型容量，自动压缩未启用”，保留原有有界消息窗口。自动阈值必须小于已知容量，容量必须大于回复预留和安全余量。

未知容量时桌面与渠道共用有界原文兼容策略：至少 24 条，并容纳当前 Markdown 最近保留数；始终按完整用户轮取尾部。记忆基数通过维护层保留数生效，不等于固定模型原文条数。已有合法工作摘要仍读取并注入；未填容量只停新压缩，不清除或忽略原摘要。输入采用与 Shiori 同类的本地估算（ASCII 约三字一 token、非 ASCII 每字两 token；实际图像低清 85、其余 4096 的固定预算），不是服务商 tokenizer 或编码体积计费。

在普通桌面/渠道 provider 请求前计入完整可见输入、schema 与输出预留，用明确标识的估算预算触发。超阈值时以当前有效模型、空工具和受限中性提示生成工作摘要；摘要不具备授权作用。使用原请求已获准的消息范围，不跨角色/渠道取原文；图片不额外上传到摘要请求，既有原图规则不变。

明确预算顺序：设模型容量 C、当前用途回复预留 O、安全余量 S，则可用输入 A = C - O - S，A 必须为正。有效触发 T = min(A, 模型绝对压缩阈值或 floor(C × 触发比例))；目标 G = min(A, floor(C × 目标比例), T)，要求 0 < G < T。输入估算包含实际渲染 system、memory、工具 schema 与消息；G 是压缩选择的目标，完整必留块不能为了达到目标而被切断。

工作摘要采用与 Shiori 相同的结构：tasks / constraints / decisions / unfinished / tool_state / entities 六个字符串，以及去重后的非空 source_message_ids；只接受本次被移除原文或上一合法摘要包含的来源 ID。辅助生成输出预留为 min(2 × summaryTokenLimit, 当前用途输出上限)，合法摘要 JSON（含来源 ID）的硬限仍为 summaryTokenLimit；不能把生成预留和可提交摘要上限混为一谈。无效 JSON、伪造来源或截断直接失败，仅合法但过长时允许一次缩短请求；这两个请求都计入普通运行预算。

摘要请求必须按自己的实际输出预留和同一安全余量计算输入容量，计入中性提示、待压缩前缀与已有摘要。前缀本身超容量时在本地明确拒绝，不能先发送超限全文、无限分块或反复摘要。摘要后重新测量，不减少输入或仍超过可用输入时结束并报错，不悄悄丢弃原文。该限制和未知容量状态在界面/诊断明确说明。

原始历史和工具审计不删改。按 Shiori 真实实现持久化工作窗口，不能以仅 run 内临时 summary 冒充复刻：在既有 sessions.db 新增独立工作窗口表，按原角色、会话和来源 scope 分开保存 summary JSON、source IDs、裁剪序号、版本、原文指纹及授权代。迁移为新增空表，旧历史不改写；摘要不是长期记忆，也不能跨会话共享。

在一个 SQLite 事务中条件提交摘要与新 cut，前提是窗口版本、被裁前缀/来源 ID、角色与来源授权代仍一致，并且待逐出消息的既有记忆维护义务已完成；失败不得推进 cut。后续回合及重启加载同一摘要，并将新增被移除原文与旧摘要合并生成下一版。切换模型重新计量，不因此删除合法来源摘要；解绑/重新绑定或可见来源变化按 scope 失效，不能恢复别人的窗口。角色删除、聊天回滚/撤销及备份恢复必须覆盖该表；删除失败的回滚保留原窗口，不能留下孤立摘要。

维护结果经既有 MemoryEngine 边界返回可核验的覆盖状态，不使用 ensure_memory_for_window 的“曾尝试”布尔值作为提交证据。对具有记忆资格且记忆开启的来源，要求持久维护游标已覆盖同一授权前缀/来源 ID，相关待发布义务已完成；抽取失败、游标未推进或发布待完成均不得推进 cut。记忆总暂停或原本无记忆资格的访客/群来源明确为 not_required，不强制抽取也不永久阻塞压缩。维护已完成而窗口 CAS 失败，不回滚已提交记忆；下次依持久游标复用覆盖，不能重复抽取已完成范围。恢复旧备份后必须重新检查当前来源许可，曾合法但现已解绑的摘要不得注入请求。

保留完整近期用户轮、工具调用和全部对应结果，不能从工具链中间裁切。单次压缩最多两次辅助请求，受当前运行剩余步数/用途预算约束，不自动无限重试。摘要失败、保留块本身超限或剩余额度不足时，明确报错，不悄悄丢弃消息或继续超限发送。停止回复会取消摘要模型请求并等待清理。

### C. 热更新与开发者模式

记忆整理继续使用原 Worker/Loop，增加读取当前开关/间隔与重新计时的接口，不另建调度服务。准入同时要求原记忆总开关和新增后台整理开关启用；任一暂停均禁止新的整理模型调用，保留已开始任务的收尾责任。停用不删除文件，保存不触发立即优化；重新启用仅安排下一次正常计时。

开发者模式控制新增有界诊断的生成与查看，不放开工具、来源或账号许可，不记录原图、凭据或请求全文。既有必要运行记录继续保留；这与 Shiori 完整 payload 快照有明确差别。

## 4. 验收与风险

- 十三项均可读取、校验、保存、重启恢复；409 与失败保留草稿，不能将遗漏字段恢复默认。
- 本地 provider HTTP 夹具观测实际回复 token 上限；持续工具调用达到有限请求数后终止，无额外模型消费。
- 发现开关决定新运行初始 schema；spawn 关闭拒绝原运行新建且仍能停止原任务；关闭再开启不复活旧许可。
- 受控时钟证明记忆基数、优化开关/间隔实际生效，保存不立即调用模型，没有重复循环。
- 压缩夹具证明触发/目标/安全余量、摘要输出上限、保留轮数与工具配对实际影响后续请求；跨回合/重启复用窗口，事务失败不推进 cut，解绑和删除回滚不泄漏来源。失败/取消不丢原文、不留下进程或 HTTP 连接。未知容量、过小容量与超大单轮有明确反馈。
- 关闭开发者模式不生成新增诊断；启用后只包含已定义的有限字段，不含 fixture 密钥、图像或请求全文。
- React 与 1650/1070/390px 浏览器夹具验收全部五组、字段辅助说明、键盘切换与独立保存；类型检查和构建通过，两轴独立审查。

以上仅实施与无费用夹具验收；不使用真实账号、付费模型、主人真实桌面或平台业务事务。压缩估算与实际服务商 tokenizer 可能不同，须明确是估算并保留安全余量，不宣称能精确测得所有模型 token。

## 5. 本地验收结果

2026-10-19，Python 夹具使用隔离目录、本地 HTTP/stdio 和模拟渠道投递。运行/模型相关 48 项、上下文与 MemoryEngine 45 项、高级 HTTP 9 项、记忆维护/调度相关 20 项通过；后续新增的真实保留数和整理暂停入口各 1 项通过。直接展示/MCP 最终回归 8 项、能力发现相关 35 项通过；这些分组存在重叠，不作为全套测试总数。

React 高级、分类往返和 App 相关最终 10 项通过；模型既有 7 项与新增容量保存 1 项通过。TypeScript 和 Vite 构建通过；构建保留现有大于 500 kB 分块提示。浏览器夹具验证十三项、串行保存、重开读取、模型数值保存、键盘开关及 1650/1070/390px 对齐和无横向溢出。规范、规格两轴独立审查的问题已修正并复核。

相关日志为工作区外 `D:/meido-artifacts/advanced-*.log`；未据此宣称完整 CI 或真实服务消费验收通过。七栏剩余工作见[总规格](shiori-settings-parity-spec.md)。
