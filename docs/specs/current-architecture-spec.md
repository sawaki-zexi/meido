## 1. 产品形态

Meido 是面向单一主人的本地网页应用。浏览器网页连接本地 FastAPI 后端，后端管理角色、唯一会话、消息、模型连接、记忆和应用级插件。当前不提供多用户账户、云端共享或远程同步。

网页当前提供：

- 角色酒馆、角色创建、编辑、头像/角色卡和删除；
- 角色唯一会话、历史消息和流式回复；
- 模型连接设置与角色模型绑定；
- 记忆总开关、共享向量模型开关与配置，以及角色记忆查看、搜索和维护；
- 主人资料插件设置、飞书只读同步和角色理解；
- 待办管理、提醒角色和角色主动提醒。

项目介绍落地页是独立的静态体验，不调用本地后端，也不等同于实际聊天应用。

## 2. 角色与会话

- 角色拥有稳定且不可变的内部 ID；名称可以修改，也可以重复。
- 一个角色对应一个持续的唯一会话，逻辑键为 `role:<role_id>`。
- 角色设定包括简介、身份背景、性格、行为规则、回复约束和称呼。
- 角色删除会清理其会话、消息、记忆、索引和未完成的角色级维护工作；活动运行期间删除会被拒绝。
- 消息按稳定顺序持久化。用户消息、完整助手消息、结构化工具调用和工具结果具有明确类型；主动提醒不会被当作新的用户回合。

## 3. 模型与运行时

模型连接由本地后端维护。网页提交的表单可以先测试再显式保存；角色保存连接 ID，不直接持有密钥。模型配置和角色绑定在每次运行开始时快照化，运行期间的配置变更只影响后续运行。

每次用户消息创建一个 Agent Runtime 运行。Runtime 负责：

- 角色级并发锁、取消、超时和终态；
- provider-neutral 的文本/工具循环；
- 能力快照、工具策略和工具审计；
- SQLite transcript 持久化和兼容的 SSE 事件。

SQLite 是会话和运行状态的权威来源。服务启动时未完成的运行收束为失败；任何可恢复的消息结束必须在下一次 provider 请求前持久化。Agent Runtime 不负责长期任务、远程执行器或外部事务调度。

## 4. 记忆与应用插件

记忆按角色隔离，由 `MemoryEngine` 统一提供检索、写入、维护和管理接口。结构化 SQLite 记录是权威来源，Markdown 文档是可读视图；回合后维护、consolidation 和 Optimizer 在后台运行，失败不会撤销已完成对话。

当前应用级能力包括：

- **主人资料**：从飞书知识库只读同步普通文档，建立本地索引，并为每个角色生成独立的角色理解；不修改飞书原文，不写入角色记忆。
- **待办**：通过网页或角色工具共用应用服务管理主人待办；提醒以指定角色的主动消息写入会话，不触发普通回合或记忆维护。
- **能力扩展**：Tool、Skill 和 Plugin 在运行开始时解析为冻结的 `CapabilitySnapshot`。角色范围工具由后端注入作用域，插件不能直接访问核心存储。

## 5. 当前边界与后续能力

当前不承诺以下能力：

- 多用户、云端同步和跨设备记忆；
- 邮件、教务系统、QQ、Telegram 等外部事务的接入；
- 长期任务、远程 Executor、Subagent、审批工作流和动态插件市场；
- 将 Skill 当作可执行代码，或把 Plugin 当作操作系统 sandbox；
- 由 Meido 代表主人发送、删除、归档或移动外部服务中的内容。

邮件能力已有 #92–#98 需求池，但尚未形成当前实现。依赖顺序为 `#92 -> #93 -> #94 -> (#95) -> (#96/#97)`，#98 依赖 #94；#95 当前仍为 `needs-info`，因为“明确重新生成”是覆盖原草稿、创建新草稿还是让主人选择，尚未确认。接入邮件前需要独立的邮件规格，至少明确：

- QQ 邮箱协议、文件夹发现、凭据保存和连接测试边界；
- 同步 checkpoint、来源邮件/线程模型、自动与手动任务的幂等键和重启恢复；
- 后台 `TaskRuntime` 与普通 Agent Runtime 的职责、状态和错误可见性；
- 草稿写入的服务端验证、来源映射、人工修改检测、过时标记和重新生成策略；
- 只生成草稿、不发送/删除/归档/移动邮件的权限与审计规则；
- 附件、已读状态、邮件全文进入模型或记忆的边界，以及邮件提醒角色的主动消息去重。

未来能力不得直接扩展普通 Agent Loop 的职责；需要长期运行、外部副作用或强隔离时，应新增对应的 TaskRuntime、Executor 或 ADR。
