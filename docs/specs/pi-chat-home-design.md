# 新版 Meido 聊天首页

状态：设计草案 · 布局方向已确认 · 2026-11-19。设计依据为维护者提供的 QQ 式聊天参考图和[新版重构决策](pi-refactor-decisions.md)。

## 桌面布局

打开首页即可和角色继续聊天。桌面从左到右依次为窄导航轨、角色列表、当前对话和可收起的角色状态栏。中间对话区使用剩余宽度。

| 区域 | 内容与操作 |
| --- | --- |
| 导航轨 | 顶部是搜索按钮，点开后焦点进入角色列表的搜索框。中段放「聊天」和「角色库」，选中的图标带高亮底色。设置固定在底部。滚动角色列表时，这些入口保持原位。 |
| 角色列表 | 每行展示头像、名字、最近一条桌面主聊消息的摘要和时间。选中行高亮。点击整行或头像都打开该角色的桌面主聊。可按名字筛选。 |
| 当前对话 | 标题栏展示角色头像和名字。角色消息靠左，主人消息靠右。消息区独立滚动，输入框固定在底部，旁边提供图片、表情和发送入口。阅读历史时，新到文字保留当前阅读位置。 |
| 角色状态 | 上方展示当前角色立绘，下方展示心情标签和一句以角色口吻表达的近况。角色执行任务时可临时显示实际进度，任务结束后回到日常状态。收起右栏后，对话区获得这部分宽度。 |

「角色库」用于浏览角色卡和创建角色。从角色库返回聊天时，恢复此前选中的角色和消息阅读位置。[角色创建方案](pi-role-creation-design.md)

## 切换角色与状态更新

选择新角色时，标题、选中行和立绘随角色一起切换，消息区读取该角色的桌面主聊历史。平台私聊和群聊各自使用独立线程。迟到的消息或任务进度仍归原线程和角色。切换期间，新角色的心情和近况可先留空，等对应数据到达后再显示。[多端会话方案](pi-multichannel-development.md)

心情和近况的来源、更新时机待定。首个原型可用两位角色的示例数据验证切换效果。接入正式数据后，仅展示已有的状态字段。输入框的素材选择器按当前角色读取图片和表情。[素材模块方案](pi-media-library-design.md)

## 原型建议

- 桌面先试导航轨 56 px、角色列表 240 px、右侧状态栏 300 px，再根据长消息和立绘的实际显示效果调整。窄屏优先显示当前对话，从左侧打开角色列表，点标题栏头像打开状态栏。
- 视觉上参考浅蓝至浅粉的页面背景、近白色气泡和柔和的选中态。角色色用于心情标签等小面积强调。
- 组件库首选候选为 shadcn/ui。可用 Sidebar 搭导航，Message、Bubble 和 MessageScroller 搭消息区，Sheet 承载窄屏侧栏。立绘与状态组合单独设计。[导航示例](https://ui.shadcn.com/blocks/sidebar) · [消息组件](https://ui.shadcn.com/docs/components/base/message)

## 原型验收

1. 搜索第二位角色，点结果后列表高亮、标题、历史、立绘与状态都对应她。此时第一位角色的迟到回复或进度只在切回该角色后可见。
2. 向上翻阅较早消息，收到流式回复时仍能读完当前段落。进入角色库再返回，回到原角色和阅读位置。
3. 收起右栏后可用更宽的区域阅读长消息，重新展开仍显示当前角色。窄屏打开角色状态再关闭，回到同一段对话，输入框保留未发送的文字。
