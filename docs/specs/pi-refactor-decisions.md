# 新版 Meido 重构决策

状态：当前 · 返回[重构开发索引](pi-based-meido-design.md)。本页只记录维护者已确认的决策。

## 2026-11-18

1. 新版 Meido 采用完整的 Pi Coding Agent 作为执行底层，后续逐项确定 Meido 功能如何接入 Pi。
2. 旧 Meido 仅作为需求参考。
3. 新版不迁移旧待办及提醒记录。[飞书用途于 2026-11-19 调整](#2026-11-19)。
4. 新版 Meido 的自然聊天设计可参考 MaiBot（麦麦）。
5. 素材库首版覆盖图片与表情包，包含动态表情。原件存于本地，使用 SQLite 建立索引，界面分为图片库和表情库。
6. 角色生图体验参考 SillyTavern。普通图片和角色原创表情共用生图流程，制作表情时在角色外观和当次要求上补充「Q 版生气表情包」等提示词。
7. 保存在角色素材库中的图片和表情可在该角色的所有聊天中查找和发送。表情收藏、聊天偏好的图包和主动选图参考 AstrBot Meme Manager。
8. 角色人设与长期记忆采用 AIRI 的组织方式：角色卡与记忆分开保存，角色专属记忆按角色归属。
9. 初始角色卡包含五个字段：名字、人物设定、关系起点、表达风格、示例对话。

10. 首版生图以能在前端使用为验收要求。角色可以自主发起付费生图，系统限制请求次数。
11. 每张原创表情发起一次生图请求和一次视觉评估请求。同一次评估检查角色形象、要求的画面形式（如 Q 版表情包）和表意效果。通过后供该角色的所有聊天使用，效果不佳的可以丢弃，不自动重画。

12. 新版 Meido 的记忆系统采用 Shiori 的分层架构：角色的常驻记忆由 Markdown 文档承载，按需检索的结构化记忆由记忆引擎管理。
13. 每次正式回复成功时结算本轮 SQLite 结构化记忆。每次 Pi 压缩成功，无论手动还是自动，都从本次压缩移出的原话中提取并更新 Pending。
14. Meido 的 SQLite 记忆设计参考 N.E.K.O. 对事件时间、事实、角色推断及其来源证据的组织方式。Dreaming 根据 Pending 更新 `MEMORY.md` 和 `SELF.md`。
15. 事件时间线只负责展示，按事件发生时间排列 SQLite 中已有的经历。角色直接检索底层记录，需要时追溯到聊天原话。
16. Dreaming 每晚在角色空闲时整理待处理的 Pending。
17. 女仆日记作为 Pi 工具提供给角色。角色自己决定何时调用，并用自己的口吻写下日记正文。
18. 每次工具调用分别校验发起人身份、工具使用权限和操作目标。生图、素材检索和发送图片都遵循这条规则。
19. 普通群友无权通过发言新增、修改或删除群记忆和成员档案，包括要求角色长期使用某个称呼。自动整理同样遵守这项限制。

图片与表情的生图、收藏及发送流程见[素材模块详细设计](pi-media-library-design.md)。

### 多端会话

获准群聊中，普通群友的默认工具采用 Shiori 的 `external_allowed` 清单。对应插件启用后，其列入清单的工具自动可用；群和成员的显式禁用仍然生效。受限的 `account_send` 只允许发给已绑定主人。[默认工具与验收](pi-multichannel-development.md#普通群友能用哪些工具)

外部平台经 Koishi/Satori 接入。Meido 按 Shiori 的私聊配对方式识别主人，按 N.E.K.O. 的人员、群和工具分项授权。会话历史归 Meido 持有，桌面主聊天、每个平台私聊以及各群或话题分别保存线程历史。只有主人通过绑定跨端识别，同一角色在主人的私人入口可读取获准的主人记忆。每轮只读取当前线程的历史。每个入站回合使用独立的 Pi 内存会话。首条验收链路为 Meido 主聊天、QQ NapCat 私聊和群聊。[多端会话开发方案](pi-multichannel-development.md)

## 2026-11-19

渠道发送状态直接取自发送接口的返回值。接口成功时显示「已发送」，报错时直接返回失败原因。分别发送的文字和图片各有一个结果。[多端会话开发方案](pi-multichannel-development.md#回合记忆与故障恢复)

新版前端首页采用 QQ 式聊天布局。桌面从左到右为导航轨、角色列表、当前对话和可收起的角色状态栏。导航轨参考维护者提供的布局，搜索在顶部，聊天和角色库居中段，设置固定在底部。切换角色时，对话、立绘和状态一起切换。[聊天首页与导航方案](pi-chat-home-design.md)

通用能力优先复用 Pi 已有工具和扩展。网页搜索与网页读取直接加载现成 Pi 扩展，Meido 沿用统一的会话权限。具体包、版本和兼容性验证见[多端工具来源](pi-multichannel-development.md#工具由谁提供开发时接在哪里)。

角色记忆的文本检索采用关键词和向量双路召回，支持 HyDE 辅助查询。推理期间展示本轮的回忆进度和实际召回内容。[双路检索](pi-memory-design.md#关键词与向量双路召回) · [回忆展示与 HyDE](pi-memory-design.md#推理期间的回忆展示与-hyde)

[飞书共享上下文](feishu-shared-workspace-spec.md)保存主人愿意共享的上层信息，包括个人资料、共同规范和资料索引。当前由 Codex 按需使用，将来接入其他 Agent 时可作为共享上下文的中间层。任务在各自的会话或工作区发起和完成，项目索引和决策放在项目侧。周报、通知、待办和多 Agent 调度退出本期范围。
