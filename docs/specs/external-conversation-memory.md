## 用户流程

手机进入群聊或陌生人私聊，点击“聊天信息”，查看当前笔记、最近动态和本会话已有档案的成员。已配对主人私聊不显示入口。离线账号允许本地编辑；账号移除后只读历史。

笔记可以保存、还原或以空文本清空。进入成员页后返回会保留笔记草稿；返回聊天保留已加载消息、阅读位置和入口焦点。成员页展示平台编号、只读昵称历史、来源会话、速记及完整档案，支持保存、还原和确认删除。删除不会删除聊天，后续正常整理可以重建档案。

多个会话共享同一个规范身份档案。两个同名不同编号的成员保持分开，不同角色的资料保持分开。不同 QQBot/飞书应用的相同 open_id 保持分开；同一已证实应用重新连接仍能使用原档案。当前会话未观察到的成员不能通过修改 URL 访问。

后台整理或其他页面已更新时，保存返回冲突，保留草稿并提供“重新读取并保留草稿”。当前已保存内容会并列展示，主人编辑合并后再保存。成员刚完成配对时，旧页面、在途保存及整理均重新核验，不能继续把主人当作外部成员。

## 整理和模型可见范围

群聊及陌生人私聊的笔记和动态来自当前线程的合规窗口，包含主人参与的群事件与已确认送达的角色回复。未知送达、内部提示、无效来源和主人私聊内容不作为外部事件；成员事实只使用可证实的外部发送者输入。

共享档案按 Shiori 优先注入触发者、结构化提及及被引用者的完整档案，其他近期成员按最近出现顺序使用速记；自动整理的空档案/速记不清除既有事实，人工编辑仍可清空。只注入当前语境中出现的相关成员；不会把成员库、群原文或旁听原文整体注入其他会话。当前笔记仅用于所属外部会话。最近动态按更新时间选择最近三天、最多五个外部会话，外部回合排除自己。每次模型请求都重验范围，超出当前请求预算的条目整体跳过，保留其余条目的来源。主动及 Drift 不把动态固化进后续请求的冻结输入。

## HTTP 契约

前缀为 `/api/roles/{role_id}/channels/threads/{thread_id}/external-memory`。所有操作均重新检查角色、线程、当前绑定及成员来源关联。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /` | 返回笔记、只读动态与时间、版本、只读状态及当前会话成员列表 |
| `PUT /note` | `{note, expectedRevision}`；笔记最多 12000 字，允许空文本 |
| `GET /members/{key}` | 返回规范档案、昵称历史、来源、状态、版本及待确认候选 |
| `PUT /members/{key}` | `{profile, shorthand, expectedRevision}`；完整档案最多 8000 字，速记最多 200 字；同时用于确认冲突候选 |
| `DELETE /members/{key}?expectedRevision=...` | 删除当前档案，成功返回 204；保留来源与持久删除版本 |

版本冲突返回 409，当前权限不允许返回 403，角色/线程/成员关联不存在返回 404，无效输入返回 422。模型成员查询遇到多个应用作用域时先返回 `scopes`，须指定 `member_scope`，不会把不同应用的事实合成一个人。

## 兼容和验证

迁移保持旧原文、笔记及摘要归属，不调用模型。相同内容可合并；不同内容标为“需整理”，页面可按来源查看并采用候选，未确认内容不注入共同事实。未知历史应用保持独立，重启不会重复导入。备份、失败恢复和降级见[操作说明](../handbook/external-memory-migration.md)。
