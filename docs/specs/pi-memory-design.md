# 新版 Meido 角色记忆与女仆日记开发方案

状态为开发设计草案，最后核验于 2026-11-19。记忆归属、更新时机、时间线和日记的产品行为见重构决策中的角色与记忆条目。下文的表名、工具签名和源码布局为建议实现，验收场景待开发验证。[重构决策](pi-refactor-decisions.md) · [Pi 执行底层](pi-runtime-integration-design.md) · [多端会话](pi-multichannel-development.md)

## 主人会体验到什么

主人说“以后讨论架构，先讲最大的风险”。这轮就可以记下这项有适用条件的偏好，下次讨论架构时能用上。等这段对话离开 Pi 窗口，角色才考虑把它列为长期候选。晚上空闲时，她可以把偏好写进 `MEMORY.md`，同时判断这件事是否改变了她对双方关系的理解。若她在下午就想写下今天的感受，可以当场调用日记工具。

原话、结构化记忆和长期文档各有用途。会话宿主持有“主人当时说了什么”；SQLite 保存“这件事何时发生、适用到什么时候、依据是什么”；角色 Markdown 表达“我长期知道什么、怎样理解我们”。角色卡保存创建时的设定，正式聊天中的长期认识另属角色记忆。草稿试聊使用临时上下文。[角色创建方案](pi-role-creation-design.md)

## 对话与后台的数据流

| 时机 | 输入与处理 | 提交结果 |
| --- | --- | --- |
| 回复前 | 宿主在当前线程内按角色、发言者、受众和绑定生效范围选取历史，创建独立的 Pi 内存会话。加载适用的 Markdown 段落、临近的重要事项和与当前话题相关的少量事件概要。 | 通过 Pi 的 `context` 钩子装配本轮记忆，同一轮的多次模型调用复用结果。记忆工具成功纠正一项内容时刷新受影响部分。近期对话和工作摘要沿用会话模块。 |
| 回复中 | 角色按需搜索经历、查看原话、明确记住或纠正一项内容，也可以自主写日记。宿主授予本轮可用工具并校验实际参数与当前权限。 | 工具返回已提交记录的回执。用户当轮明确交代的记忆立即可查。 |
| 正式回复成功 | 宿主结合 `agent_settled`、取消状态和最终回复确认回复成功，持久化该状态时登记一次 SQLite 记忆结算任务。读取已提交的原话与显式工具回执。 | 新增、合并、替代或零新增。已成功执行的工具写入有独立回执。同一次正式回复只结算一次。消息的发送结果由会话模块另行记录。 |
| Pi 手动或自动压缩成功 | 两种压缩走同一提取流程。在 `session_before_compact` 获取当前分支和拟压缩范围，在 `session_compact` 按实际 `firstKeptEntryId` 核定边界。将新移出的原话映射回 Meido 稳定消息 ID。 | 宿主持久化压缩摘要、覆盖范围并登记提取任务，再释放本轮内存会话。角色从这段原话提取零条或多条 Pending，可引用同范围内可用的结构化记录。失败或取消的压缩不推进进度。 |
| 每晚空闲 | 角色有待处理 Pending 时运行 Dreaming。取本批候选、可见的来源和当前文档，分别判断各文档是否需要修改。 | 只提交有依据的改动，保留处理进度。日记由独立的角色工具写入。 |

会话宿主在装入历史时建立 Pi 条目到业务消息的映射。连续压缩、工具循环中途压缩及自动重试都以实际覆盖的原话判定；工作摘要、注入的记忆、工具回执和日记正文不能充当新的用户证据。任务按角色、来源和范围去重。进程在提交压缩后中断时，可以从宿主已提交的范围续做。[Pi v1.5.2 压缩边界](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/compaction.md) · [Pi 扩展事件](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/extensions.md)

## 多端记忆的读取与更新

同一角色的各入口使用 Meido 宿主上的同一记忆引擎。桌面、各平台私聊、群与话题分别保留线程历史；每次建立 Pi 内存会话时，从当前线程装配历史，再从角色记忆中选本轮可见的条目。换端读取的是已经提交的记忆。回查原句、引用、附件或“上一张图”时，仍须在来源线程内操作。[多端会话的身份与受众](pi-multichannel-development.md)

| 入口 | 本轮能读取 | 新信息写到哪里 |
| --- | --- | --- |
| 桌面主人、已配对的主人私聊 | 本线程的历史，以及当前角色获准在该私人入口使用的主人记忆、长期文档段落和当前有效的纠正。 | 主人的称呼、偏好和约定归当前角色的主人记忆，证据保留来源线程与绑定代次。在桌面改的称呼，一经提交，下次已配对 QQ 私聊即可使用，反向也相同。 |
| 普通成员或陌生人私聊 | 当前私聊历史；仅在设置开启时读取该角色对该渠道稳定身份的成员记忆。陌生人是否应答沿用私聊设置。 | 允许记录时写到该成员获准的私聊范围。普通成员与管理员均沿用所在渠道的身份范围，相同昵称或头像不会合并为同一个人。 |
| 获准群聊或话题 | 当前线程、本群笔记、在本群可见的成员资料。默认关闭私人记忆；群开关和实际发言者本人的个人记忆开关均开启时，可以有限读取该发言者获准在本群使用的条目。 | 群事项按群整理。已配对主人本人的发言单独标识来源；“只在这里叫我队长”限定本群，“以后在各处都叫我阿泽”可形成该角色的主人偏好。原话保留在群线程。 |
| 仅旁听、拒收或只浏览历史 | 按群策略处理允许保留的旁听记录。网页浏览仅展示已有历史。 | 仅旁听的消息可按群记录设置成为本群语境和群资料的来源。正式回复结算只发生在有成功回复的回合；拒收事件和网页浏览均不产生记忆任务。 |

### 同群成员的记忆边界

入站时按绑定代次和实际作者识别主人。只给主人自己写的内容标记主人来源，引用、转发或群友复述的文字保留原作者；未核实的引用不能成为主人交代。主人的普通闲聊照常留在群线程，关于本人的明确通用偏好可在回合结算时进入 SQLite，成功压缩时才产生相应 Pending，供 Dreaming 判断。给偏好标记主人来源不会扩大群回复可读的私人内容。[Shiori 的群内主人分流](https://github.com/YinFengWindy/Shiori-Agent/blob/7ecceb3be3954aa3ba4b154b5e052411fe7ccb08/docs/_handbook/memory-markdown.md#L17-L24)

群友共享的长期信息限于角色在**本群**记下的公共事项，例如“本群周五晚八点活动”。个人称呼、偏好和对成员的印象按角色、群、成员稳定 ID 分别保存。回复甲时可以采用甲在本群的称呼；乙提到甲、引用甲或要求“列出你对甲的印象”时，只按乙这轮的权限使用公共材料，不能借此检索甲的个人档案。本线程里实际可见的公开发言仍可用来理解对话。同一人在另一群的称呼独立维护。

个人私聊记忆默认留在私聊。即使群和发言者本人都已开启群内参考，也只把**本人已获准向该群展示的条目**交给模型。此时输出的受众是全群。显式召回、来源回查、压缩和 Dreaming 使用相同的范围；群笔记只收录来自本群且适合共同引用的内容，不把个人档案或私聊结论转写成公共事项。

### 怎样判定群友的记忆修改请求

复用宿主已有的工具授权。记忆工具中，普通群友回合只开放获准的读取操作；执行前按实际发言者、操作和目标复核，引用主人或平台管理员头衔不赋权。称呼优先取本群已获准的设置，其次用群名片。角色按自己的口吻回应，仅在收到写入成功回执时确认“记住了”。[N.E.K.O. QQ 插件的执行前复核](https://github.com/zhaijiunknow/n.e.k.o_plugin_qq_auto_reply/blob/54acf36bf978edad4757e5fffc743c5618360700/plugin_tool_service.py#L681-L695)

后台沿用 Shiori 按会话和实际作者整理的方式。普通群聊来源只允许生成有独立事件依据的群观察或成员经历，例如“甲组织过这场活动”。固定称呼、群规等设置要求有相应写权限的直接来源；提取、压缩和 Dreaming 提交前均复用该检查。群友说“以后叫我队长”、多次重复或被旧笔记转述，都不能改变称呼。依据不足时保留聊天原文即可。[Shiori 外部会话整理](https://github.com/YinFengWindy/Shiori-Agent/blob/7ecceb3be3954aa3ba4b154b5e052411fe7ccb08/apps/backend/core/memory/markdown/external_segment.py#L1-L7)

### 主人在群里提问、在桌面查阅与群记忆更新

角色在群 A 回复主人时，消息会发给群 A 的所有人。默认使用当前线程和本群材料；群内参考私人记忆的双开关同样适用于主人。在本机管理页，主人可以选择该角色已接入的群 A 或群 B，分别查看各线程已保存的群聊记录。打开管理页只产生读取操作。回到桌面主聊天或已配对的主人私聊，角色使用该入口获准的主人记忆；其他群的原话要到对应线程查阅。

| 时机 | 本群的更新 |
| --- | --- |
| 收到群消息 | 获准保留的消息带上角色、群、话题、实际发言者、业务消息 ID 和来源时间。仅旁听时按本群设置留作后续语境；单条旁听消息不会触发正式回复结算。 |
| 正式回复成功 | 从本轮可用的群发言中提取带来源的 SQLite 记录。已确认的公共活动按群保存，成员称呼的设定须有相应写权限。区分常规安排、已确认的临时改期与群友的个人提议。 |
| 本群线程压缩成功 | 从实际移出的本群原话提取 Pending，继承群、话题和受众范围。其他群压缩、主人在网页浏览或单纯经过一晚均不产生这一批候选。 |
| 晚间空闲 | Dreaming 依据本群候选与来源，更新对应群笔记或本群成员档案。短期安排可以留在 SQLite，长期反复适用的内容才需要写入文档。 |

### 两端同时更新一个偏好

建议宿主在首次接收入站消息时为同一角色分配持久、可比较的顺序号，重复投递沿用原号。更新一个明确偏好时，在 SQLite 事务中按“角色、主体、适用范围、偏好项”定位当前版本。对于同一有效时期、同一事项的明确纠正，以来源在宿主的接收顺序裁决；平台时间可用于表达事件日期，后台模型返回的先后不参与裁决。有明确有效期的陈述按该时期保存，不追溯覆盖其他时期。遇到含义不明的冲突，保留依据供角色核实。

例如桌面先收到“叫我小林”，QQ 后收到“以后叫我阿林”。即使桌面的后台提取最后才完成，也只补充历史和依据。QQ 的明确纠正提交后，两端下一轮都读“阿林”；已经装入上下文的另一端，在下一次装配时按最新版本读取。压缩与 Dreaming 的提交也复查版本，防止旧称呼在写回 Markdown 后重新生效。

### 各线程压缩，各范围整理

宿主分别记录每条线程实际压缩覆盖的业务消息 ID。桌面聊天按本次移出的桌面原话提取，QQ 群和私聊各按自己的压缩范围提取。已结算的 SQLite 记忆可以在获准入口直接检索。

Dreaming 每晚按角色取候选，再按主体、受众和目标段落处理。桌面和已配对 QQ 中获准共享的主人候选可合并为同一条认识，保留两条来源；两个群各自的称呼写入各自的档案。读取和提交均校验来源授权：配对以前的消息不追认为主人证据，解绑后该入口立即失去主人权限。重新配对从新绑定起点核定来源；若一个段落混入当前入口不可读的证据，只使用可独立支持的可见内容，否则跳过该段。排队中的提取、工具和待发送草稿按入站授权与当前授权的交集重新校验。

## SQLite 保存什么

建议在 Node.js 服务端使用本地 SQLite。记忆库引用会话模块的稳定消息 ID，聊天回合中查证原话时，会话模块按当前线程和授权回读。主人在另一已绑定的私人入口可读取该角色获准使用的记忆内容；证据消息的 ID 只用于追溯，原话按来源线程读取。角色改名不改变记忆归属；业务查询、唯一约束、来源引用和替代关系均包含角色边界。

| 建议表 | 核心内容与用途 |
| --- | --- |
| `memory_items` | ID、角色、主体、受众范围、类型、一行概要、详情、发生时间、记录时间、有效期、状态及替代关系。类型包含经历、事实、偏好、约定和待验证的角色推断。约定可完成或取消，有时效的事项可在有效期内优先加载。 |
| `memory_evidence` | 关联记忆、来源消息、实际发言者及支持或反驳关系。多次转述同一句原话只计一份依据。 |
| `memory_directives`、`memory_mentions` | 前者保存“别再主动提这件事”等带范围的要求；后者按已送达的回复记录实际主动提到的记忆。检索命中而未说出口的内容不计提及。 |
| `pending_items` | 压缩批次、候选正文、适用场景、来源消息与记忆 ID、建议目标。对每个目标分别记录待处理、已写入、无需更新或等待新证据。 |
| `memory_jobs`、`document_revisions` | 任务保存来源范围、去重键、进度和重试状态；文档修订保存目标文档与段落、所用候选、前后版本和哈希。日记写入同样保留操作回执，以区分重放与主动再写一篇。 |

事件发生时间可以未知，或者只精确到月；“今天说起上周三答辩”要分别存两个时间。事件时间线按可确定的发生时间展示，时间未知时标明，不用记录日期冒充。页面和角色检索共用这些记录，首版无需另行追加一份 `HISTORY.md`。

### 关键词与向量双路召回

正常的文本检索同时走两路。首版建议在同一个 `memory.sqlite` 内使用 **FTS5/BM25 + sqlite-vec 0.1.9**。Node 服务用 `node:sqlite` 加载随发行版固定的扩展，再关闭动态加载。采用普通向量表和扩展的 `vec_distance_cosine` 精确计算获准候选的距离，便于直接复用多端授权、有效期、内容版本和证据条件。查询成本随可见向量数和维度增长，在 Windows 目标机测量延迟后再决定是否需要近似索引。[sqlite-vec 的 Node 接入](https://alexgarcia.xyz/sqlite-vec/js.html) · [普通表的精确向量查询](https://alexgarcia.xyz/sqlite-vec/features/knn.html) · [SQLite FTS5](https://www.sqlite.org/fts5.html)

| 步骤 | 首版实现 |
| --- | --- |
| 候选与单位 | 一条 `memory_items` 对应一个搜索单元，两路共用稳定 ID。查询先解析角色、发言人、受众、意图和事件时间范围。两路都在 SQL 的排序和 LIMIT 前限定同一可读集合；日常回复取当前有效记录，明确查过去时按当时的有效期取。主动搭话还要遵守禁提和已提规则。 |
| 关键词路 | `memory_fts` 分列索引名称与别名、概要、正文。写入和查询统一规范化全半角与大小写，用同版本的 `Intl.Segmenter('zh-CN')` 分词；群名、人名、项目代号额外保留完整检索词。将词作为转义后的字面量构造 MATCH，并绑定 SQL 参数。BM25 优先名称和概要，解决“阿泽”“转接头”等精确命中。 |
| 向量路 | `memory_embeddings` 存记忆 ID、内容版本、模型指纹、维度和 float32 向量。把主体、概要、适用条件和必要细节编码成一条文本。查询使用同一向量空间及模型规定的 query/document 编码方式。用余弦距离升序取最近项，解决换一种说法仍在问同一件事的情况。嵌入模型由实例配置，接口返回值校验维度和有限非零向量。 |
| 融合与使用 | 初始每路最多 20 条，按记忆 ID 用等权 RRF 合并：每次命中贡献 `1 / (60 + 路内名次)`，名次从 1 开始。默认回复前最多注入 3 条概要，显式回忆最多返回 8 条，可按需取正文。RRF 只排序；自动注入另检查有效关键词匹配或经中文样本校准的语义相关门槛，弱匹配可返回零条。纯时间查询走时间索引；指定 ID 按权限点查。回读原话只查当前获准线程。 |
| 更新与降级 | 业务记录与 FTS 在同一事务更新，同时登记幂等的向量任务。文本变化时旧版本向量立即退出检索；后台仅在内容版本、模型指纹仍匹配时提交结果。撤回、删除与授权变更立即影响两路。服务超时、扩展不可用或新条目尚未编码时，保留 FTS 与时间检索并标明降级状态。切换模型时后台重建新一代，查询和文档不得混用不同空间；索引可从主表重建。 |

检索由 `retrieval.ts` 统一服务于回复前自动召回与 `recall_memory`。按角色权限过滤后的条目可返回来源引用；时间线、Pending、日记和聊天原文各自沿用原有读取入口。常驻文档已覆盖的同一记忆，本轮按关联 ID 去重。融合参数和注入数量是待评测的起始值。[N.E.K.O. 混合召回](https://github.com/Project-N-E-K-O/N.E.K.O/blob/19c43089033b7e5d06c48f97811ed4ae3e940fdc/docs/zh-CN/architecture/memory-system.md#L76-L89)

2026-11-19 在隔离的 Windows x64 环境，以 Node 22.19.0、sqlite-vec 0.1.9、FTS5 和内存 SQLite 验证：两路均可执行，合并后同一条只出现一次，越权与失效记录未进入候选，旧内容版本的向量未命中。使用构造向量；交付时另用真实中文嵌入模型评测专名、改述、时间限定、零命中和跨群隔离，对比单路与双路 Recall@8、自动注入误报和 P95 延迟，并记录样本规模、维度、硬件和编码耗时。

### 推理期间的回忆展示与 HyDE

聊天界面在本轮进度区放一个可展开的“回忆”条目。回复前自动召回开始时显示“正在回忆…”，即使助手正文还没开始输出也可见。实际将条目装入模型上下文，或经主动工具交给模型后，显示“已找到 2 条回忆”，展开可看本轮可见的真实概要、可用日期及获准的来源入口。这个数量只统计交给模型的去重条目；常驻 Markdown、初筛候选和 HyDE 生成的文字不计数。零条显示“未找到相关回忆”，取消或查询失败有独立终态。辅助查询失败但原查询有结果时照常展示真实结果。

宿主在检索服务边界发开始和结束事件，带运行 ID、检索 ID、自动或主动来源。对主动 `recall_memory` 关联 Pi 的 `toolCallId`；同一次主动调用与工具进度共用一行。Pi 的 `context` 重入复用本轮已发事件。向客户端投递或重连回读时再按当前受众过滤概要、计数和来源。界面展示检索事实；群聊渠道不自动转发这些界面事件。[Pi 运行进度](pi-runtime-integration-design.md)

HyDE 用一段“假设库中有相关记忆，它可能怎样写”的短文本辅助向量检索。首版建议对有话题的显式回忆默认开启；回复前自动召回仅在有明确回指且原查询证据较弱时加查一次。纯日期、条目 ID 点查和普通寒暄跳过生成。宿主先裁定可读范围，辅助模型只接收本轮可见的问题和必要指代，生成一段假设，以文档编码方式向量化。原问题继续查 FTS5 和向量；同范围内用假设向量补查，原问与假设的向量命中按记忆 ID 取最佳余弦排名依据，合成一份向量结果再参与双路 RRF，每条记忆最多获得一次向量路计分。原查询的时间、状态和授权过滤保持有效。

生成最多一次，沿用本轮取消信号和检索时限；超时、输出为空或嵌入失败时保留原查询结果。假设只在本次检索内使用，禁止作为回复依据、可展示的回忆、SQLite 记忆、Pending 或 Dreaming 证据。只有数据库中确实存在、仍获准且通过相关性筛选的条目才返回。[HyDE 原论文](https://aclanthology.org/2023.acl-long.99/) · [Shiori 的显式回忆实现](https://github.com/YinFengWindy/Shiori-Agent/blob/7ecceb3be3954aa3ba4b154b5e052411fe7ccb08/plugins/default_memory/backend/engine/query.py#L100-L161)

## 长期文档与 Dreaming

| 每个角色的建议文件 | 内容与读者 |
| --- | --- |
| `memory/MEMORY.md` | 主人的稳定事实、明确偏好和长期交代。主人私聊按授权读取。 |
| `memory/SELF.md` | 角色的性格与形象、对主人的理解、对关系的认识。带私人来源的段落仅在相应受众范围内使用。 |
| `memory/groups/<group-key>.md`、`memory/members/<member-key>.md` | 群背景、群内共同话题或对具体成员的了解。宿主保留群、渠道和来源范围，群友的自述归所属成员。 |
| `journal/YYYY-MM-DD.md` | 角色自己写下的日记。按实例本地日期归档，一天可以写多次，也可以整天不写。 |

Dreaming 的触发规则只有一条：**每晚角色空闲且有待整理的 Pending 时，整理一批**。正在聊天就等空闲；无候选就跳过。一次可消化多次压缩的候选。首版按实例本地时间判断夜间，具体时段属于运行设置。

整理时固定本批候选。明确、持续适用的用户信息可进入 `MEMORY.md`；有直接交代或独立经历支持的关系判断可修订 `SELF.md` 相应段落。一件偶发经历可以只留在 SQLite。提出继续观察的候选在有新证据时再审。来源受众贯穿处理过程，群资料与主人私人认识分别落到适当文档。[Shiori 整理器](https://github.com/YinFengWindy/Shiori-Agent/blob/7ecceb3be3954aa3ba4b154b5e052411fe7ccb08/plugins/memory_optimizer/backend/optimizer.py)

每个目标文档独立提交。程序先登记拟修改的段落、证据、基础版本和预期哈希，再经临时文件原子替换，最后确认完成。重启时若哈希已匹配，补登记即可；版本已变化则用新版本复核。同一角色串行提交，期间新到的纠正在写入前重新核对。已明确作废的记忆，通过段落与记忆 ID 的关联从读取结果剔除或替换，下一次 Dreaming 再更新文档正文。

## Pi 工具与女仆日记

| 建议接口 | 角色什么时候用 | 成功结果 |
| --- | --- | --- |
| `recall_memory(query?, time?, item_id?, detail?)` | 回想一个话题、时间段或查证原话。要求至少一个定位条件。 | 带日期的概要列表，或指定条目的详情与可见来源。 |
| `remember_memory(content, kind?)` | 用户明确要求记住，或本轮确有值得当场保存的事实。 | 已提交的 SQLite 记录 ID、绑定的来源。 |
| `correct_memory(item_id, change, content?)` | 用户指出原先记错，或说明某项偏好现在变了。目标不明时先检索。 | 错误归属被撤回，或旧偏好结束有效期并关联新条目。后续回合可立即采用。 |
| `write_diary(content)` | **角色自己想写时调用，正文由她用自己的口吻写。** | 正文保存后返回条目 ID 和日期。同日再次主动调用可增加新条目；同一调用重试只返回原回执。 |

角色 ID、时间、受众、操作 ID 和文件路径均由宿主提供。日记可以记录角色的主观感受，保留角色作者身份和来源范围；私人日记正文不随群聊工具回执公开。普通回合、压缩和晚间整理均不自动生成日记。写入失败如实返回错误。建议用稳定操作 ID 将同日条目按序写入当天文件，恢复时检查已有条目标记，避免一次调用被追加两遍。

## 交付顺序与验收

在隔离开发实例中使用可控模型、可控时钟和真实 Pi SDK。先跑通主人私聊的保存与回忆，再验证跨压缩及跨晚间的认识更新，最后验收群聊可见范围与独立的日记工具。

| 场景 | 通过条件 |
| --- | --- |
| 回忆进度与真实结果 | 延迟检索，正文前能看到“正在回忆…”；两路命中同一条只展示一次，展开所见与交给模型的可见条目一致。主动查证时工具事件不重复显示。空结果、取消、撤权后重连分别验证。 |
| HyDE 辅助查证 | 用可控模型生成含虚构细节的假设。真实近义条目可以被补召回，假设不出现在回忆、回答证据或记忆存储中；库中没有相关条目时返回零条。模拟生成超时，原查询仍返回。用真实中文问题对比开关 HyDE 时的 Recall@8、误召回和 P95 延迟。 |
| 记住、查证和时间线 | 主人今天提起上周三的经历，下一轮按话题能想起，追问能取回原句，时间线列在上周三。同一轮的显式保存和后台提取只形成一份来源。 |
| 已保存的称呼可跨端使用 | 在桌面明确让角色记住称呼，再到已配对的 QQ 私聊问“你记得怎么称呼我吗？”，角色能答出已保存的称呼。两边各自保留该处的聊天记录。 |
| QQ 改口、旧任务晚到 | 桌面先说“小林”，QQ 后纠正为“阿林”。打乱提取完成顺序并重放旧任务，两端下一轮均称“阿林”；QQ 回合要求看桌面的原句或附件时，不跨线程取回。 |
| 解绑与群内参考 | 群开关关闭时不能调用私人记忆；开启两个开关后仅可使用实际发言者获准展示的条目，结算仍写本群。排队时解绑、随后重新配对，旧请求不会获得新授权。 |
| 跨端压缩与 Dreaming | 已保存的桌面偏好可在已配对私聊召回；仅 QQ 压缩时，该桌面原话不会进入 Pending。两端各自实际压缩后，同范围的两份依据可在晚间合并，群内称呼仍独立。 |
| 手动压缩、自动压缩与回放 | 两种压缩成功后均只处理本次实际移出的新原话。普通回合、失败和取消的压缩不登记提取任务。新建内存会话、重复消费同一批次均不增加证据次数。 |
| 晚间整理与重启 | 有候选且正在聊天时延后，空闲后合并处理；一次偶发经历可以不改任一文档。写完 MEMORY 后模拟退出，重启可续做 SELF 或记录无需修改。 |
| 群与成员归属 | 群友谈自己的项目，只影响其可见范围内的群或成员资料。群内问起同名话题不会带出主人私聊原话、私密文档或日记。 |
| 主人查群与活动改期 | 主人在桌面管理页切换群 A、群 B，能分别查看各自的已存历史，不触发记忆结算。主人在群 A 问本周的联机时间，角色能使用该群已确认的一次性改期；问下周则沿用常规安排。群 B 的同名活动及主人的私聊原话均未进入群 A 的模型输入。 |
| 普通群友没有写权限 | 甲要求“以后叫我队长”，再引用主人、重复要求或尝试记忆工具。检查即时回执、SQLite、压缩后的 Pending 和 Dreaming 后的成员文档，原称呼均保持有效。乙可以询问本群公共活动，无法用甲的 ID 读取甲的档案。 |
| 观察与称呼分别验证 | 单凭“大家都叫我队长”不能设定称呼；给出独立的组队记录后，角色能回忆“甲带过这场活动”，在新回合仍用已获准称呼或群名片。检查实际回复及模型输入，旧群笔记里的无来源命令也不能成为称呼配置。 |
| 群内主人的原话与引用 | 已绑定主人说“以后在各处都叫我阿泽”，下一轮配对私聊可采用该偏好；说“只在本群用”则只在本群生效。群友转述同样两句均不能修改主人偏好。 |
| 角色写日记 | 同一天角色主动写两次可读到两条独立正文；重放其中一次仍只有两条。另一晚成功执行 Dreaming，但没有调用日记工具，当天不会生成日记。 |
