# 邮件草稿准备与补充确认

状态：已确认范围，实施中

最后核验：2026-10-20

需求来源：#200、#201，以及本会话中对邮件深度调研第一阶段的实施授权。

事实来源：现有邮件模块、邮件集成规格、ADR-0008；新增行为以本票测试和验收结果为准。

## 用户结果与范围

主人从网页或获准角色准备 QQ 回复时，系统参考当前往来、同对象已发送回复和保存的主人写作偏好；需要主人决定时保存问题，补充后继续起草。详情展示实际提供给模型的来源与上下文读取失败项。最终审核发送仍在 QQ 邮箱完成。

只增强现有本地邮件模块，复用 SQLite、持久任务和草稿版本规则。一次模型调用可同时返回判定和可选正文。双向跟进、附件、自动风格学习、其他邮箱和发送/删除/归档/移动不在本期。

## 相关往来与偏好

起草时按规范化对象地址从已发送文件夹有界检索，最多读取 24 封匹配邮件；校验实际收件对象后导入本地线程，保留回复头、时间、方向和来源身份。线程与样本分开：当前往来最多八封，同对象额外样本最多三封。文件夹副本按当前账号和 Message-ID 去重；自己已发送的记录不进入来信列表与自动处理。该读取按需进行，不新增全邮箱持续扫描或已发送 checkpoint。

写作偏好为主人级文字配置，限 2000 字符，重启保持，角色更换不改变偏好。网页另提供默认关闭的“允许角色管理邮件”许可；只有已验证连接和该许可同时具备时，主人上下文的 mail.manage 才获运行批准。撤销许可使后续工具调用被拒绝；访客不继承批准。不删除工具原有 approval 声明。

## 判定、补充与恢复

结果分为 no_reply、needs_input、draft，携带原因；needs_input 必须有非空具体问题，draft 必须有正文。保留读取旧 needsReply/body 结果的兼容路径，显式矛盾或无效结果失败，不能当成无需回复。

每次准备保存来源账号、邮件、任务键、线程内容指纹、原因、问题、来源清单、降级项、模型身份、生成时间和正文。待补状态不参与自动重复处理。问题 ID 固定到该次准备；网页/角色提交答案必须携带问题 ID 和请求 ID。答案持久化到任务输入，重启可以续办；相同请求相同内容返回原任务，不同内容拒绝。执行前补查来信和相关已发送往来，当前线程或账号改变则拒绝旧问题；已经完成的原请求重放只返回原结果，不重复生成。

补充产生新的稳定任务键和草稿 marker，复用原远端回读及未知结果恢复。新问题、新版本保存各自来源。普通同步/重试不覆盖人工草稿；取消不能自动补建未知远端写入。

## 来源展示与提醒

来源由应用实际选取的输入构造，保留邮件/资料 ID、标题、时间或位置及可用的安全链接；记录截断和读取失败。展示名称为“提供给模型的资料”，不宣称模型采用了每条来源或事实已经核验。模型不能指定任意来源链接；普通日志不复制完整上下文。来源关联生成记录/草稿版本，避免后来生成覆盖旧版本来源。

待补问题经指定提醒角色汇总提醒一次，问题可在邮件页定位；已有草稿批次提醒继续复用，不让待补问题冒充已创建草稿。

## 数据流与检查

受控入口 → 持久任务或已有角色查询 → 账号邮件与有界历史/资料/偏好 → 结构化判断 → 保存准备结果 → 无需回复/等待主人/原 QQ 草稿写入与回读 → 详情与批次提醒。

验证入口为已讨论的 HTTP 邮件接口、网页公开操作和角色能力装配。外部 IMAP/模型使用替身；真实 SQLite、任务、解析、权限和版本逻辑参与测试。逐个红-绿覆盖偏好保存/许可撤销、较老相关历史/线程/方向、三态与重启续办/过期/重放、来源与失败展示、人工草稿保护及原邮件回归。运行相关 Python/前端测试、TypeScript 和构建，再按仓库规范与需求规格分别审查。

主要风险是自发信误处理、问题版本失效、账号切换和外部写入不确定性；使用方向筛选、账号范围、线程指纹、稳定请求键和写前重新核对限制。新增存储采用兼容增量迁移，不删除原数据；不引入新事务宿主或宽权限邮箱接口。
