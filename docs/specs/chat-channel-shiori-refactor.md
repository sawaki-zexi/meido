# 聊天与 QQ 多端 Shiori 对齐重构（#265）

状态：已实现，待 PR 验收与合并。基线 Meido `6103b55`；参考 Shiori `d3acaed186b172a78a5892e0307e9affd89759f0`。

## 用户结果与授权

普通聊天、工具、搜索、生图及桌面/QQ 图片输出应能连成实际可用链路；按上游实际行为修正拟人回复与外部成员工具边界。维护者明确允许较大范围代码重构，要求一个总 PR。本范围不包含清空历史、迁移回滚、使用真实付费服务、测试发送 QQ 消息或自动部署/合并。

## 已核实故障与差异

- 本机仍运行 `bb29bdd`。最近三次桌面聊天在正文前因工作摘要未正常完成而失败，工具审计与渠道投递尝试均为零。旧记录没有供应商实际 stop reason/usage，不能断言一定是输出上限耗尽。
- Shiori 的压缩失败在软阈值且原请求仍可容纳时保留原请求；硬超限采用受限最小请求，不把未完成摘要当成已提交历史。Meido 当前把摘要异常传播为整个聊天失败。
- OpenAI Chat Completions 的 tool message 不承载 image_url；上游把工具文本和后续 user 多模态观察分开。Meido 当前的直接图片 tool content 与严格兼容端点不匹配。
- 现有发送工具只有附件 ID 输入，但普通文件工具没有把工作区文件接成该 ID 的用户流程；桌面上传文件的模型投影也不提供可用 ID。消息渲染器本身支持图片和文件。
- Shiori 桌面 message_push 支持本地文件；QQ account_send 支持图片路径/URL，不支持任意出站文件。不得把 QQ 文件发送虚构为上游能力。
- Shiori 拟人聊天是普通回合中的 finish_reply/messages 协议，桌面和普通渠道共用。Meido 原群 naturalEnabled 控制的是未提及主动插话，应明确独立命名，不能冒充该协议。
- Shiori QQ 群普通回合由 @/引用机器人触发，其余为监听。主人完整工具、访客 external_allowed 白名单；生图在外部白名单。QQ 没有 Grok Bot 的 full_tools capability。
- 上游 list_schedules 列当前角色任务；account_list/targets 列当前角色渠道目录，访客 account_send 只能发向绑定主人，但不只限来源账号。身份和历史可见性不因此升级为主人。
- 搜索的上游默认同为 Exa 公共 MCP。本机旧记录只保留泛化错误，不能定位 DNS/HTTP/协议原因；空结果应返回 count=0 而不是网络失败。

## 实施分工与数据流

1. **普通聊天可持续**：ContextWindowProvider 对齐压缩降级与一次尝试语义；保存脱敏 stage/stop_reason/usage。规范 OpenAI 工具图片投影，修复连接测试与真实 rich 路径不一致及空正文成功。仅可选能力故障降级，必需身份/预算不能跳过。
2. **文件到可见消息**：在既有附件存储归一化 ID、角色工作区路径和图片 URL；message_push/account_send 共用。实际发送工具才产生附件副作用；看图工具的观察像素不自动发出。桌面已提交推送通过原消息事件即时显示，QQ 复用原真实回执。
3. **QQ 与拟人**：普通回合增加上游分条回复协议与角色级开关；旧群主动插话保留数据并改名区分。按实际外部工具白名单接入生成与目录/任务功能，源身份保持真实，既有授权撤销和投递状态继续有效。
4. **搜索可定位**：复用现有 Exa 请求和网络防护，区分成功空结果、HTTP拒绝、传输、协议和解析错误，给出安全操作提示。

共同改动集中整合到本 issue 总分支，不发布堆叠 PR。不为本次重构再建通用运行时、消息账本或配置版本框架。

## 明确保留的边界

- 源渠道、角色归属与历史范围不靠模型自称改变；QQ 外部工具可用不等于读取主人私聊历史。
- 输出本地文件限制在角色当前已授权工作区或既有 owned 附件，不能发送其它角色、配置或凭据文件。图片 URL 保留现有地址、重定向与大小验证。
- 普通二进制文件作为下载附件而非可执行内联内容。QQ 不支持的格式明确报告，不偷偷变成外链发送。
- 取消和未知结果不代表远端未发生；不自动重发外部发送或付费生图。保留所有既有记录，不靠删库恢复功能。
- 新代码改变的是应用能力与界面，不自动修改用户本机连接、凭据或运行服务。
