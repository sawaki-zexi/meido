# Meido 前端风格与结构

状态：当前
事实来源：`web/src/`、`web/src/App.test.tsx`
最后核验：2026-10-20（角色表单操作位置与应用内删除确认）

## 风格原则

> 需要她时，她就在；不需要时，她安静地留在那儿。

- **首页即对话**：进入后直接打开上次对话的角色（`localStorage` 键 `meido:last-role`），没有记录时打开第一个角色；没有角色时仍显示对话界面（输入框禁用），并提示创建角色。
- **消息应用布局**：桌面采用三栏：最左为 64px 导航轨道，顶部搜索，其下为“对话 / 角色”图标，设置固定在左下角；第二栏为 276px 角色列表，展示头像、名称和一行简介，当前对话角色以浅色表面高亮；右侧显示对话或角色酒馆。搜索按名称与简介筛选列表和酒馆卡片，卡牌编号不随筛选变化。回复生成中锁定角色切换。
- **角色酒馆**：第二栏顶部提供“新建 / 导入角色卡”和“全部角色”计数，角色行保留进入对话的行为；主区以自适应网格展示角色，每行卡片均分可用宽度，卡片表面进入对话，右上角的铅笔图标打开编辑。新建和导入复用原有居中角色填写页：左侧卡牌预览，右侧表单；导入先预览并确认填充，保存前不创建角色。保存后弹出她的专属卡牌，可“开始对话”或“稍后再聊”。关闭或取消填写页回到打开前的页面。
- **专属卡牌**：编号按酒馆中的顺序；色相、背景纹样与角标符号由角色 ID 稳定派生（`RoleCard` 的 `cardTraits`），改名不变。酒馆、创建页预览和新卡牌统一为 4:5；专用卡片图铺满卡面，底部渐变衬托名称、简介和称呼，独立小头像按钮保留头像原图预览。没有卡片图时，酒馆保留圆形头像或角色首字。
- **角色资料**：打开后直接编辑，保存成功后保持可编辑；取消丢弃本次未保存修改。创建与资料表单的保存、取消随内容位于表单末尾，不悬浮遮挡字段；已有角色的删除入口独立置于下方管理区。删除使用应用内小弹窗，显示已保存的角色名称和永久删除范围，默认聚焦取消；取消或 Esc 返回原草稿，删除请求期间禁止重复提交与关闭，失败在确认框内显示原因并允许重试。资料与账号标签下的内容受弹窗可用高度约束，桌面表单独立滚动、手机整页内容滚动，底部操作始终可达。
- **图片裁切**：头像使用圆形 1:1 预览并保存为方形 PNG，卡片图按 4:5 预览和保存；拖动、缩放与窗口尺寸变化后，预览范围始终与导出一致。上传后自动滚动到裁切区，短窗口按可用高度缩小预览；裁切期间只显示裁切操作，完成或取消后恢复角色表单保存操作。更换图片重置裁切，加载失败提示错误并禁止保存。
- **克制的按钮**：不使用高饱和实心按钮。导航与发送等动作使用有可访问名称和提示的图标；新建和导入同时显示图标与文字。
- **图标语义**：不同功能使用独立的 24×24 线性图标：模型为层叠、记忆为心形、主人资料为书册、待办为清单、邮件为信封、多端连接为多设备、我的身份为证件卡、MCP 服务为插头、NovelAI 生图为图片、编程委托为代码；功能内出现的图标与入口保持一致。附件使用回形针，编辑使用铅笔；关闭、刷新、新建等同类动作保持一致，按钮继续提供可访问名称与提示。
- **聊天输入区**：标题栏保留角色资料、记忆和待办入口；消息区居中，底部为悬浮圆角输入框，上层输入文字、下层为附件、模型选择和发送，保留多附件预览、拖放与键盘发送行为。
- **消息滚动**：打开会话和主动发送时定位到最新消息；在底部阅读时持续跟随流式文本、图片加载和消息区尺寸变化，使用消息区自身的即时滚动，避免每个片段重启平滑动画。向上阅读历史后暂停跟随，回到底部附近或主动发送后恢复；后台刷新不打断阅读位置。记忆、待办来源继续定位到原消息，定位后发送新消息恢复底部跟随。
- **发送与停止**：提交后立即清空本次文字和附件；生成期间可编辑下一条草稿，发送按钮切换为“停止回复”，Enter 不并发提交。收到回复完成或失败的终态事件后立即恢复发送，不等待 HTTP 连接关闭或流取消回收；中间文字和工具输出不视为终态。停止仅取消当前桌面运行，保留已生成内容并标为“已停止”；后端确认取消并释放运行锁后恢复发送。完成或停止不覆盖新草稿；未接收的失败提交恢复原草稿与附件，已有新文字时另行保留未发送内容，避免覆盖新草稿。
- **浮层**：`Dialog` 提供四种形态，`page`（居中大页：角色填写页与角色资料，左侧为卡牌预览）、`drawer`（右侧抽屉，备用）、`modal`（居中：设置）与 `compact`（小卡片：新卡牌展示）；Esc 或点击遮罩关闭，关闭后焦点回到触发位置。关闭角色填写页保留草稿。
- **设置可扩展**：设置由分类导航与内容区组成，分类在 `SettingsDialog` 的 `sections` 数组中声明；当前包含“模型”“记忆”“主人资料”“待办”“邮件”“多端连接”“我的身份”“MCP 服务”“NovelAI 生图”和“编程委托”。
- **淡粉色调**：浅粉为主、轻紫过渡的连续渐变覆盖整个界面；导航、列表与主区通过半透明表面和轻阴影保持连贯，避免强烈的区块分割。
- **角色可辨**：每个角色由稳定 ID 派生色相（`--role-hue`），用于头像、卡牌和她的名字。改名不改变颜色。
- **状态一致**：
  - 加载：`Placeholder loading`（旋转点 + 文字，`role="status"`）
  - 空内容：`Placeholder`
  - 失败：`Notice`（`role="alert"`，可关闭）；成功提示用 `Notice tone="success"`
  - 生成中 / 未完成：消息标题中的状态标签；未完成回复使用虚线边框
- **响应式**：760px 以下保留 56px 的最左导航，右侧一次只显示列表或主区，默认显示对话；标题栏返回图标或导航搜索切到列表，选择角色或进入酒馆后切回主区。酒馆按可用宽度排列卡片，手机为单列，设置全屏显示。

## 目录结构

```text
web/src/
  api/             后端请求、错误文本、SSE 解析和共享类型
  ui/              与业务无关的展示组件（Avatar、Icon、Dialog、Placeholder、Notice）
  features/
    role-management/  角色列表、详情编辑、创建草稿和删除
    chat/             唯一会话、欢迎页、消息发送和流式回复
    model/            对话模型连接设置（设置中的“模型”分类）
    settings/         设置分类注册、记忆和主人资料配置
    tavern/           角色酒馆与角色卡牌
  App.tsx          外壳布局、首页角色选择、浮层切换和跨功能协调
  styles.css       设计变量（:root）、全局布局和共享样式
```

- 功能状态放在各自的 `use*` Hook 中，组件只负责渲染；`App.tsx` 只协调浮层切换和跨功能动作（例如删除角色后清空其会话）。
- 待办面板参考 Today AI 的分组任务界面，使用 `page` 形态居中展开宽幅工作区：桌面左侧为导航与筛选，右侧为清单，详情使用宽幅表单；窄屏导航移到顶部，手机全屏展示。保留“待办 / 提醒”页签与独立详情编辑；数据加载和写入由 `useTodos` 管理，局部样式位于 `features/todo/todo.css`，复用全局外观变量。日期分组和时间编辑规则见[待办规格](todo-reminder-spec.md#9-前端行为)。
- 流式事件先由 `api/stream.ts` 解析为类型化事件，再由 `applyStreamEvent` 纯函数更新消息列表。
- 目录名避免使用 `roles/`：它被 `.gitignore` 用于本地角色数据。
