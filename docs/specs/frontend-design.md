# Meido 前端风格与结构

状态：当前
事实来源：`web/src/`、`web/src/App.test.tsx`
最后核验：2026-09-30（Issue #20）

## 风格原则

> 需要她时，她就在；不需要时，她安静地留在那儿。

- **首页即对话**：进入后直接打开上次对话的角色（`localStorage` 键 `meido:last-role`），没有记录时打开第一个角色；没有角色时仍显示对话界面（输入框禁用），并提示创建角色。
- **消息应用布局**：左侧为会话列表（参考 QQ：头像、名称、一行简介，当前角色高亮），右侧为当前角色的对话。品牌名下方是“对话 / 角色”分段切换，在对话页与角色酒馆之间来回；设置图标在左下角；对话标题栏的图标打开角色资料。回复生成中锁定角色切换。
- **角色酒馆**：独立的角色展示页，以卡牌网格展示全部角色；最后一张虚线卡牌用于新建角色（空对话页的“+”也可直接打开），点击后在屏幕中央打开角色填写页：左侧是随输入实时更新的卡牌预览，右侧是表单。点击卡牌查看资料，卡牌上的对话图标直接进入她的会话。保存新角色后弹出她的专属卡牌，可“开始对话”或“稍后再聊”。关闭或取消填写页回到打开前的页面。
- **专属卡牌**：编号按酒馆中的顺序；色相、背景纹样与角标符号都由角色 ID 稳定派生（`RoleCard` 的 `cardTraits`），改名不变。卡面显示首字、名称、简介和她对你的称呼。
- **克制的按钮**：不使用粉色实心按钮。发送、新建、编辑、删除等动作使用图标按钮；表单内的主要动作只以文字颜色强调。
- **浮层**：`Dialog` 提供四种形态，`page`（居中大页：角色填写页）、`drawer`（右侧抽屉：角色资料）、`modal`（居中：设置）与 `compact`（小卡片：新卡牌展示）；Esc 或点击遮罩关闭，关闭后焦点回到触发位置。关闭角色填写页保留草稿。
- **设置可扩展**：设置由分类导航与内容区组成，分类在 `SettingsDialog` 的 `sections` 数组中声明；当前只有“模型”。
- **白粉色调**：雪白与樱粉为底，主色为玫粉 `--rose`；标题使用衬线字体。
- **角色可辨**：每个角色由稳定 ID 派生色相（`--role-hue`），用于头像、卡牌和她的名字。改名不改变颜色。
- **状态一致**：
  - 加载：`Placeholder loading`（旋转点 + 文字，`role="status"`）
  - 空内容：`Placeholder`
  - 失败：`Notice`（`role="alert"`，可关闭）；成功提示用 `Notice tone="success"`
  - 生成中 / 未完成：消息标题中的状态标签；未完成回复使用虚线边框
- **响应式**：760px 以下一次只显示一栏，默认显示对话；标题栏返回图标切换到会话列表，选择角色或进入酒馆后切回主区域。酒馆为两列卡牌，设置全屏显示。

## 目录结构

```text
web/src/
  api/             后端请求、错误文本、SSE 解析和共享类型
  ui/              与业务无关的展示组件（Avatar、Icon、Dialog、Placeholder、Notice）
  features/
    role-management/  角色列表、详情编辑、创建草稿和删除
    chat/             唯一会话、欢迎页、消息发送和流式回复
    model/            模型连接设置（设置中的“模型”分类）
    settings/         设置对话框与分类注册
    tavern/           角色酒馆与角色卡牌
  App.tsx          外壳布局、首页角色选择、浮层切换和跨功能协调
  styles.css       设计变量（:root）和全部样式
```

- 功能状态放在各自的 `use*` Hook 中，组件只负责渲染；`App.tsx` 只协调浮层切换和跨功能动作（例如删除角色后清空其会话）。
- 流式事件先由 `api/stream.ts` 解析为类型化事件，再由 `applyStreamEvent` 纯函数更新消息列表。
- 目录名避免使用 `roles/`：它被 `.gitignore` 用于本地角色数据。

## 测试

前端使用 Vitest + Testing Library，在 jsdom 中渲染完整 `App` 并模拟后端接口，只断言用户可见行为。运行：

```bash
npm run test:web
```
