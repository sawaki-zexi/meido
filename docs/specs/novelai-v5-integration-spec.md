# NovelAI V5 生图接入规格

状态：已确认的开发规格。2026-11-12 主人要求开始实现，按第 8 节三阶段顺序交付。真实生图验收和 PR 合并分别等待对应授权。

最后核验：2026-11-12。当前源码基线为 `origin/main` 的 `76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf`。本规格基于本次对话中的三阶段方案，区分已核验事实、拟议行为和待核验事项。

事实来源：[当前生图配置](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/backend/app/novelai_generation/config.py)、[请求构造](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/backend/app/novelai_generation/parameters.py)、[生图服务](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/backend/app/novelai_generation/application.py)、[现有生成契约](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/docs/reference/novelai-generation.md)、[ADR-0016](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/docs/adr/0016-bounded-novelai-generation.md)、[ADR-0031](https://github.com/sawaki-zexi/meido/blob/76242e6e0a5972d41f7c04a6eaa62bc32fb7dfaf/docs/adr/0031-novelai-plugin-readiness.md)、[NovelAI 模型说明](https://docs.novelai.net/en/image/models/)、[生图 API](https://image.novelai.net/docs/doc.json)和 [V5 Full 强度说明](https://docs.novelai.net/en/image/effort/)。当前源码和测试优先于历史文档中已过时的实现描述。

## 1. 问题与目标

主人已经可以通过 Meido 的 NovelAI 工作台、角色聊天和故事功能使用生图，但当前配置只允许 V4.5 Full 和 Curated，请求及提示词校验也围绕 V4.5 编写。主人无法选择 V5，不能在现有工作流中使用 V5 的多语言提示词或 Full Medium 模式。

本规格的目标是：主人在保留 V4.5 和既有角色、历史及授权的前提下，选择 V5 Full 或 Curated，通过现有工作台和获准的角色交互生成、保存、查看和重生成图片；随后增加多语言输入及 Full Medium 选项。系统须向主人准确展示所选模型、实际参数和未完成的生成状态。

本规格复用已有 NovelAI 服务，不新建通用多供应商生图平台。现有默认模型不因升级自动改变；选择 V5 是主人的显式设置或单次选择。

## 2. 已核验事实与边界

1. **已提取：**主线的模型允许列表只包含 V4.5 Full 和 Curated，允许列表长度最多为 2；生成请求固定使用 V4.5 相关参数。工作台、聊天工具、标签库及场景 CG 存在英文 ASCII 限制。
2. **已提取：**故事插画目前优先选用已获允许的 V4.5 Full；只在基础请求中增加 V5 模型并不能保证故事模式实际选用 V5。
3. **已提取：**现有服务拥有独立凭据、配置修订、角色与来源校验、有限尝试次数、TaskRuntime、持久账本、媒体历史及原来源交付。来源许可以当前源码为准：符合现有许可的群友也可能触发生图，主人专用管理权限不因此扩大。[自然来源任务 #343](https://github.com/sawaki-zexi/meido/issues/343)、[原会话管理 #346](https://github.com/sawaki-zexi/meido/issues/346)。
4. **已提取：**NovelAI 已提供 V5 Full、V5 Curated，V5 Full 有 High 和 Medium。公开网页的[模型常量](https://novelai.net/_next/static/chunks/1qr-_uukhj8ho.js)分别列有 `nai-diffusion-5-full`、`nai-diffusion-5-curated` 和 `nai-diffusion-5-full-medium`；核验时该公开文件 SHA-256 为 `c86de7b60f86da1c96ecc8de60c5a7bace6aea750279733769997401d976196a`。网页代码是标识证据，**不是**对这些标识、各请求字段、图生图和账户权限已通过真实 API 验证的证明。
5. **已提取** 官方 API 描述接受通用模型字符串，要求生成请求由人的操作发起，并禁止自动生成造成过量负载。其公开 schema 需要结合官方客户端核验各模型的请求映射。**实施判断** 既有场景 CG 由真实主人输入回合触发，沿用有限次数、去重、冷却和单次请求边界即可接入 V5。这是依据当前接口要求作出的集成判断，供应商并未对 Meido 作出单独认证。
6. **已提取：**NovelAI 对 V5 Opus 免费生成设置使用上限。本地尝试次数不是供应商余额、免费额度或 Anlas 费用估算。[模型说明](https://docs.novelai.net/en/image/models/) · [订阅说明](https://docs.novelai.net/en/subscription/)

## 3. 用户故事

1. 作为主人，我想在生图设置中允许并选择 V5 Full 或 Curated，以便使用新的图片模型。
2. 作为现有用户，我想升级后保留 V4.5 默认、凭据、额度和历史，以便原有使用方式继续工作。
3. 作为主人，我想在工作台使用 V5 文生图，并查看实际模型和生成参数，以便知道使用了什么条件。
4. 作为主人，我想使用自己获准的图片进行 V5 图生图，以便基于已有素材创作。
5. 作为主人，我想让角色按现有授权在聊天中使用 V5，以便图片随原对话返回。
6. 作为主人，我想让故事插画使用我选择的 V5，而不是被旧的 V4.5 优先规则覆盖，以便故事与当前设置一致。
7. 作为主人，我想让符合条件的自动场景 CG 使用 V5，并在不可用时看到原因，以便判断是否调整设置。
8. 作为主人，我想浏览 V4.5 和 V5 的历史并重用参数，以便继续创作而不混淆原图模型。
9. 作为主人，我想用中文、日文或英文为 V5 编写提示词，以便自然地描述画面。
10. 作为主人，我想预览角色标签扩写在当前模型下的实际结果，以便在发送请求前发现不兼容内容。
11. 作为主人，我想选择 V5 Full 的 High 或 Medium，并提前看到参数限制，以便权衡效果和额度。
12. 作为主人，我想在模型不可用、余额不足或结果未知时看到准确状态，以便决定下一步而不重复消费。
13. 作为主人，我想停止或查询仍在运行的生成，并保留原会话和实际交付状态，以便知道图片是否真正完成。

## 4. 用户可见行为与验收

以下为目标行为；阶段之间的依赖和未解决问题见第 8、9 节。

### 4.1 V5 基础生图

- 主人能在服务设置中分别允许 V5 Full 和 Curated，并选择已允许的模型作为默认；工作台和已有手动生图入口可从当前允许列表选择模型。V4.5 与 V5 可以同时存在。
- 对已有配置，升级和普通保存不自动添加已允许模型、不变更默认/NSFW 模型、不改变开关、凭据或额度；新模型须由主人明确允许和选择。旧客户端仍可读取与保存其支持的字段，未提交的新字段不得被清空。旧界面如果提交只包含 V4.5 的完整允许列表，不能因此静默移除已允许的 V5：服务须保留未被旧客户端明确管理的模型，或拒绝该保存并提示刷新；同时保留现有配置修订冲突检查。
- 主人在工作台选择 V5 后，可使用核实受支持的文生图与图生图；底图仍限当前角色和来源获准的附件或角色素材。参数不符合模型能力时，在占用本地次数或发出请求前明确提示，保留可编辑内容。
- 主人或现有许可允许的当前渠道输入可使用角色聊天生图；受管后台任务完成后仅按当前来源和投递权限附图或发送。不能因接入 V5 扩大访客、群聊、主动回合、工具或媒体权限。
- 当前有效默认为 V5 时，故事中的新插画使用该 V5；旧 V4.5 配置保持原有故事模型选择行为。已冻结的故事资源和生成请求不因之后改设置而改变。不可用时说明原因，不静默改用其他模型。
- 自动场景 CG 使用角色已有开关、辅助模型、真实主人输入检查、额度、冷却与去重，以实际选定的模型和该版本的提示词要求提交。V5 候选须冻结服务修订与模型，配置变化后重新核验资格。V4.5 沿用已有行为。
- 新历史展示实际模型、模式、有效参数、状态、图片和交付事实。V4.5 历史不被改写；复用参数或重生成不把原 V4.5 记录冒充 V5，也不把 V5 记录静默替换成 V4.5。
- 重生成是新的明确请求，须按当前模型允许列表、来源、模式、资源和额度重新校验。原底图按现有规则冻结；已有结果、未知结果和权限变化不触发自动重复生成或重新投递。
- 由服务返回并受支持的透明图片，在 Meido 受管保存、历史和下载中保留原有透明通道；渠道平台如何处理图片以实际平台回执与能力为准，不承诺外部平台保留透明度。

### 4.2 V5 多语言提示词

- V5 的正向和负向提示词可包含中文、日文、英文及其混合文本。角色聊天和场景辅助模型在实际使用 V5 时不再被要求只能输出英文；现有角色外观信息、标签扩写与权限边界继续适用。
- V4.5 保持现有 ASCII 输入约束；切回 V4.5 后，若当前提示词或匹配的标签包含不兼容字符，在提交前指出原因并保留输入，不自动翻译、删除或截断。
- 角色标签可保存多语言内容。预览按所选模型检查；旧客户端未提供模型时使用当前有效模型。正式提交按实际冻结模型重新校验，不能因为预览通过而绕过当前许可。
- 标签中的权重片段继续按原语义保留；多语言文字在编辑、预览、提交、历史和重用时不被静默改写。前后端对长度、换行和控制字符使用一致且有界的规则；多字节文字、组合字符及边界长度须可预测地通过或拒绝。字符数限制不冒充供应商 token 计数。

### 4.3 V5 Full Medium

- 主人可为 V5 Full 选择 High 或 Medium；其他模型不得错误展示或接受 Medium。旧 V5 记录若无强度字段，只有在有证据可确定原本为 High 时才显示 High；无法确定时显示未知，不虚构历史。
- Medium 固定 14 步和 Euler Ancestral；不能指定自定义负向提示词或更改其预设。受限制的输入在界面有清楚说明，后端也必须拒绝不兼容请求。[官方强度说明](https://docs.novelai.net/en/image/effort/)
- 从 High 切换到 Medium 时，已有负向提示词及不兼容的参数不能静默消失或被伪称生效：界面展示限制并让主人处理；切回 High 后可恢复未提交的草稿。已保存历史不受切换影响。
- 实际强度及有效参数随新生成记录保存，复用和重生成能够恢复；不自动把 High 改为 Medium，也不以本地次数估算 NovelAI 费用。

## 5. 拟议实现边界与数据流

```text
工作台 / 聊天工具 / 经核验的场景 CG / 故事
  → 冻结所选模型、来源、许可、输入和有效参数
  → 按模型版本与模式校验、构造 NovelAI 请求
  → 既有有限次数与 TaskRuntime / 持久账本
  → NovelAI 一次生成请求
  → 校验并保存受管媒体、历史与原来源交付
```

1. 在现有 NovelAI 服务内部维护明确的模型能力和请求转换边界。每个可选模型必须有经证据支持的请求映射；未知模型或未知组合明确拒绝，不能把 V4.5 参数当成 V5 已验证契约。无需为本次功能抽象出跨供应商平台。
2. 设置、工作台、聊天、场景与故事应共用同一模型能力事实和服务端准入；前端展示只辅助输入，服务端是最终权威。故事的旧 V4.5 优先规则须按第 4.1 节兼容处理。
3. 在准入时冻结模型、模式、强度、有效提示词和实际生图参数，作为本次尝试和历史事实。配置修订、角色策略或来源变化仍沿用现有撤销和资格检查；新配置不能赋权给旧工具或在途任务。
4. 图片资产、历史、背景任务、取消、恢复和渠道投递复用既有业务账本和单一结果出口。单次 attempt 最多一次付费生成 POST；超时、断线、取消后不确定的结果保持 unknown，恢复只做已收到结果的本地处理。取消不承诺供应商停止、未扣费或退款。
5. 提示词库可保存与特定模型不兼容的草稿，但预览和发送必须以实际选择模型为准。身份、角色和原渠道不得由模型参数伪造；凭据不出现在工具参数、普通配置响应、历史或日志中。
6. 未提供新字段的旧记录和旧请求有明确定义的兼容行为；不得迁移、覆盖或删除原历史来制造默认值。必要时记录请求版本和真实有效值，避免将之后变动的服务默认值套回旧结果。
7. 透明图片延用受限响应与完整图片校验；不得因支持新模型去掉字节、像素、解压、附件归属或存储预算。

## 6. 验收与测试决定

以用户可观察的工作台/API、角色工具和任务结果为主要测试边界，使用隔离数据、真实服务编排与本地模拟 NovelAI HTTP，不读取正式凭据、不使用正式数据。既有生图、来源和恢复测试作为回归基础；不以仅断言内部函数调用代替完整用户行为。

- **模型与配置：**两个 V5 模型独立选择；V4.5/V5 共存；老配置、旧客户端部分保存、默认模型、NSFW 模式和配置修订不丢失或隐式迁移。覆盖旧界面提交仅含 V4.5 的完整允许列表，确认已允许的 V5 不被静默移除。未知/不允许模型及无效参数在出网前拒绝。
- **真实应用路径：**工作台和角色工具分别走准入、模拟 HTTP、图片导入、历史与原会话投递；覆盖 V5 文生图、获准底图的图生图、多个入口的实际模型，以及故事模式不会被旧 V4.5 偏好覆盖。受限或被撤销的来源不得获得图片或扩大权限。
- **CG** 覆盖辅助模型、真实主人回合、冻结参数、切换模型、场景去重与原来源投递，验证无人值守输入不能获得当前主人生图资格，既有 V4.5 流程继续通过。
- **历史与费用：**分别从 V4.5 和 V5 历史复用、重生成；测试配置变化、失去权限、删除底图、重复请求、断线、取消和结果未知。断言每次尝试最多一个生成请求、已知实际记录不被覆写、不重复投递。
- **多语言与标签：**中/日/英文及混合内容端到端进入模拟请求并返回历史；V4.5 不兼容输入在出网前保留并提示；验证标签预览与实际结果、权重片段、长度边界、控制字符和旧客户端默认模型。
- **Medium：**仅 V5 Full 可选，14 步和采样器限制生效，不支持的负向输入和预设不会静默提交；草稿切换、历史、参数复用和重生成表现一致。
- **输出和界面：**图片完整性、透明通道、角色归属、窄屏工作台、加载/失败/未知状态及模型和实际参数显示可验证。
- 相关后端与前端测试、类型检查、构建及项目要求的仓库规范和需求规格两轴 Code Review 均需通过。真实 NovelAI 账号、图片效果、账单和真实渠道另行验收，不能以模拟服务成功冒充。

## 7. 范围外

- 通用多供应商生图平台、自定义 NovelAI 生产 endpoint、直接复用聊天模型凭据。
- 新增 Vibe Transfer、Precise Reference、局部重绘、独立放大、多角色定位编辑器或完整 NovelAI 官网功能；V5 模型本身支持某能力不代表 Meido 已提供入口。
- 自动升级默认模型、扩大访客或无人值守授权、替用户估算或保证免费、自动重试未知消费。
- 绕过已有角色/来源/存储边界，或在本规格写作阶段访问正式数据、发起付费请求、更新常驻实例、合并 PR 或关闭 Issue。

## 8. 交付顺序

1. **V5 基础体验** 模型选择、V5 文生图/图生图、现有聊天、真实主人回合场景 CG 及故事入口、历史与重生成、旧版本兼容。当前实施对应 [#356](https://github.com/sawaki-zexi/meido/issues/356)。
2. **多语言提示词** 工作台、聊天、角色标签预览和历史对 V5 的一致支持，保留 V4.5 约束。依赖基础体验合入，对应 [#357](https://github.com/sawaki-zexi/meido/issues/357)。
3. **V5 Full Medium** 强度选择、受限参数、草稿和历史重放。依赖多语言阶段合入，对应 [#358](https://github.com/sawaki-zexi/meido/issues/358)。

主人在本规格提交后要求开始实现，沿用以上三阶段拆分。上述阶段共享模型、提示词和工作台模块，顺序完成。前置 PR 合入后，后续工作从最新 main 创建独立分支。

## 9. 待核验事项和发布前决策

1. **V5 API 契约** 基础阶段已核验官方客户端的 Full、Curated 请求路径、版本、提示词扩写、图生图和图片格式，见下文。Medium 的完整映射随第三阶段核验。真实消费验证仍待对应授权。
2. **自动 CG 触发** 初稿增加的供应商单独答复门槛已在实施核验时修正。依据官方 API 的人类操作触发要求，落实第 4.1 节真实主人输入和既有有限消费校验，并以测试验证。
3. **产品与交付确认** 当前已获开始实施授权。合并和真实付费测试分别等待对应授权。
