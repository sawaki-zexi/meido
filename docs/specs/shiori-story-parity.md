# Story 剧情模式对齐

状态：当前；Refs #261。最后核验：2026-10-28。
事实来源：Shiori `d3acaed186b172a78a5892e0307e9affd89759f0` 的 `plugins/story/{backend,ui}`；Meido `backend/app/story`、`web/src/features/story`。

## 用户可完成的流程

- 选择角色 → 故事标题/背景/日期/时段 → 玩家昵称/身份/外观 → 确认创建。
- 使用角色所绑定的现有模型生成开场；每轮最多 3 个 Beat、每段 400 字、合计 1200 字。正式角色台词与场景在场者校验沿用上游。
- 逐段播放、继续故事或输入玩家行动/剧情方向；上游没有预设分支选择树，输入行动即选择。设置控制文字速度、完整显示、自动播放和减弱动画。
- 所有输入、提交文本、日期/时段、场景与资源持久化；存档列表重开、按日期和时段回看剧情记录。归档/恢复不删除原记录。
- 开场背景、普通场景 CG、重要人物 CG 的独立生成与图库；失败可显式重试，CG 可重生成且不改变剧情。
- 角色设定和图片在创建时冻结；保存的故事不是普通聊天，不向聊天写入虚构消息或记忆。

## Meido 集成和消费边界

使用原有角色模型连接和协议适配器，不保存密钥或增加插件框架。图片仍走原有 NovelAI 服务和持久消费账本，单张、landscape、history-only；不开启服务、没有有限手动消费许可或额度不足时不发送生图请求。与上游一样默认生成视觉资源，也可选择纯文字。每个主人触发的故事回合最多一张图片。Story 不增加独立消费授权或长期版本重确认：实际生成遵循当前 NovelAI 设置和既有许可/额度，单次 attempt 固定服务版本以防调度竞态。

同请求 ID 重放不重复图像消费；未知结果保留真实 attempt/status/consumption，不能解释为“未消费”。中断后只从已成功回执恢复本地图片，不自动重复远端生成。图片显示使用 Story 自有副本和受控媒体地址。若主人开启原有 NovelAI 普通生图自动写回，Story 的角色归属生成也遵循该设置；其独立存档副本不随角色库变化。

## 对齐范围说明

上游“存档”是每个 Story 的持久自动保存与重开，不是手动槽位/分支时间旅行。上游没有实际 TTS/BGM 播放接线，Meido 不添加无法工作的音量旋钮。剧情输入、播放、场景背景/人物立绘、记录与 CG 采用 Meido 原生界面；不是复制 Shiori 的主题或插件壳。
