# 聊天过程与输入工具栏

状态：当前（#271 已实现，#277 补充运行中反馈与预算回退）
最后核验：2026-10-30
事实来源：`backend/app/chat_presentation.py`、`session_manager.py`、`web/src/features/chat/`、`web/src/features/role-management/chatPreviews.ts`；上游来源见[研究报告](../research/shiori-chat-presentation.md)。

## 用户结果

- 左侧会话列表显示头像、名称、最近有效消息与时间，替代角色介绍。角色正文直接预览，主人消息加“你：”；图片/文件用对应占位，无历史留空。用户明确澄清：不改变聊天气泡左右位置。
- 聊天顶部身份区仅保留头像、名字，仍能进入资料、多端、记忆和更多操作。
- 角色回复内按 Shiori 组件展示模型实际返回的思考、过程正文与工具调用：思考默认展开，星光图标、细竖线、灰色小字；工具组执行中展开，回合完成后收起。调用行显示图标、名称及单行脱敏参数 chip，逐行点击才展开结果。实时更新和历史重开使用同一回合身份；工具摘要作为纯文本展示，不回显凭据、签名、redacted block 或完整工具对象。
- 回复底部显示实际计时与本回合模型报告的 token 总数，时间戳位于气泡下方。没有统计的旧消息不填造数据。
- 输入区笑脸按钮打开 Unicode Emoji 面板，选择后替换当前选区/插入光标处，保留草稿并由发送按钮提交。支持方向键、Escape 和点击外部关闭；切换角色重新初始化面板和草稿。
- 上下文圆环显示最近一次模型请求的输入 token / 当时配置的窗口容量，点击可查看数值与来源。供应商未回报时使用实际请求的本地估算；没有请求统计或容量时显示未知，不伪造百分比。切换模型后旧模型统计不作为新模型占用。

## 数据与兼容

SQLite 仍是权威 transcript，读取时按 runId 和 toolCallGroupId 生成展示过程，不新增历史数据库或改写旧消息。思考增量通过现有 runtime 事件循环向 SSE 传递；完成事件和 session API 都使用相同公开投影。签名和完整 content blocks 仅继续用于供应商回放。

`GET /api/chat/previews` 只返回每角色最新完成的桌面可见消息摘要，不返回渠道线程、工具过程、失败或生成中的草稿。首次加载及 10 秒/窗口焦点刷新使用该接口，当前会话完成消息立即更新本地列表。此读取不调用模型。

模型 metadata 中 `contextUsage` 记录当次请求的输入量、来源、模型/配置与容量。OpenAI 输入量已包含缓存，不重复相加；Anthropic/Bedrock 分开报告的缓存输入加入总输入。输出 token 不属于输入上下文占用。

## 与上游的明确差异

思考、工具与底部统计组件移植自 Shiori `d149de7`，保留其布局、折叠、动画和 Phosphor 图标，MIT 来源见 `third_party/shiori-agent/README.md`。数据继续沿用 Meido 原生 runtime/SSE。Shiori 将最终思考的耗时放在标题；Meido 统一放在气泡底部，避免把整回合计时误归某个子步骤。计时口径同上游：从回合开始到首段正文返回，无流式正文时计至模型回复完成；token 是本回合各次模型请求的实际输入与输出总量（同次并列工具和自然分条不重复累计），任一步缺少用量则不显示总数。发生空回复重试、自然回复格式纠正或辅助摘要请求时，当前未完整计量，隐藏总数。

上游上下文圆环使用当前请求的 actual/anchor_delta/local 估计；本次沿用 Meido 已有请求估算器，显示“最近一次请求”快照，不声称是包含草稿的实时预算，也不显示累计费用。普通流式模型逐增量展示；自然分条回复透传模型公开思考，正文和输出协议仍须通过校验后提交。失效计划抑制后续公开事件并消费完当前模型步骤；显式取消关闭流，不泄漏草稿或纠正协议。未知工具结果保持未知。工具参数经过凭据、浏览器输入、邮件隐私过滤并限长 120 字符；老数据缺少参数时显示“参数未记录”。

## #277：首段回复前的反馈与工具连续性

发送开始即在头部展示 Shiori 星光动画与“正在输入…”，停止中显示对应状态，终态清理。服务端建立回复占位后，即使尚无正文或思考，仍显示等待光标。关闭流式正文只隐藏正文增量，头部状态、等待光标、公开思考与工具进度仍然可见。此次只显示模型实际返回的公开 reasoning 数据，不生成额外思考文本。

长历史超过硬预算且摘要失败时，最小请求保留当次已授权工具，重新计量包括 schema 的完整请求；装不下则明确失败。工具发现成功后下一请求载入所选声明，真实执行及工具回执继续进入同一回复。`generate_image` 保持 always-on，禁用工具不因发现或回退获得权限。Shiori 固定基线在 minimal 时移除业务工具，因此保留工具是满足本次连续性要求的明确差异，详见 [ADR-0024](../adr/0024-ordinary-chat-budgets-and-durable-windows.md)。

来源与证据见 [2026-10-30 核验](../research/shiori-live-reply-tool-loading-2026-10-30.md)。正式日志只证实摘要 TimeoutError/ValueError 后工具被清空；没有足够证据把 ValueError 归为某个 JSON 错误。通过本地 HTTP 模拟验证长历史回退、发现、执行和最终回复，不据此保证真实服务耗时或所有摘要失败均已消除。

## #277 后续：工具可见性与调用契约

工具分类与调用说明以 Shiori `21e68d99` 为新核验基线，完整已接入工具、risk/external_allowed 和适配清单见[工具核验报告](../research/shiori-tool-exposure-and-guidance-2026-10-30.md)。已通过权限准入时，桌宠、生图、屏幕观察、委托、记忆及共用基础工具常驻；电脑、定时任务、浏览器、账号/群管理、MCP、Herdr 按需。关闭按需开关则全量提供已授权 schema，同时保留核心 tool_search；已加载搜索返回 already_loaded，不增加许可。

实际请求加入有界未加载工具名目录及条件化的搜索、委托、记忆纠错和历史回溯指引。目录与命名空间总计不超过4096 UTF-8字节，每请求更新授权与已加载状态；最小预算请求可省略目录但保留搜索方法。空业务工具/仅 finish_reply 请求不注入某个业务工具存在的指令。已注入技能直接遵循，未载入技能仅在路径可读时读取，不增加文件根权限。

pet_action/task_stop/spawn_manage/herdr_cancel_task 按上游标记外部副作用；保留本地 spawn 更保守的 external 和仅桌面 message_push 的 mutating 差异。generate_image 的 external_allowed 声明不取代原来源和 owner/服务准入。所有现有冻结授权、请求绑定、搜索后下一请求加载和及时撤权行为沿用 ADR-0026；不注册未实现的上游业务工具，也不引入通用进度 description 参数协议。

## 验证边界

沿用已有聊天 HTTP/SSE 和 React 用户操作边界：历史投影、签名与 redacted 内容过滤、实时思考/工具、回复终态、停止/角色切换、最近消息、Emoji 插入发送、上下文来源。另做隔离数据桌面/窄屏浏览器检查、TypeScript 和网页/桌宠/落地页构建。全部验证使用合成数据，不调用真实模型、渠道或付费服务；不修改常驻实例。
