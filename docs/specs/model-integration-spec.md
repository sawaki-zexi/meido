# Meido 模型接入架构方案

状态：草案

本文描述第一版模型配置与模型调用的产品边界和架构约束。它补充
[`mvp-technical-spec.md`](mvp-technical-spec.md)，不替代角色、会话和消息的
MVP 规则。

## 1. 目标

用户可以在本地网页完成以下闭环：

```text
打开模型设置
  -> 添加一个或多个服务商/模型连接
  -> 用当前表单内容测试流式连接
  -> 点击“保存”
  -> 在角色会话中选择当前角色使用的模型
  -> 后续对话使用该角色的模型
```

模型连接配置是本地服务的全局可用模型目录。每个角色可以从已保存的模型连接
中选择自己的对话模型。

## 2. 范围

### 2.1 服务商预设

第一版提供 Shiori 当前模型配置中已有的服务商预设：

- OpenAI
- DeepSeek
- 阿里云百炼
- Moonshot
- 智谱
- 硅基流动
- OpenRouter
- Ollama

预设是界面和配置层的模板，至少可以提供服务商名称、默认 endpoint（如果
适用）、认证方式提示和常用模型输入方式。预设不代表系统自动支持该服务商
所有原生 API；具体请求必须由对应的模型适配器处理。

### 2.2 自定义服务商

用户可以添加自定义服务商，填写：

- OpenAI Chat Completions 兼容的 endpoint
- API Key（本地服务需要认证时）
- model ID

自定义服务商只承诺兼容 OpenAI Chat Completions 的流式聊天请求。其他协议需
在未来增加专用适配器。

### 2.3 连接测试

连接测试使用当前表单草稿，不要求先保存。测试请求应走实际对话使用的流式
请求路径，并使用短小的测试输入，返回明确的成功或失败结果。

测试连接不会保存配置，也不会改变当前正在生效的配置。即使测试成功，用户
仍需点击“保存”。

### 2.4 保存模型连接

- 表单存在明确的“保存”按钮。
- 只有保存成功后，模型连接才进入全局可用模型目录。
- 未保存的修改不会影响模型目录或后续对话。
- 刷新网页或重启本地服务后，已保存配置仍可恢复。
- 保存失败时，当前可用模型目录保持不变，并显示错误。

### 2.5 会话内切换角色模型

- 会话页面展示当前角色已绑定的对话模型。
- 用户可以从已保存的模型连接中选择另一个模型。
- 切换通过后端更新该角色的模型绑定，并在成功后立即用于后续新消息。
- 一个角色的模型切换不改变其他角色的模型绑定。
- 切换不会创建新会话，也不会修改历史消息。
- 已经开始生成的回复继续使用生成开始时捕获的模型配置。
- 当前角色没有可用模型时，界面应允许用户进入模型设置或选择模型。

## 3. 总体架构

```text
网页模型设置页
  | 读取/编辑模型连接草稿、测试连接、保存
  v
本地后端配置服务
  |-- 连接校验与持久化
  |-- Provider Registry：预设和模型连接目录
  |-- Model Adapter：统一流式调用边界
  v
已保存的模型连接目录
  v
角色模型绑定 <- 会话模型选择菜单
  v
对话服务 -> Prompt 编译 -> 角色绑定的 Model Adapter -> 服务商 API
```

网页只维护编辑中的草稿和展示状态。后端是配置和生效状态的权威来源，模型
调用不能直接读取前端状态。

## 4. 核心概念

### 4.1 Provider Preset

服务商预设是静态元数据，不是用户凭据。它用于初始化表单并选择适配器，例如
服务商显示名称、连接方式和默认地址。

预设应有稳定的内部标识，显示名称可以在界面调整。新增预设不应改变已经
保存的配置含义。

### 4.2 Model Registration

全局模型目录中的一个模型连接至少表达以下信息：

```text
ModelRegistration
  id: 稳定的连接 ID
  provider_type: preset | custom
  provider_id: 预设 ID 或 custom
  endpoint: 可选或必填，取决于服务商
  api_key: 可选或必填，取决于服务商
  model_id: 必填
```

实际字段名和存储格式仍由实现计划确定。角色只保存所选连接的稳定 ID，不直接
持有服务商密钥。

### 4.3 Draft Configuration

草稿是网页表单当前内容。草稿可以用于连接测试，但不是生效配置，也不应在
测试失败时覆盖已保存配置。

### 4.4 Active Registration Catalog

生效模型目录是后端最近一次成功保存的完整模型连接列表。每次模型调用开始时，
后端根据角色绑定的连接 ID 读取一份连接快照；调用过程中保存新连接或切换角色
模型，不改变已经开始的请求。

### 4.5 Role Model Binding

角色模型绑定属于角色运行时配置，至少包含当前对话模型的模型连接 ID。会话中
选择模型时更新该绑定；绑定变化不改变角色 ID、唯一会话或消息历史。

## 5. 模块边界

### 5.1 网页前端

负责：

- 展示预设和自定义服务商选项
- 管理一个或多个模型连接
- 编辑 endpoint、API Key、model ID 等表单字段
- 区分草稿值和已保存值
- 发起连接测试和保存操作
- 展示测试、保存和模型调用错误
- 对 API Key 做遮蔽显示

不负责：

- 生成或校验最终生效配置
- 直接请求第三方模型服务
- 保存 API Key 的权威副本
- 决定对话实际使用哪个模型连接

会话页面还负责展示当前角色模型和发起角色模型切换；切换结果由后端持久化。

### 5.2 本地后端配置服务

负责：

- 返回已保存模型连接目录和可用预设
- 校验模型连接完整性和字段格式
- 使用草稿执行连接测试
- 保存模型连接目录并替换当前生效目录
- 更新角色的模型连接绑定
- 在刷新和重启后恢复模型目录和角色绑定
- 向模型适配层提供角色模型快照

### 5.3 Provider Registry

负责维护预设元数据和预设到适配器的映射。它不保存用户 API Key，也不负责
模型连接目录的用户数据、会话历史或角色资料。

### 5.4 Model Adapter

负责把统一的聊天调用转换为服务商请求，并把服务商响应转换为统一的流式
事件。对话服务只依赖适配器边界，不直接依赖具体服务商 SDK。

统一调用至少需要支持：

- 输入消息列表
- 模型 ID
- 流式响应
- 增量文本
- 完成
- 请求失败
- 流式中断

## 6. 关键流程

### 6.1 加载设置页

1. 前端请求可用预设和当前已保存配置。
2. 后端返回预设元数据及脱敏后的当前配置。
3. 前端以当前配置初始化草稿。

### 6.2 测试连接

1. 用户修改草稿并点击“测试连接”。
2. 前端提交草稿到后端的测试入口。
3. 后端校验草稿，创建临时适配器和请求配置。
4. 适配器发送短小的流式聊天请求。
5. 后端消费并关闭测试流，返回成功或可读的失败原因。
6. 后端不写入生效配置。

### 6.3 保存模型连接

1. 用户点击“保存”。
2. 后端重新校验完整的模型连接目录。
3. 后端持久化目录并原子替换当前生效目录。
4. 后端返回脱敏后的最新目录。
5. 前端用服务端返回值更新已保存状态，清除草稿差异。

### 6.4 会话内切换模型

1. 会话页面读取模型连接目录和当前角色绑定。
2. 用户选择一个已保存的模型连接。
3. 后端校验连接仍存在，并更新角色的模型绑定。
4. 前端刷新当前角色模型显示；后续消息使用新绑定。

### 6.5 对话调用

1. 对话服务读取角色当前模型绑定和对应的目录项快照。
2. 对话服务编译角色设定和会话历史。
3. 对话服务调用 Model Adapter。
4. 适配器把增量文本转换为 MVP 已定义的流式事件。
5. 模型连接或角色绑定在生成过程中被保存时，本次生成继续使用开始时的快照。

## 7. 错误规则

- 配置字段不完整或格式非法时，不发送第三方请求。
- 测试失败只影响测试结果，不改变当前模型目录或角色绑定。
- 保存失败时，当前模型目录和可用对话能力保持不变。
- 角色模型切换失败时，角色继续使用原绑定。
- 对话请求失败或流式中断时，遵循 MVP 的 `assistant_failed` 规则。
- API Key 不出现在前端日志、模型请求错误文本或普通运行日志中。
- 错误信息可以帮助用户修复 endpoint、认证或 model ID，但不得泄露密钥。

## 8. 持久化与安全边界

第一版使用本地后端持久化模型连接目录和角色模型绑定。具体存储引擎沿用 MVP
的存储决策，本文不指定 JSON、SQLite 或其他实现。

需要满足以下约束：

- API Key 只由本地后端读取并注入模型请求。
- 前端读取配置时返回脱敏值或“已设置”状态，不返回完整密钥。
- 日志不记录完整 API Key、认证请求头或包含密钥的 URL。
- 模型目录更新或角色绑定更新成功后，后续新请求使用新配置；已开始的请求使用旧快照。
- 删除或替换配置时，不影响角色、会话和消息数据。

本地服务的访问控制、密钥加密方式和备份策略仍属于 MVP 的通用安全决策，
需要在实现前单独确认。

## 9. 明确不包含

- 同一会话自动切换或故障转移到其他服务商
- Pi 式多种原生协议、OAuth 和广泛的模型能力目录
- 模型自动发现、自动推荐和价格管理
- 多用户账户、云端同步和远程配置
- 模型配置版本比较、回滚和审计界面

## 10. 已确认的架构决定

| 决定 | 选择 | 影响 |
| --- | --- | --- |
| 配置入口 | 本地网页 | 需要本地后端提供配置读取、测试和保存能力 |
| 接入范围 | Shiori 的预设范围 + 自定义 OpenAI Chat Completions 兼容服务 | 需要 Provider Registry 和统一适配器边界 |
| 流式方式 | 测试和实际对话都验证流式请求 | 适配器和测试入口都要处理增量、完成和中断 |
| 保存交互 | 显式点击“保存”后生效 | 前端必须区分草稿与生效配置 |
| 测试语义 | 使用未保存草稿，测试成功仍需保存 | 测试请求不能写入配置存储 |
| 配置粒度 | 全局模型连接目录 + 角色级对话模型绑定 | 连接统一管理，角色可在会话中切换 |

## 11. 尚未确定的实现选项

以下内容没有在产品讨论中拍板，开发前应由实现计划确认：

1. 配置和角色模型绑定接口使用现有 HTTP API 的具体路径和请求结构。
2. 本地网页和后端之间采用的流式测试传输方式。
3. 配置存储的具体引擎、文件位置和迁移方式。
4. 每个 Shiori 预设使用统一兼容适配器还是拆分专用适配器。
5. endpoint 的默认值、路径拼接和尾部斜杠规范化规则。
6. API Key 的本地加密方案和进程权限边界。
7. Ollama 等本地服务是否允许无 API Key 配置。
8. 服务商预设是否允许用户覆盖默认 endpoint。

## 12. 验收场景

### 场景一：预设配置

用户选择一个服务商预设，填写模型和认证信息，测试流式连接成功，点击保存，
刷新设置页后连接仍存在；在角色会话中选择该连接后可用于对话。

### 场景二：自定义兼容服务

用户填写兼容 endpoint、API Key 和 model ID，使用当前草稿测试成功，保存后，
在角色会话中选择该连接并得到流式回复。

### 场景三：测试不保存

用户修改已保存连接后测试失败或成功，但不点击保存；刷新设置页和发送对话时，
仍使用原来的模型目录和角色绑定。

### 场景四：保存失败

保存非法或不可持久化的模型目录时，界面显示错误，原模型目录仍可用于对话。

### 场景五：生成期间改配置

对话开始生成后保存新连接或切换角色模型；当前回复继续使用旧配置，下一条新消息
使用新配置。

### 场景六：角色之间的模型隔离

角色 A 在会话中切换到模型连接 B，角色 B 的绑定保持不变；刷新页面后角色 A
仍显示模型连接 B，且两者继续使用各自的绑定。
