# Inbox Zero 与 Meido 邮件能力对照矩阵

状态：当前；用于继续实施和验收时的差距清单。

最后核验：2026-10-24（Asia/Shanghai）。

事实来源：Inbox Zero 固定提交 `aea0ec2db43a1147b90776d9bbf3f467afc0af26` 的邮件源码与测试；Meido 当前分支源码、邮件规格、ADR-0008、邮件 Python/网页回归。Inbox Zero 的完整产品范围大于 #201，本表把“已复刻”“有边界地复刻”和“明确不复刻”分开，避免把产品差异误报成遗漏。

| Inbox Zero 能力 | Meido 当前状态 | 结论与下一步 |
| --- | --- | --- |
| 当前线程上下文、主题、收件人和正文 | 已实现；当前来信只注入一次，历史按时间排序并有字符上限 | 保持；真实模型评估继续检查截断和引用清理 |
| 同对象已发送回复样本 | 已实现；按实际收件方向读取，最多 24 封检索、最多 3 封注入 | 保持有界读取；真实 QQ 验证早于扩展搜索代理 |
| 主人资料和写作风格 | 已实现；资料来源、位置、安全链接、失败和截断信息持久化 | 保持主人级显式偏好，不自动从临时草稿学习长期风格 |
| `no_reply / needs_input / draft` | 已实现；`needs_input` 固定绑定问题、线程指纹、账号代次和请求 ID | 保持 Meido 的主人决定边界，不照搬低置信度猜测答案 |
| 生成归因和上下文元数据 | 已实现；模型、配置、流水线版本、Prompt hash、字符量、来源和 warnings | 真实模型评估补充人工抽检和可选语义 judge |
| 线程状态、问题、承诺和截止时间 | 已实现；`signals-v3`、逐事项问题/承诺、兑现事件、行动筛选 | 用真实线程样本继续校准歧义和跨语言表达 |
| 到期跟进提醒 | 已实现；默认关闭、批次/线程提醒持久化、原子认领、重启恢复 | 真实 QQ 长期运行验证提醒失败和重启 |
| 到期催复草稿 | 已实现但默认关闭；只写 QQ 草稿箱，不自动发送 | 等真实模型和 QQ 验收通过后再考虑默认策略 |
| 草稿版本、人工修改保护、未知 APPEND 对账 | 已实现；marker、回读、退避、账号代次和版本确认 | 保持“未知不重写、不删除”边界 |
| Sent 发送副本关联 | 已实现；`pending/matched/ambiguous/unknown`，支持尾部重扫 | 真实 QQ 验证网页手动发送和副本延迟 |
| 邮件搜索和线程行动视图 | 已实现；当前账号本地已同步内容搜索，线程状态/动作/待核实筛选 | 不把本地搜索误称为远端全量搜索 |
| Gmail/Outlook 多供应商 | 未实现 | 当前 QQ SSL IMAP 范围明确排除；另立需求再设计 provider 适配层 |
| 发送、删除、归档、移动、标签和规则自动化 | 未实现 | ADR-0008 明确禁止/排除；不复制 Inbox Zero 的外部写操作 |
| 附件复制、附件事实注入和富文本编辑器 | 未实现 | 当前规格明确不解析附件；先完成真实模型/QQ 验收 |
| 日历、会议、Booking link、外部工具上下文 | 未实现 | 不在 #201；避免把外部时间或承诺自动写进邮件 |
| 多步历史搜索代理、离线本地邮件客户端 | 未实现 | 先用评估证明一次有界检索不足，再单独立项，避免扩大成本和恢复面 |

当前真正的完成门槛只有两项：在专用测试账号上运行受控 QQ 长期验收，以及在明确授权后运行真实模型质量评估。合成测试、固定回放和源码对照不能替代这两项证据。
