## 数据流与责任

```text
原文会话 / 来源身份
  ├─ 已保存工作摘要 + 切点 ─┐
  ├─ 会话维护游标           │
  │    ├─ 宿主 Markdown    │
  │    └─ 独立消费者进度    │
  └─ 当前原文工具窗口       │
                           ↓
稳定 system → 历史/工作摘要 → 动态 frame → 当前输入/本轮工具交换
                           ↓
           实际请求规范化与用量测量（只读）
             ├─ 未达阈值：直接请求模型
             └─ 达阈值/手动：冻结合法前缀
                    → 必需记忆覆盖 → 分批工作摘要
                    → 验证仍有效 → 发布摘要和切点
```

宿主文档、语义引擎、周期优化各有工作和恢复进度。语义检索只完成本次查询，不补建历史向量。下游消费者成功与否不替代“原文已被记忆覆盖”的事实。模型 KV 缓存仍由供应商负责；本地负责稳定输入前缀与可靠用量锚点，不增加本地 KV 服务。

## 同一分支内的实施顺序

以下是内部里程碑，**不是六张 Ticket，也不分别提交 PR**。每步用外部行为验证后再推进，共享模块顺序修改。

### 1. 固定契约、迁移基础与会话维护责任

- 将本规格和研究归入 `docs/specs/`、`docs/research/`；新增 ADR 明确替代 ADR-0002、ADR-0024 和后续相关决定中的冲突部分，保留历史说明。
- 对照会话存储、`memory_maintenance.py`、`context_windows` 现有责任，建立会话维护进度和消费者恢复的唯一读写边界；替换全历史相等验证为上游冻结前缀与实际身份/版本验证。
- 先建立旧进度、合法窗口、待处理事件及 Markdown 迁移夹具；验证合法尾部追加与真实失效行为。
- 不额外创建平行权威库。原有物理会话/渠道表可作为适配，稳定 ID 和权限关系保持可追溯。

### 2. 读路径与请求排列

- 调整 `main.py` 的普通回合入口、角色记忆读取及 Provider 请求构建；稳定文档入 system，历史在动态 frame 之前。
- 删除读文档时刷新近期语境、查询时等待缺失向量回填等写入行为；不在每个回复前按自有条数同步整理。
- 普通积压使用上游后台触发与已知失败语义；工作窗口、工具恢复、独立检查和发送使用同一真实输入。
- 验证短对话无摘要、无读时写入，长稳定前缀不会因新的时间信息整体改变；缓存命中计数不降低容量估算。

### 3. 阈值压缩、失败与消费者恢复

- 在 `context_provider.py` 和维护边界实现记忆覆盖先于工作摘要，复用已有分批与合法缩短协议；单次发布摘要和切点。
- 恢复消费者时不重复提取已覆盖原文或重发已确认事件。编辑/撤销等正确失效；前缀外追加不无故取消提交。
- 对齐软失败、硬失败、真实供应商溢出及上游允许的 minimal 路径。minimal 不再携带业务工具；保留必要回复协议和完整当前输入/既有工具回执。
- 取消/重启行为与既有后端任务所有权一致。不得用重复执行工具来恢复请求。

### 4. 文档、语义引擎与周期优化

- 解开 `memory_service.py`、`memory_documents.py`、`memory_optimizer.py` 的强同步与长锁关系；采用上游文档结构、来源标记、PENDING snapshot 及恢复行为。
- 默认语义引擎有独立 embedding 配置和指纹；显式写入 embedding-first。正常读取不自动重建旧空间，缺失配置/不匹配按上游可用性处理。
- 按固定源码对齐意图分流、HyDE、RRF、阈值、注入配额和预算、热度及 procedure guard，使用当前配置值而不是历史近似默认值。
- 记忆工具说明、常驻条件和实际执行能力同源。设置页将“引擎可用性”与宿主文档维护说明一致呈现，不增加调试面板。

### 5. 所有消费者及 Shiori 手动入口

- 对齐桌面、主人私聊、外部会话、旁听、主动/Drift、子代理的上下文和记忆范围，沿用当前注册表工具执行与原文窗口恢复。
- `channels/consolidation.py` 已有 50 条旁听批次和 30 分钟扫查；复用这些行为，检查与修正来源、非旁听保留窗口、开关和文档/引擎分工，而非重建同类 worker。
- 独立检查、圆环点击压缩和 `/compact` 共用控制器；上游圆环容量填充、未知/忙碌显示、简短浮层和点击行为保持一致。草稿不提交，命令不伪装为普通聊天回合。
- 已有切页/刷新恢复与显式停止继续工作；不引入第二套过程展示。

### 6. 组合验收、简化与交付

- 删除已迁移的旧正常写路径、重复预算/维护组装与无调用者的兼容逻辑；兼容代码仅保留在导入/恢复边界。
- 完成下面的真实浏览器验收与迁移恢复测试，记录阶段耗时和请求/事件证据；修正受影响文档。
- 运行必要检查、CI 和独立规范/规格审查，解决阻塞问题，再提交一个面向 main 的 PR。合并、部署和关闭 Issue 不含在实施批准中。

## 迁移与回滚

| 旧状态 | 处理与验收 |
| --- | --- |
| 原始消息、来源 ID、账号/角色/线程绑定 | 不重写成新来源；迁移前后数量、内容与授权视图对照 |
| 合法工作摘要和窗口切点 | 证明来源/版本有效时保留；旧过期派生结果归档，不假称已经覆盖 |
| 分散维护游标和 pending event | 导入会话维护所有者及独立消费者进度；中断后重跑不得重复已确认消费 |
| SELF/MEMORY 手工内容及旧托管块 | 备份原文；托管块内容转为普通文档保留，不继续由语义库整体投影；未知结构不猜测主人/外部可见语义 |
| PENDING、snapshot、HISTORY 和来源标记 | 按来源恢复，验证中断/重启与新增候选并存，不覆盖新候选 |
| 结构化记录和旧向量 | 保留数据；可验证的空间指纹迁入；无法证明匹配时明确不可用，不自动删除、重建或调用真实 embedding |
| 旧共享 embedding 和记忆开关 | 复制已配置值到引擎独立配置，主人资料配置保留；保留显式开关意愿。宿主文档独立维护的行为变化在界面和迁移说明中明确 |

迁移在独立测试数据执行，采用可重入的版本标记和迁移前备份；不在本轮开发期间操作正式数据。运行手册给出停止独立实例、恢复同一版本代码及匹配数据备份、校验后再启动的完整回滚步骤。不能让旧代码读到仅部分更新的数据后继续双轨写入。

## 验收矩阵

| 场景 | 外部可观察证据 |
| --- | --- |
| 阈值以下多轮普通聊天 | 无工作摘要请求；只读检查不写记忆；窗口和工具 schema 正确；真实首输出可见 |
| 首次越阈值与下一轮 | 覆盖事件早于工作摘要，提交后下一轮复用；请求携带合法摘要和保留原文 |
| 重启与手动压缩 | 已提交切点继续生效；圆环和 `/compact` 使用同一结果；草稿、原文和消息数量不被误改 |
| 合法追加/编辑/撤销/解绑 | 仅不影响冻结前缀的追加可提交；真正变化阻止旧结果，原文和权限不被绕过 |
| 摘要、消费及模型故障 | 软/硬行为符合上游；已覆盖结果不重提取；成功事件不重发；原文和旧窗口保留 |
| 工具跨阈值与供应商溢出 | 执行回执保留；业务副作用次数正确；minimal 工具范围一致 |
| 慢 embedding/检索、整理和优化并行 | 无读时回填；等待期间设置/插件页面与明确停止可响应；各阶段耗时独立记录 |
| 引擎关闭/不匹配 | 不宣称显式记忆写成功；文档层独立可用；配置不自动借用或破坏旧空间 |
| 多角色、主人/外部、旁听与子代理 | 来源隔离正确；各自历史、游标和用量不会混入主人普通回复 |
| 迁移中断、重跑与回滚 | 原文/手工内容保留，pending 恢复不重复；不存在持续双写 |

最高验收使用真实浏览器、实际 HTTP/SSE 与真实存储，加本地受控聊天和 embedding 服务；**记忆路径开启**。原 #301 的关闭记忆场景只作为已有回归，不能替代本轮验收。供应商限额、付费模型速度与实际 KV 命中率不由本地受控服务证明；记录其模拟指标与真实能力边界，不把缓存命中承诺为性能保证。

针对关键新行为先红后绿；复用现有上下文、记忆、渠道、模型协议与浏览器夹具，不测试私有结构的复制品。实现结束后按仓库约定完成相关测试、类型检查、构建、CI 与两轴独立审查。

## 已明确的取舍与风险

- “全部对齐”包含真实行为改变：硬压缩失败不再被统一吞掉；允许的 minimal 不带业务工具；关闭语义引擎仍有宿主文档维护；结构化记忆管理不再强制重投影文档。均以固定 Shiori 为准，不自行添加替代策略。
- 文档维护、摘要和 HyDE 仍可能调用模型。架构移除无关同步等待，不承诺外部模型无等待，也不以跳过应有记忆处理换取速度。
- 老数据缺少足够来源或指纹时只能保留并明确其状态，不能自动构造可信来源。兼容迁移是必要适配，不能演变为长期第二套语义。
- 真实付费/渠道验收、部署、数据迁移到正式实例，以及 PR 合并/Issue 关闭需要另行授权；本轮不触碰正式实例。
