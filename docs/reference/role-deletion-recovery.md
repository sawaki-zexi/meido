# 角色删除恢复契约

角色删除是一个跨角色清单、角色目录、会话 SQLite 和记忆 SQLite 的受控流程。删除开始时先建立角色级删除闸门，并写入 `roles/.deleting-<role_id>-<token>.json`。闸门会拒绝新的回合事件、Optimizer 任务、记忆管理写入和角色文件写入，同时等待已运行的角色级任务结束。

正常流程按以下顺序提交：

1. 暂存角色目录到 `.deleted-<role_id>-<token>`。
2. 从角色清单移除角色。
3. 删除该角色的会话记录和结构化记忆表记录。
4. 清理暂存目录。
5. 删除 `.deleting-*` 标记。

`memory_items`、embedding、embedding 空间、`consolidation_events` 和 `memory_replacements` 都按 `role_id` 删除。其他角色的数据不参与快照、删除或恢复。

如果流程在进程内失败，服务会使用会话/记忆快照、角色清单和暂存目录恢复原角色；删除闸门随后解除。若进程在流程中途退出，启动时按标记和角色清单判断：角色仍在清单中则恢复暂存目录并清除未完成标记；角色已从清单移除则清理残留角色目录和暂存目录，并以幂等方式删除会话和记忆 SQLite 数据。暂存目录或标记清理失败会保留标记，下一次启动继续重试。

维护和 Optimizer 的启动恢复只处理当前角色清单中的目录。删除成功后，角色不再被事件恢复、近期上下文维护或 Optimizer 重新创建；同一进程中已删除的 `role_id` 也会被 worker tombstone 拒绝后续事件。
