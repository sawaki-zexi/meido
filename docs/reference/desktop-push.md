# 普通对话桌面推送

状态：#167 实现，待总 PR #162 集成与合入。事实来源：[工具](../../backend/app/desktop_push.py)、[原子消息存储](../../backend/app/session_store.py)、[来源测试](../../tests/python/test_desktop_push_authority.py)和[公开 HTTP 测试](../../tests/python/test_desktop_push_api.py)。

`message_push` 是默认提供的基础工具，独立于渠道账号。新旧角色无需勾选桌面推送；仍只允许真实主人来源向当前角色桌面对话投递。构造及目录预览不创建渠道 push 表、不改变提醒账本、不启动外发服务。

参数 `channel` 只接受 `desktop`，`chat_id` 只接受当前角色自己的 `owner`/`user`。`message` 最多 4000 字符，可为空；`image`、`file`、`attachments` 使用当前角色已保存的 32 位媒体 ID。保留既有协议的单个 `attachments` 数组最多四项，合并 `image`/`file` 并去重后也最多四项；文本和媒体至少一项。每个声明的媒体类型都须匹配，全部附件有效才写一条消息；链接重定向的附件目录拒绝，不读取模型给定的宿主路径。

来源以实际角色、原 run、持久 user 入站、宿主线程/账号和 FrozenChannelSource 为准。主人桌面及有效配对主人来源可写当前角色桌面；访客、伪造身份、不同角色/会话、终态或无入站 run 拒绝。解绑、账号重建、平台暂停、角色删除和取消继续实时校验，不凭参数选目标。

SQLite `BEGIN IMMEDIATE` 取得写锁后重新解析并比对媒体，随后最终校验来源和取消，再一次提交。角色/run/call 共同生成稳定消息 ID，重放及重启不会重复追加。等待写锁或复核媒体期间撤权或取消不产生晚写；重复取消仍等待实际写线程结束。提交完成后消息独立于父 run，后续父失败或停止不会撤回已投事实。

事务内最终授权门禁是提交的线性化点。取消或撤权先赢门禁则不写；门禁先赢时该同步提交已获准，之后的 Stop 仍等待实际写线程退出再返回，不能承诺撤回已进入提交的消息。门禁之后没有附件读取、模型请求或其他异步等待。

成功回执为 `status=sent` 与已持久化 `messageId`。消息为 assistant/`desktop_push`，没有新主人输入、正常 run 或记忆/待办维护；原 run/call 仅作来源元数据。公开会话只含安全附件元数据，图片和文件沿用当前角色附件端点及已有焦点/10 秒刷新；媒体可以没有正文。后续模型历史只保留正文和安全附件名称/ID，不加载附件字节或宿主路径。

独立消息可以在工具执行中先于工具结果写入。数据库保持实际顺序；重建模型历史时，先按原 run/call 配对完整工具调用与结果组，再插入组内的独立消息。下一主人回合和重启重放保留真实成功回执，不将其误修复为中断，也不让独立消息拆开模型要求连续的工具结果组。

对外发送使用 `account_send`。现有显式选择的待办 `ChannelPushService.deliver_reminder` 仍沿用原账本与 uncertain 不重试规则。此工具不承担主动决策草稿、Drift 单次发送或通用调度授权；这些运行须按各自协议接入内部交付，不能伪造活跃主人 run 调用普通工具。
