# 分批工作摘要

状态：当前。最后核验：2026-10-30。
事实来源：[分批选择与来源投影](../../backend/app/agent_runtime/summary_batches.py)、[压缩事务入口](../../backend/app/agent_runtime/context_provider.py)、[行为验收](../../tests/python/test_batched_summary.py)。需求：[Ticket #283](https://github.com/sawaki-zexi/meido/issues/283)、[Spec #279](https://github.com/sawaki-zexi/meido/issues/279)。

## 输入与批次

现有完整轮选择先确定本次应移出的原文。固定 Shiori `71c8b0e460530683cd28aad6bb62e873c7167c89` 的 `core/compaction_summary{,_sources,_request}.py` 提供批次语义：先尝试全部剩余原文，装不下时二分选择当前辅助输入预算内最长的连续前缀。每次把上一批已验证摘要作为工作状态重新计量，再处理下一批，直到覆盖全部选定原文。

输入只含文本、附件名称与媒体类型、工具调用和结果及原来源 ID，不序列化图片 Base64 或完整模型元数据。工具结果先按上游 10000 字符规则保留首尾；单条仍放不下时，对其中的长字符串从 10000 字符预算逐次减半，保留首尾、截断数量和行数说明。来源 ID 与工具调用 ID 保持原样。循环下限是 200，实际依次尝试 10000、5000、2500、1250、625、312，不尝试 156；固定字段和最低可用文本仍放不下时明确报告压缩失败，不跳过该条原文。

每批复用六字符串字段及 `source_message_ids`、合法来源校验、供应商结构化输出选项和输出长度规则。合法来源集合是本次移出原文的全部 ID 与旧合法摘要来源的并集，因此后续批次可以继续引用前批状态。只有结构合法但超长的结果可以缩短一次；缩短也是真实请求。摘要提示要求保留仍有效的较早任务与结果，不能只摘要最新一批。

## 提交与失败

批次状态只保存在当前调用内存中。所有批次成功、最终正文输入可容纳且减少占用后，等待既有记忆覆盖；等待结束再次按当前原文窗口和当前工具声明计量，再由原有事务核对来源权限、原文指纹、窗口版本和覆盖证明，一次提交摘要及水位。没有中间摘要表或持久化批次流水，原始历史不删除。

后批异常、非法来源、停止、请求步数用尽、覆盖不足或最终预算失败都不提交半成品。软阈值失败且原请求仍可容纳时继续使用原文；硬预算回退沿用 #278，保留旧合法摘要、当前输入及工具结果，并计量当前合法工具。必需内容与声明仍放不下才终止普通请求。摘要不会恢复已被移出原文窗口的工具，压缩候选与正文使用相同窗口选择规则。

## 计量与验证

预检和发送共用实际适配器的纯 `prepare_input`、输出预留及 JSON 选项。每次摘要计量只用 local，不写普通对话的 actual/anchor_delta 锚点；压缩后普通请求按新历史与声明重新计量，再由其自身响应更新锚点。没有锚点也可完成分批。

每次批次生成及缩短调用均消耗现有 `maxIterations` 请求步数，并记录独立实际 usage、结束原因与耗时；继续保留正文请求所需的一个请求名额。每次辅助请求沿用 90 秒期限和取消检查，正文沿用自己的期限。多批可能增加调用数与总等待时间，不保证更快，不增加无限重试。

受控 HTTP 验证覆盖单批/多批、最长前缀及来源顺序、旧摘要续写、文本/附件/工具结果收缩、最低输入失败、后批错误/非法来源/取消/步数耗尽、每批一次缩短、软硬失败、提交前工具变化、授权/原文/版本/覆盖门槛、工具窗口回收及普通锚点隔离。已有共享主人历史与真实 loopback HTTP 工具续接回归继续适用；这些测试不调用付费模型或真实渠道账号。
