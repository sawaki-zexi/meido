# 成员昵称与档案查询

状态：当前（#165 实现，待汇入总 PR #162）。最后核验：2026-10-16。

事实来源：[工具与查询](../../backend/app/channels/group_tools.py)、[昵称观察和旧库迁移](../../backend/app/multichannel.py)、[可信来源](../../backend/app/channels/source_authority.py)、[公开 HTTP 往返](../../tests/python/test_member_lookup_api.py)、[范围与持久化测试](../../tests/python/channels/test_member_lookup.py)。对应完整规格 C09，保留 Meido 名称 `lookup_group_member`，映射 Shiori 的 `lookup_member`。

| 参数 | 行为 |
| --- | --- |
| `name` | 当前或历史昵称的一部分，忽略大小写。与 `member_id` 必须且只能给一个。返回准确 `total` 及最多 10 个候选；候选含 `channel/member_id/name/nicknames`。 |
| `member_id` | 来源中的发送者 ID；必须同时给出 `member_channel`。返回 `found` 和保存的结构化档案来源，不返回原始聊天。 |
| `member_channel` | 名字查询可省略以查所有获准渠道；按 ID 读取时必填。外部受限回合不能借此扩大到其他渠道或线程。 |
| `source_page` | 按 ID 读取时的来源页，默认 1，每页最多 5 个线程来源；返回 `sources_total/next_source_page`。名字查询不能混用。 |

例如先调用 `{"name":"Alice"}`，取得候选的渠道和 ID，再调用 `{"member_id":"22","member_channel":"qq"}`。需要继续读档案来源时传下一 `source_page`。昵称不存在返回空候选；已观察到人但尚无整理档案时可有空的 profile/shorthand，不捏造事实。

有可用渠道账号或已保存成员资料时自动提供此工具；空白新角色不因此获得无用的工具。目录说明其依赖为本地读取，账号暂停后仍可查询已有资料。

| 实际运行来源 | 可读范围 |
| --- | --- |
| 主人桌面 | 当前角色保存的各渠道成员资料；账号离线或暂停不阻止本地历史资料读取 |
| 仍有效配对的主人私聊 | 当前角色保存的各渠道结构化资料；每次调用重新验证原绑定和来源代际 |
| 群聊，包括主人在群中的回合 | 当前群线程已观察成员和该线程档案 |
| 访客私聊 | 当前私聊线程已观察成员和该线程档案 |

固定 Shiori 的外部查询范围是整个当前渠道；Meido 沿用 ADR0009 的当前线程边界。模型参数不能声明角色或主人身份，工具从实际入站 run、线程、发送者及绑定取得不可变来源；平台停用、屏蔽、范围关闭、解绑重绑或同 ID 账号重建都会撤销旧来源。消息早于账号创建代际时，首次捕获来源也拒绝。读取后再复核许可，失效时不返回结果。

昵称来自宿主接受的入站 senderName 或实际联系人目录，按角色/渠道/成员 ID 找候选；模型生成的 profile.name 不加入昵称沿革。同一成员在不同线程的 profile/shorthand 保留各自 thread/account/chat 来源，不把矛盾描述拼成一个档案。ID 读取的来源按来源键稳定分页。

NapCat 在真实入站和成功取得成员目录记录时标记观察时间；缓存目录再次枚举保留该时间。旧缓存没有时间时只把新增或改名条目作为新观察，不让无关成员的目录刷新把旧名字重新排到前面。

旧库首次升级从原有入站事件、旁听记录 metadata 和群成员目标目录回填观察名；不读取聊天正文，观察时间统一为 UTC。迁移标记与回填在同一事务提交，后续启动不重复扫描。原聊天正文及模型档案名称不作为别名来源。删除角色同时清除昵称观察；账号删除保留角色历史资料，外部运行仍须通过当前来源验证。

验收覆盖真实 NapCat 解析/宿主目录中的 Alice→艾丽丝、SQLite 重启、超过 10 候选、同 ID 跨渠道、线程档案冲突、来源撤销、旧库和角色清理。公开 HTTP 验收从未触发的实际 QQ 协议入站观察开始，暂停账号后在桌面对话按旧昵称查到人，再按 ID 读档案；两次真实工具结果均持久化并进入下一次 provider 请求。远端 QQ RPC、头像和模型使用传输夹具，未连接真实 QQ 账号或执行外部发送。
