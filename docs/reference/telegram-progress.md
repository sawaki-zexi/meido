# Telegram 运行过程反馈

状态：当前

事实来源：`backend/app/channels/telegram_progress.py`、`channels/host.py`、`main.py` 及 `tests/python/channels/test_telegram_progress.py`。

最后核验：2026-10-27

Telegram 私聊获准开始处理后显示正在输入。长工具执行期间，一次运行最多使用一条独立状态消息，显示工具名称、连接服务、完成或失败；最终回复走原投递流程。群聊暂不显示过程反馈。

反馈消费既有 Runtime 事件，以运行 ID、调用 ID 和单调序号识别更新。同名工具的两次调用仍分别识别。仅允许格式受限的工具名称和宿主已定义的 `connecting` 阶段，不转发工具参数、结果、自由文本进度、思考或凭据。

所有更新共用一个待发送的最新状态；实际发送前才读取该状态。发送、编辑和输入状态复用账号及会话调度，默认分别为 2、5、8 秒，账号整体间隔为 0.25 秒。明确限流最多尝试 5 次，每次更新沿用该运行开始时固定的 120 秒反馈期限；失败只停止对应反馈，不重新发送最终正文。

停止、撤销会话权限、切换账号连接或运行结束都会使反馈失效；等待后和实际 HTTP 请求前再次检查原始来源及连接。反馈不延长运行：结束时取消尚未发送的合并状态，而不等待平台编辑间隔。最后已显示的状态保留在 Telegram 会话中。

输入状态不是消息回执，不生成虚构消息 ID。临时工具状态虽使用真实平台消息 ID 编辑，但不会写入消息历史、回复账本、最终正文事实或主人记忆。
