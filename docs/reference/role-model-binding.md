# 角色模型连接绑定

状态：当前（#205 的兼容修复部分）。最后核验：2026-11-02。

事实来源：[RoleStore](../../backend/app/role_store.py)、[模型配置](../../backend/app/model_config.py)、
[角色 API](../../backend/app/main.py)、[持久化测试](../../tests/python/test_role_store.py)及
[API 回归测试](../../tests/python/test_api.py)。

角色使用 `modelConfigurationId` 选择已保存的模型连接。创建角色可以提交此 ID；
之后通过角色的模型选择器修改绑定。普通设定编辑不提交模型绑定，也不会覆盖它。
当前五个角色设定字段和 JSON 清单结构保持不变。

## 读取旧角色

旧清单的 `modelConfig` 只在 RoleStore 内部用于兼容读取，不进入公开角色对象、
角色 API 响应或运行快照。读取不会为了迁移而写入清单：

- 已有非空规范 ID 始终优先。该连接丢失时要求重新选择，不改用旧字段或全局模型。
- 没有规范 ID 的旧对象，先检查其中明确的连接 ID 是否存在。
- 没有可用的明确 ID 时，仅比较规范化后的 `providerId`、`provider`、`baseUrl`、
  `model`、`api` 和 `apiOptions`；必须恰好匹配一个已保存连接。
- 地址不能含账号、密码、查询参数或片段；协议选项使用现有协议白名单。
  不比较密钥，不使用名称近似匹配。
- 无匹配、多匹配或非法旧配置保留角色，并设置 `modelBindingRequired`。发送消息
  返回要求重新选择模型的 409 错误；选择器仍可加载目录并修复绑定。
- 原本没有旧配置且绑定为空的角色继续跟随全局模型。重新选择“跟随全局模型”
  会明确清除待选择状态，该选择可以跨重启保留。

## 保存和运行

新建角色不接受内嵌连接作为运行配置，也不保存提交中的 `modelConfig`。
创建及绑定编辑校验连接是否存在；绑定保存与连接删除共用同步锁，防止检查后
连接被同进程的删除请求移除。显式绑定该连接的角色存在时，删除返回 409，
应先为这些角色选择其他连接或全局模型。

发送开始时读取该角色绑定对应的配置副本。之后保存连接或切换角色绑定不改变
当前运行持有的副本；新消息使用新配置。运行快照继续排除连接密钥和旧角色配置。
角色创建、设定编辑及绑定编辑的验证错误不回显请求原值，避免错误响应包含旧凭据。

## 本次兼容边界

这是 #205 的一部分修复。**已有清单中的旧 `modelConfig` 原值仍保留在磁盘上**。
RoleStore 私下保存原字段，普通设定、绑定及素材保存都保留该字段的原 JSON 值；
不会借普通保存删除旧凭据，也不会生成含凭据的备份文件。保存成功后可同时存在
规范 ID 与保留的旧字段，但运行只使用规范 ID。

旧清单的静态凭据清理尚未交付，需要单独确定明确授权、恢复方式、文件权限和
并发修改保护后再实现。因此不能把本次修复视为 #205 全部验收完成。所有实现
验证仅使用隔离目录中的合成配置；没有读取、迁移或清理本机正式角色数据。
