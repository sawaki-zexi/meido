## 准备角色与渠道

先按[多渠道配置](multichannel-setup.md)建立属于该角色的渠道账号，并通过真实配对流程绑定主人私聊。主动决策与 Drift 分别默认关闭；来源、模型、工具和发送目标各有独立许可。

来源创建与启用见[来源作者手册](proactive-source-authoring.md)，主动运行的准入与停止见[主动决策验收](proactive-decision-acceptance.md)，Drift 技能准备见[长期技能手册](drift-skills.md)。选择目标不会赋予来源 ACK 权限，也不会扩大当前运行的文件、附件或工具范围。

## 选择并保存目标

1. 进入角色的自主设置，在“自主发送目标”查看“自主发送账号”。账号列表读取本地连接事实；“在线”“离线”“在线状态未知”分别展示已有证据。账号和平台启用不代表平台在线。
2. 选择账号与它实际支持的“目标目录类型”，再点击“读取目标目录”。只有这一显式操作才请求所选目录。查看覆盖范围、是否完整、观察时间和错误；“已观察目标”不等于完整平台目录。有下一页时继续读取，过期游标需要重新读取。
3. 勾选属于该角色账号、具有发送能力且已绑定主人的私聊。群组、群成员、访客和其他角色的账号不能作为自主发送目标；群或成员资料不会自动创建私聊目标。
4. 在最多四个许可目标中选一个“自主默认目标”。桌面若保留也占一个名额。保存配置前完成相应模式的模型、来源及有限操作确认；保存本身不会发送消息、运行来源或执行 ACK。

选择凭据只在短时间内有效。目录观察后发生解绑再配对、账号停用再启用、配置变化或适配器替换时，保存会拒绝旧选择。重新读取目录并明确选择后才能保存。修改其他设置时，省略新选择只保留并验证原许可，不会自动绑定最新主人身份。

已经保存的目标失效时，界面保留其名称和失效原因。可以重新读取并点击“重新选择目标”，或明确移除它并重新选择默认目标；目录读取失败不会自动删除原目标或改投桌面。

## 理解一次自主投递

A01 在 tick 准入时冻结默认目标与许可集合；草稿可以使用原默认目标，或指定集合中的完整账号与目标二元组。Drift 在消耗唯一发送机会前选定目标。后续修改配置不会给旧运行增加许可。

模型请求会包含本轮最多四个获准目标的最小地址，以及原冻结默认目标。外部目标只提供原账号与目标二元组；未选择的目录项、另一角色的账号、主人绑定和凭据不会加入这份投影。省略二元组仍使用原默认目标。

外部发送先保存唯一意图与事件占用，再调用原渠道发送入口。查询和恢复只核对原 attempt 与回执。关闭角色、切换模式、改目标、跨日或重启不会重发原意图。真实主人输入会阻止旧运行的新动作；已经提交给平台的请求仍可能生效，其实际回执继续保留。

在“自主投递与对账”中核对以下事实：

| 状态或字段 | 如何理解 |
| --- | --- |
| 正在核对原投递 / 等待原投递回执 | 已保留原发送身份，尚不能确认平台结果。 |
| 结果不确定 | 可能已经发送；不会再次发送这条消息。 |
| 已发送 | 有真实原渠道或桌面回执；人工报告不能产生这个状态。 |
| 确定失败 | 此次机会已经用过，不会重新发送原意图。 |
| 原 attempt、平台消息 ID | 用于核对同一次平台投递；缺失不是未发送证明。 |
| 仍有本地恢复责任 | 原意图仍需核对原回执并恢复本地记录；这本身不证明回执已存在，也不会增加平台发送。 |

外部消息记录在原渠道线程，桌面消息记录在角色桌面会话。自主投递不会制造主人输入。运行的 Runtime 清理、渠道回执、消息投影和来源 ACK 分别展示真实完成情况；Runtime 已回收不表示未知投递已解决。

实际渠道连接在宿主启动时绑定原服务事件循环。后台任务的发送、持续授权与 send lease 收尾均回到该循环；取消会等待原请求真实结束。原循环关闭或停止后拒绝新发送，不能退回后台线程。重建应用与 ChannelHost 可恢复原持久事实；不支持把仍带旧适配器的 Host 转交另一个事件循环。

## 记录主人处置

对尚未确认的投递，可以选择“继续等待原回执”“主人报告已收到”或“主人报告未收到”，填写说明，再点击“记录主人处置”。报告与平台回执分别保存。

“允许后续新的自主投递”只控制后续新意图的准入；“继续等待”不能开启它。任何处置都不会重发旧意图、释放它已经占用的事件或去重身份，也不会补造成功 ACK。之后出现真实原 attempt 的成功回执时，仍按该事实恢复原投递记录及合法来源处置。

提交失败且结果尚未确认时，先用“核对原处置请求”读取状态；需要重试时使用保留原身份和正文的“重试原处置请求”。遇到版本冲突，重新核对最新状态后填写，不自动生成第二份处置或发送请求。
