## 升级

发布必须遵循常驻实例的运行说明，仅发布已合入 `origin/main` 的版本；开发分支的验收使用独立数据。本变更不自动更新正式实例。

首次打开已有渠道数据时，在会话数据库旁生成 `sessions.before-external-memory-v1.sqlite3`（前缀随实际数据库文件名变化）。备份通过 SQLite 在线备份和 `quick_check` 校验，使用临时文件完成后替换到备份路径。已有备份不覆盖。新建空数据库直接记录初始版本。

资料导入、来源关联、冲突候选和完成标记在同一事务中写入。模型不参与迁移。启动失败时不要删除旧表、备份或强写完成标记；解决磁盘空间、权限或损坏数据问题后，用同一版本重新启动，未完成的事务会重新执行。

升级后查看手机“聊天信息 → 成员”。标为“需整理”的成员保留每份旧档案及会话来源，选取候选或编辑合并后保存，才会成为共同档案。账号离线可以编辑，已移除账号的历史只能查看。笔记和原始聊天不会因为档案合并而串到其他群。

## 恢复与降级

迁移失败先保留当前数据库和升级前备份。读取备份的 `PRAGMA quick_check` 应返回 `ok`；确认备份属于目标数据目录，并通过已保存的角色与线程核对内容。

需要降级时，先停止该实例的数据写入并保存故障后的完整数据副本，再由维护者决定恢复升级前备份。升级之后新增的聊天和编辑不在旧备份中，需要单独保留；不要将旧版本直接连接到已升级的资料表，也不要同时运行两个版本写同一数据库。已有角色文件、附件和凭据保持原目录，不把会话数据库备份当成整机备份。
