# 管理和复用普通技能

状态：当前；最后核验：2026-11-09。
事实来源：[管理页](../../web/src/features/skills/SkillLibrary.tsx)、[管理接口](../../backend/app/skill_routes.py)、[行为测试](../../tests/python/test_skill_discovery.py)。普通技能与 Drift 长期任务分开管理。

## 为一个角色启用

1. 打开角色工作区的“技能”，查看来源、有效版本、被覆盖项、启停、使用方式和不可用原因。
2. 点击“预览启用变化”。原有角色手动项保持手动，关键词项改为按任务选择，常驻项保留；已审阅内置方法逐项显示为自动候选。确认后仅为当前角色启用。
3. 可以单项改成“按任务自动选择”“仅手动指定”或“保持常驻指导”。需要恢复旧行为时点击“回退旧触发方式”；已保存的文件和资源仍保留。

启用后角色先看到简短目录，需要时读取正文。普通闲聊可以直接回复。消息过程中的“已读取技能”只是读取事实，实际执行和任务完成仍要看真实工具结果和回复。

## 导入、编辑与分享

在管理页导入一份 Markdown 后，检查正文并点击“保存并核验”。支持文件可一并添加，路径应与正文一致并位于 `references/`、`assets/` 或 `scripts/` 下，每个文件最多 256 KiB。正文引用但未提供的文件会显示具体缺项；文件保存成功不等于技能完整可用。

也可以在聊天上传 Markdown，明确说“请把这份附件保存为你的技能”。角色使用当前文件工具写入和读回，下一轮重新发现。只上传附件不会自动安装。自行创作时也要先查已有方法，核对输入、步骤、结果与未验证项。

```markdown
---
name: meeting-notes
description: 将已提供的会议原文整理成决定与行动项；普通闲聊和会议邀请不使用。
---
核对输入是否含会议原文；缺少时先询问。
列决定、负责人、截止时间；原文没有的信息标待确认。
最后逐项对照原文，不能编造承诺。
```

仅允许手动指定时，在头部增加 `allow_implicit_invocation: false`，之后用 `$meeting-notes` 或请求的 `skillIds` 指定。详细步骤留在正文，不把整份方法塞进描述。宿主不支持的外部元数据会列出但不会授权工具、安装依赖或传递 API 密钥。

编辑必须基于已读取版本；遇到保存冲突，保留草稿，重新读取当前版本再处理。更新正文会保留旧资源。公共与内置来源只读，可以另存角色私有副本。同 ID 的私有项覆盖公共版本，停用它可以恢复公共版本。

发布公共方法时，先保存修改，再明确选择“发布到公共库”并确认完整正文和支持资源。它会让所有角色可见；公共库保存于应用数据中，应用升级后继续保留。聊天中的“分享”不自动执行发布。

## 效果评估

确定性测试只验证目录、工具循环、文件、隔离和生命周期。真实模型的漏选、误选与成果质量需要单独采集，默认不运行付费模型。

使用 `python scripts/evals/skill_trigger_eval.py --write-fixtures <临时目录>` 生成三份评估技能；导入独立评估角色并启用自主选择。用 `--write-template <结果.jsonl>` 生成 30 个固定请求、每项 3 次的记录模板。逐模型、逐案例从独立的同等初始上下文执行，保留实际读取记录与最终成果；不要将上一案例的技能正文带入下一案例。填写实际 `readSkillIds`、成果核验 `completed`、证据位置，并尽量记录请求数、耗时和输入输出 token。

用 `--results <结果.jsonl> --report <报告.json>` 汇总。缺记录、重复样本或未提供证据不能通过完整矩阵检查；门槛建议为正例至少 90%、负例误触发至多 5%，相邻案例和成果另列，不能把这当成模型保证。脚本只生成/读取本地文件和评分，不连接模型或执行业务工具。
